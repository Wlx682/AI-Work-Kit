模型越强，越挑工具

最新的 Claude（Opus 4.8 / Sonnet 5）调用第三方编辑工具时，反而比老模型更容易凭空塞进乱造字段。挖到底，是所有自建 agent 框架都该知道的真相。

来源 Armin Ronacher日期 2026-07-04标签 工具调用 · harness · 受限采样
核心论点

工具的参数结构（schema）不是中立契约

它落在模型训练分布的什么位置，直接决定模型能不能稳定地把它填对。模型可能完全理解你的 schema，却依然在压力下采样不出那个精确的形状。

为什么是随机 key

模型「知道这里也许能有一个可选字段，但没有训练过的名字」，于是每次现编一个看着合理的名字。

机制 · 扁平 vs 嵌套

出错出在嵌套那条路

机制 · 奖励塑形

宽容 harness 固化了坏习惯

复用 · 落到我们工作流
  • 工具优先扁平参数：file_path/old_string/new_string，少用对象数组嵌套。
  • 自建 harness 加宽容修复层：未知字段过滤、参数别名归一、类型强转。
  • 能开严格采样就开：Anthropic 模型 + 复杂 schema 时列为默认基线。
  • 补跨 harness 迁移压测：在真实 agent 历史下测调用成功率，别只测单轮。
"越强的模型先验越硬，「靠把工具说明写好、让模型自己适应任意 schema」这条路，比半年前更难走了。
