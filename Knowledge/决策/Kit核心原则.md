# Kit 核心原则

AI-Work-Kit 的作用是帮助人把目标快速转化为可验证结果。它不定义完成工作的标准路径，也不把 LLM 当作可靠的自治成员。

## 人拥有方向

目标、优先级、价值取舍、授权范围、对他人的承诺和最终验收属于人。LLM 可以整理证据、暴露矛盾、提出选项和执行选择后的工作，但不能用“最佳实践”或模型共识替人做决定。

人在一次表达中给出的目标、约束和权限构成本次委派。无需为了适配 Kit 改写成固定表单；LLM 应先从对话、代码和现有资料中恢复事实，只有缺失信息会实质改变结果时才提问。

## LLM 只做授权内的操作性选择

LLM 不可靠、无持续记忆、不能承担责任。它适合高效完成边界明确的转换、检索、修改、测试和整理工作。

LLM 可以自行选择具体方法，前提是该选择仍在人的目标内、影响可撤销且结果可验证。以下事项必须交还给人：

- 改变目标、范围、优先级或用户可见语义；
- 引入新的安全、成本、合规或组织取舍；
- 扩大权限、联系他人、作出外部承诺；
- 执行不可逆操作或无法证明结果的动作。

请求人决定时，只说明当前事实、为什么需要人、可选影响和哪些工作被阻塞；不要把整个分析过程转嫁给人。

## AI 帮助人协作，不代表人承诺

现实任务可能依赖其他人的隐性知识、权限、行动或接受。AI 应先完成不依赖他们的工作，再帮助当前用户识别需要谁、为什么现在需要、要获得什么以及延迟的影响。

未经授权，AI 不代表用户联系他人、许诺结果或解释沉默。沟通材料应短到对方能快速作出判断，并附上必要证据；人的回复会成为新的目标约束或事实，而不是一个固定流程节点。

## 证据决定完成

LLM 的完成声明、自评得分、置信度以及另一个 LLM 的赞同都不是事实。完成必须落在模型之外：测试结果、命令输出、文件差异、可运行产物、一手来源或人的真实观察。

验证方式随任务即时选择，不维护一套覆盖所有任务的固定检查表。能机械验证的优先机械验证；涉及体验、价值和现实效果的部分由人判断。

## 把边界写具体，把路径留动态

长期规则只保存不会随任务类型变化的不变量。具体步骤、任务拆分、工具选择、参与者数量和输出形式由当前目标与现实证据即时决定。

- 不设置阶段链、固定路由、统一 Gate 或必填文档。
- 不把一次成功做法自动升级为通用流程。
- 不保存临时任务包、模型思考过程和进度百分比。
- 只有反复出现且跨任务仍成立的知识，经人确认后才进入 `Knowledge/`。

## 最小状态

默认状态存在于对话和真实产物中。只有跨会话或交接需要时，才在 `Sessions/` 写自由文本快照，保留：目标、人的关键决定、已证实事实和未解决问题。快照不是计划，不规定下一步，也不需要完成后的维护。
