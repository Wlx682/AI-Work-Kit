## 10 项硬 checklist

> 每项打 0 或 1（0=没做 / 1=做了），合计 X / 10。  
> **< 9 分禁止说"完成"**，必须把差异表交付给用户由其决定下一步。

| # | 检查项 | 通过标准 | 分 |
|---|--------|---------|---|
| 1 | **度量表已列** | 含每个节点的 W/H、cornerRadius、fill、strokeWeight、字号、行高；不只贴截图 | □ |
| 2 | **形状已判定** | 度量表每行有「形状」列：圆 / squircle / 圆角矩形 / 直角；按 `cornerRadius` 数值判，不靠肉眼猜 | □ |
| 3 | **色板 1:1** | 色值 + 数量 + 顺序与节点完全一致；不自由发挥 | □ |
| 4 | **图标集 1:1** | 种类 + 顺序 + 首选项与节点一致；SF Symbol 不能自由替代设计图标 | □ |
| 5 | **字号 / 圆角取整正确** | ÷2 后小数 ≥0.5 向上取整；圆角宁大勿小；视觉偏差 ≤ 1pt | □ |
| 6 | **Variant 全覆盖** | 默认 / 选中 / 禁用 / 按压 / 加载 / 空 等状态稿都已实现 | □ |
| 7 | **切图清单已落** | 所有 `**…**` 节点已确认（已导出 / 已在 Assets / 用 SF Symbol 替代并标注） | □ |
| 8 | **截图对比已做** | MCP `get_screenshot` 取设计稿 + 真机/模拟器截图，并排对比 | □ |
| 9 | **差异表已列** | 每个差异已标 "已修复 / 待设计确认 / 接受偏差（写明原因）" | □ |
| 10 | **自评 ≥ 9** | 上述 1~9 至少做对 9 项；< 9 时必须告知用户"未达完成"，不能糊弄 | □ |

## 报告口径（AI 对用户说话的措辞）

| 分数 | 口径 |
|------|------|
| **9~10** | "还原完成"，附差异表（即使 0 条也写"无差异"） |
| **7~8** | "**主体完成，但 X 项未对齐**"，列差异表 + 修复建议，请用户决定 |
| **< 7** | "**未达完成度**"，列原因 + 修复方案 + 预估工作量 |

> 禁止"完成"+"还有一点小问题"这种含糊话术。**报喜不报忧 = 不合格。**
