# 模板约定

> **存放原则**（Contexts vs Plans、做完删 plan）→ 只读 [[Contexts/决策/Kit核心原则]]，本文不写第二份。

## 日期

- 占位符 **`{{date}}`**（推荐 `YYYY-MM-DD`）。
- 文件名：`{{date}}-{{title}}.md`。

## Plan 状态（YAML + 正文一致）

```yaml
status: 草稿 | 进行中 | 评审中 | 已采纳 | 搁置
```

## workflow / lifecycle_state

```yaml
workflow: client-dev | computer-mgmt | ...
lifecycle_state: requirement | architecture | development | test | deploy | done
```

`workflow` 是工作流选择字段；`lifecycle_state` 仅保留作兼容展示/人工阅读，不驱动 workflow 路由。真实阶段由 `scripts/workflow-gate.sh` 读取蓝图和子 Plan 文件事实派生，展示用 `scripts/derive-epic-status.sh`。

## Epic frontmatter

| 字段 | 所在 | 说明 |
|------|------|------|
| `epic_id` | Epic | 短 kebab |
| `epic` | 子 plan | `Plans/Epic/xxx.md` |
| `plans.*` | Epic | 各阶段 plan 路径或 `null`；只作路径索引，不驱动阶段 |
| `p0_open` | Epic、需求 | 0 才可开发 |
| `含业务逻辑` | Epic、功能 | `是` → 技术方案 `status: 已采纳` |
| `parent` | 子任务 | 主功能 plan |
| `fix_slices` | Bug plan | 重开 WBS 编号 |

门禁：`plan-gate-check.sh` · `workflow-gate.sh --workflow <name> --epic …`

## Epic 入口

| 场景 | 规则 |
|------|------|
| 新模块 / 含业务逻辑 | 先 `workflow-router` 选具体 workflow → `Plans/Epic/` |
| 学习工作流 | `learning-loop` 必须先建 `Plans/Epic/` 学习 Epic，子阶段 plan 放 `Plans/学习循环/` |
| 功能主 plan | 必有 `epic:`；无 Epic → 改走 `workflow-router` |
| 纯 UI 小改 | `含业务逻辑: 否` + figma-ui + ≤1 人日；仍建议挂 Epic |

## 续做（全库唯一）

```text
/resume plan=Plans/【分类】/{{date}}-{{title}}.md 进度=【当前完成情况】
```

## 轻流程建 plan

无 Epic 轻流程（如 `ui-change` / `bugfix` / `task-split-only`）用脚本生成阶段 plan：

```bash
python3 scripts/workflow-plan-init.py --workflow ui-change --title 卡片
python3 scripts/workflow-plan-init.py --workflow bugfix --title 价格错误 --all
```

脚本只生成开工骨架，默认不写 `skill_run`；阶段完成后由对应 Skill 在 plan 末尾追加反馈块，再由 `workflow-gate.sh` 推进。

## 分卷规范（需求分析类 plan）

正文物理拆两卷，分隔符 `<!-- AI工作底稿 ↓ -->`：

| 卷 | 内容 | 约束 |
|----|------|------|
| 人类卷（前） | ①用户使用地图 ②核心操作流程 ③关键业务规则(Do/Don't) ④需求问题清单(产品视角一句话表,标 P0/P1+🤔不理解/⚔️矛盾/🕳️遗漏) | 软约束 ≤3 页；禁止字段类型/异常矩阵/依赖编号 |
| AI 工作底稿（后） | 数据字典、状态机、边界/异常矩阵、逻辑/交互问题、遗漏分析、AC | 供 architecture / test 阶段消费 |

人类校验门禁：人类卷须让没读过 PRD 的人 3 分钟答清「先点哪→解决什么场景→能做/不能做→有哪些要我拍板」；④缺失或答不清则重写人类卷,把冗余踢进底稿。`skill_run` 等元数据仍在 frontmatter,不进正文。

## 标签

`tags: [排查, 功能开发, …]` — 标准集见历史 plan 或 Epic 母版。
