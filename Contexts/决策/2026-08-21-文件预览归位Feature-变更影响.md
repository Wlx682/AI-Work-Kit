# 文件预览归位 Feature｜变更影响

## 变更裁决

2026-08-21 用户明确指出当前方案将“App 负责装配”扩大成“预览 UI、协调逻辑和插件适配都放 App”，并确认改为：

- 文件预览是独立 `features/file_preview` 能力，不是 `app/integrations` 的实现仓库。
- 预览 UI、编排、状态/取消、缓存、持久化和 Flutter 插件适配归 Feature 内分层。
- 上传/下载/分享归 `features/files` 的传输能力；原生代码仍在各插件 package 中。
- App 只保留 Provider 生产装配、路由入口和跨 Feature 绑定，不承载预览页面或业务协调器。

## 影响范围

| 区域 | 处置 | 结果 |
|---|---|---|
| 需求 AC-05 | 从“预览实现留 App”改为“预览 Feature 持有实现，App 只装配” | 需求真理源修订 |
| ADR-CFR-001/004 | 收窄 App composition 职责，新增 Feature 归位裁决 | 架构设计修订 |
| US-CFR-005 | 建立 `features/file_preview` 并迁移预览纵切 | 当前 Story 重做落点 |
| US-CFR-006 | 迁移剩余 transfer/跨 Feature 消费者，删除 App 兼容面 | 后续 Story 保留 |
| 源码 | `app/integrations/app_file_*` 的 UI/application/data 迁出；composition 留 App | 产品行为不变 |
| 测试 | 新增 Feature → App 禁止边界，原 preview 聚焦回归迁到 Feature 测试语义 | Red→Green |

## 保留不变

- US-CFR-001～004 已完成的 Runtime 分离、owner/generation fencing、Files Host 注入与 Feature → App import 清零继续有效。
- 不改 HTTP/Gateway 协议、签名、`personal-cloud` namespace、持久化格式、平台预览选择和用户交互。
- 完整 Android/iOS 设备矩阵仍在 Epic 里程碑执行。

## 确认

用户于 2026-08-21 明确指令“改”，本变更已确认，可从 US-CFR-005 implementation-design 继续。
