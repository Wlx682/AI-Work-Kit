# 对话用词习惯（用户专属沉淀）

> 用户的口语模式与 Agent 默认理解之间的映射表。每条规则附**触发词**、**优先动作**、**置信度归类**、**形成日期与背景**，便于后续审视与剔除噪音。

---

## 一、为什么需要

- 同一句话在不同用户那里语义边界不同。把口语→动作的映射沉淀下来，避免反复被同一种误解纠正。
- Agent 默认对"结束/删/清理"等动词偏保守（倾向反问），用户偏向直接执行——需要按用户实际偏好校准。
- 「关键词≠铁证」：关键词只是把候选优先级抬高，仍要用上下文复核，避免武断。

---

## 二、规则清单（按形成时间倒序）

### 规则 02 · 「直接 X」= 不要再问

| 项 | 内容 |
|---|---|
| **触发词** | 直接结束 / 直接删 / 直接做 / 直接处理 / 直接 + 动词 |
| **优先动作** | 按当前语境最直接的默认路径执行，**不**提供 A/B 选项、**不**追问归档/记录/反馈等次级问题、**不**追加「要不要顺便 Y」 |
| **置信度** | 极高（用户在 2026-06-24 连续 3 次因这条被违反而表达不满） |
| **执行后回复** | ≤ 1 句话确认，即停 |
| **边界** | 仅当该动作可逆性高 或 上下文已锁定唯一目标时直接执行；若仍涉及多目标/破坏性，可一次性列候选并自选默认值后执行 |
| **形成日期** | 2026-06-24 |
| **背景** | 清理「项目内专家团」测试 plan 时连续违反 |

---

### 规则 01 · 「项目 / 计划 / 不需要了 / 结束」→ Plans 优先

| 项 | 内容 |
|---|---|
| **触发词** | 项目 / 计划 / 需求 / 不需要了 / 结束 / 砍掉 / 不做了 |
| **优先动作** | **先**到 `Plans/` 用关键词 `find -iname` 搜索候选 plan 文件，把"涉及 plan"的判断概率显著抬高（但非 100%） |
| **置信度** | 高（不是绝对，需结合上下文） |
| **决策路径** | 1. 搜 → 2. 有匹配则进入 plan 处理流程 → 3. 无匹配再考虑其他解释 |
| **形成日期** | 2026-06-24 |
| **背景** | 用户说"项目内专家团不需要了，直接结束吧"时，Agent 把"结束"理解为对话层面"知道了"，未主动搜 Plans，被纠正 |

## 三、维护规则

1. **只增不删**：新发现的用词模式追加为新规则；旧规则失效时打 `~~`，不直接抹除（保留学习痕迹）。
2. **触发词归一**：同义触发词归到同一规则下，不为每个近义词单开规则。
3. **置信度三档**：极高 / 高 / 中——「中」及以下规则不强约束 Agent 行为，仅作参考。
4. **每月复盘**：月度复盘扫一遍此文件，淘汰 90 天内未命中的规则，避免规则库膨胀。
