# 关系图谱协议

> Vault 文件之间的 **5 种关系**：用 frontmatter `relations:` 字段表达，配套 `relations-check.py` 双向校验与 `pre-commit-relations.sh` 枢纽文件 hook。
> 母原则：[[Contexts/决策/Kit核心原则]]；反馈字段与聚合规则见 [[Contexts/决策/Skill反馈协议]]。

## 一、目的

让 Vault 从"散文件集"升级为"有向图谱"，使下述场景在工具层面可行：

1. 改 `Kit核心原则.md` 时，自动列出**所有依赖它的文件**让人逐个确认
2. 查"谁替代了 X / X 替代了谁"无需人工记忆
3. Dataview 视图直接呈现关系网，孤立文件 / 冲突文件可视化
4. 校验脚本兜底：手填 `dependents` 漏写自动补，双向不一致报错

## 二、5 种关系类型（限定，不再扩展）

| # | 字段 | 含义 | 对偶字段 | 备注 |
|---|------|------|----------|------|
| 1 | `supersedes` | 我替代了它 | `superseded_by` | 旧→新；旧文件保留作兼容链接 |
| 2 | `superseded_by` | 我被它替代 | `supersedes` | — |
| 3 | `depends_on` | 我引用它的规则 | `dependents` | **手填项**：写文件时声明 |
| 4 | `dependents` | 谁依赖我 | `depends_on` | **自动反推**，不手填 |
| 5 | `conflicts` | 与之冲突，未决 | `conflicts` | 对称；解决后清空 |

### 不收录的关系类型（避免噪音）

- `related` / "相关但无强关系" — 用 `[[wikilink]]` 即可，不入图谱
- `derives_from` / "衍生自，但不依赖" — 用 `supersedes` 或 `depends_on` 之一表达即可

## 三、frontmatter 格式

```yaml
---
tags: [决策, 协议]
date: 2026-06-24
relations:
  depends_on:
    - Contexts/决策/Kit核心原则.md
    - Templates/模板约定.md
  dependents:                 # 自动反推，不手填
    - Plans/Epic/2026-06-24-项目内专家团.md
  supersedes: []              # 留空时可省略字段，但保留 key 利于 grep
  superseded_by: []
  conflicts: []
---
```

**关键约定**：

- 路径必须**仓库相对路径**，带 `.md` 后缀
- 留空字段可省略，但 `depends_on` 即便为空也建议显式写 `[]`，便于 grep "未声明"
- `dependents` **不要手填** — 由 `relations-check.py --write-dependents` 自动维护
- 自动反推会**清空原有手填的 dependents**（容忍漂移）

## 四、什么文件应该上图谱

### 必上（枢纽文件，7 份）

修改这些文件会触发 pre-commit hook：

1. `Contexts/决策/Kit核心原则.md`
2. `Contexts/决策/AI-Work-Kit工作流总览.md`
3. `Contexts/决策/Skill反馈协议.md`
4. `Contexts/决策/资料与代码仓库边界.md`
5. `Contexts/决策/关系图谱协议.md`（本文）
6. `Templates/模板约定.md`
7. `Contexts/需求分析/需求分析产出标准.md`

### 建议上（决策类 / 模板核心 / Skill 真理源中有 supersedes 关系的）

- `Contexts/决策/*` 全部
- `Templates/Epic模板-client-dev.md` / `需求分析模板.md` / `需求分析-带验收标准模板.md` / `技术方案模板.md` / `客户端功能开发模板.md`
- `Skills/*.md`：仅在有明确 `supersedes` / `conflicts` 关系时回填；advisory 反馈段已 soft-depend `Skill反馈协议.md`，**不需要**额外声明 depends_on

### 不上（避免噪音）

- `Plans/` 全部（任务临时，做完删）
- `Contexts/日报/` `Contexts/周报/` `Contexts/复盘/`（时序性记录，无结构关系）

> **脚本兜底**：`relations-check.py` 会拒绝任何指向 `Plans/` 的 `relations` 目标并报错——防止临时产物（如审计报告 plan）通过 `depends_on` 被 `--write-dependents` 反推进决策文档的 `dependents`。这类文件要引用长期规范用 `[[wikilink]]`，不入图谱。

## 五、工具链

| 工具 | 作用 |
|------|------|
| `scripts/relations-check.py` | 双向一致性校验：每个 `depends_on: X` 必有 `X.dependents` 含本文件；不一致报错 |
| `scripts/relations-check.py --write-dependents` | 一次性扫全库，自动反推所有 `dependents` 字段 |
| `scripts/pre-commit-relations.sh` | git pre-commit hook：仅当暂存区含枢纽文件时，列出 dependents 让用户确认 |
| Dataview 视图 `Contexts/决策/关系图谱.md` | 按关系类型可视化呈现 |

## 六、生命周期

| 触发 | 动作 |
|------|------|
| 新建枢纽 / 决策类文件 | 手填 `depends_on`；跑 `relations-check.py --write-dependents` 反推 |
| 修改枢纽文件 | git commit 时 hook 自动列 dependents |
| 替代旧文件 | 旧文件加 `superseded_by`；新文件加 `supersedes`；跑反推 |
| 发现冲突 | 双方互加 `conflicts`；解决后清空 |
| 校验失败 | 按报错修，必要时跑 `--write-dependents` 同步 |
