# 需求分析产出标准

**路径**：`Contexts/需求分析/需求分析产出标准.md`  
**用途**：定义需求 plan「可开发」最低字段；配合 `scripts/plan-gate-check.sh` 与 `feature-dev-assistant`。

---

## 可开发最低字段

| 字段 | 位置 | 要求 |
|------|------|------|
| PRD 摘要 | 需求 plan §一 | 3–5 句，说清用户与价值 |
| 范围矩阵 | §二 | 入口 / 场景 / 目标页 |
| 业务逻辑图 | §一·六 | 至少决策流程图，覆盖主路径与分支（事件建模+四图见 [[需求分析规范]] §三） |
| 边界覆盖 | §四 | **图优先**：决策流程图所有菱形判断点均有「是/否」出线即视为边界已覆盖；**若未画图，则表格至少列 6 条**（空数据、弱网、权限等） |
| 异常矩阵 | §五 | 4xx/5xx/业务拒绝有用户反馈 |
| 用户旅程 | §八 | mermaid 或表格闭环 |
| **验收标准** | §九 | ≥ 3 条可测 AC，含 P0 |
| P0 清单 | §十 | 未闭环条目数 = `p0_open` |
| 分析结论 | §十一 | 可否进入架构：✅ / ⚠️ / ❌ |

## 与门禁脚本对齐

- 需求 plan 正文字数 ≥ 500
- 必须含「验收标准」章节标题
- `p0_open: 0` 才允许功能 plan 进入开发切片 4+
- 功能 plan §一 须链 `Plans/需求分析/` 真实路径，**禁止**仅写「用户声明 PRD 已评审」
