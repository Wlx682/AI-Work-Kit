# 案例报告模板

> 用途：`best-practice-digest` 产出每周提效案例。度量口径见 [[Contexts/最佳实践/提效度量口径]]；进化闭环见 [[Contexts/最佳实践/进化闭环]]。
> 一套骨架通用，技术/QA 与 产品/设计/运营 只是「所属环节」不同、证据链取材不同。
> **三卷产物**：①人类卷 `.md`（干净成品 + Mermaid 图，给读者/纳米Work）②AI 卷 `.meta.yaml`（skill_run，给进化脚本）③提示词卷 `.prompt.md`（给纳米Work 智能体，生成云端 web 分享链接）。

---

## 一、开工前先补齐输入（信息不全必须逐项追问，禁止瞎编）

采集这些，缺哪项就追问用户，直到能写出完整报告：

1. 本周主要完成哪项任务（需求调研/原型设计/官网设计/代码提交/数据分析…）
2. 以前你/团队通常怎么做、大约花多久（**基线**）
3. 这次用了什么 AI 工具 / 什么 Prompt / 什么新组合方式
4. 这次实际花了多久（**精确到分钟**）
5. 过程中是否有试错/迭代（Prompt 改了几版）
6. 是否有过程记录（对话链接 / 设计稿历史 / 截图 / commit）

> **红线**：任一项缺失且影响「可测量可验证」→ 追问，不得编造。见 [[提效度量口径]] 反作弊红线。

---

## 二、人类卷写作规范（硬约束，产出必须过这几条）

> 目标：一篇**技术博客水准**的分享——客观、准确、有信息密度，让同行快速看懂并复用。既不是填字段的交付物，也不是娱乐化的段子。基准参照优秀工程博客（如官方 engineering blog）。

1. **叙事骨架，不是字段清单**：按下面「叙事顺序」写成连贯文章，小标题用**说明性短语**（如「问题：三端手工同步」「方案」「踩到的坑」），不许出现「基本信息 / 对应哪个 Kit 能力 / 证据链（可验证佐证）」这类表单标签。
2. **符号当标点用**：正文只用标题、`>` 引用、`-` 列表、**加粗**、代码块。禁止 📌🔴🟢✅⏸ 这类装饰性图标堆砌。
3. **专业中性的语气**：术语直接用、必要时一句话解释，不回避技术细节。**禁止娱乐化比喻、段子、卖关子**（不要「像体检完直接出院」这类打比方）。踩坑部分当作**根因分析**写：现象 → 根因 → 修复，给出可复查的技术细节。
4. **标题：主标题短而响亮 + 副标题补准确**：主标题控制在 15 字内、有冲击力（如「会自进化的知识库」）；紧跟一行副标题交代准确主题（如「Skill 反馈回路与月度进化链」）。不要交付物腔「提效案例：XXX」，也不要一长串糊成一行。
5. **必须配图，且非技术人员看图能懂**：涉及结构/流程/数据流（多端、管道、状态机、链路）时，用 **Mermaid**（`flowchart` / `sequenceDiagram` 等）画流程图或架构图，飞书/纳米Work 可直接渲染成真图。图内标签用**大白话**（如「每个 Skill 干完留一条记录」而非 `skill_run emit`），让不读正文、只看图的非技术同事也能懂大意。受众混杂的案例至少 1 张图。禁止只用纯文本描述流程。
6. **排版碎块化，拒绝大段密集文字**：这是硬约束，密集成段即返工。
   - 单段不超过 3 行；讲多个点就拆成**编号/项目列表**，别糊在一段里。
   - 每个小节开头用一句**加粗归纳句**点题，读者扫加粗就能抓主旨。
   - 关键结论用 `>` 引用块或单独一行**加粗**突出，制造视觉停顿。
   - 能列表就列表、能表格就表格、能配图就配图——文字、列表、图表交替，避免连续三段以上纯文字。
7. **成品自然干净**：人类卷正常按叙事顺序写完即成品，不必刻意去痕迹。「零 WIP、零元说明/元指令」的把关在 `.prompt.md`（见第六节）。`.meta.yaml` 至多在文末一行小字注释提一句。

**叙事顺序（推荐段落流）**：
```
主标题（短而响亮，≤15字）+ 副标题（补准确主题）
→ 一句话摘要（转发用，前置，客观陈述成果与数据）
→ 文章主题（这次要讲的机制/做法是什么，为什么值得说）
→ 自己的想法（面对什么问题、怎么思考、为什么这么设计——观点与推理）
→ 结论（方案落成什么样，机制如何运作，可复现的要点；配 Mermaid 图）
→ 数据（表格，效果与可验证性）
→ 复用（前提 + 下一步建议 + 溯源实锤）
→ 小结（一句话点明机制本质）
```
> 每小节开头一句加粗归纳句；段落碎块化、多列表；文字/列表/图表交替，不堆密集文字。

## 三、信息完整性自查清单（Agent 内部用，确保没漏，但不作为文章结构）

写完文章后自查，以下信息点是否都已**自然融进叙事**（不是列成字段）：

- [ ] 提交人 / 环节 / 目标频道（可放 frontmatter 或标题行）
- [ ] 旧办法 + 基线数据（含估算需标注「估算」）
- [ ] 新方法（具体到可复现）+ 对应哪个 Kit 能力（融进正文，不单列）
- [ ] 迭代/翻车过程（证明非偶然）
- [ ] 可测量数据表（耗时/可复用性等，选 1–3 维）
- [ ] 证据链（commit/plan/脚本行数等实锤）+ 复现前置条件
- [ ] 进化建议（缺陷→Kit 该补什么 / 完美→固化命名建议）
- [ ] 主标题短而响亮（≤15字）+ 副标题补准确主题
- [ ] 排版碎块化：单段≤3行、每小节开头加粗归纳句、多列表、文字/列表/图表交替
- [ ] 正文含 ≥1 张 Mermaid 图（受众混杂时），图内标签大白话
- [ ] `.prompt.md` 已写明「生成页面零 WIP/零元说明/元指令」的生成约束

> 度量口径见 [[提效度量口径]] 反作弊红线：无基线/断证据链一律打回。

## 四、参考范文

三卷范文（人类卷 `.md` + AI 卷 `.meta.yaml` + 提示词卷 `.prompt.md`）随任务生成到 `Plans/最佳实践/`。新案例照三卷齐全、有量化基线与证据链的手感生成；缺提示词卷或含待回填占位的样例不作为范文。

## 五、AI 卷：独立元数据文件（`{{案例名}}.meta.yaml`）

> **双卷分离**：人类卷（上面 .md）讲故事、给结论，**不含** YAML 噪音；AI 卷（本 .meta.yaml）只放结构化数据，喂 `feedback-aggregate → vault-evolve`。
> 与 .md 同目录、同名、后缀 `.meta.yaml`。**纯 YAML，不套 Markdown 代码块**（脚本已支持直接解析整文件）。

写一个 `Plans/最佳实践/{{案例名}}.meta.yaml`，内容即原 skill_run（遵 [[Contexts/决策/Skill反馈协议]]）：

```yaml
skill_run:
  skill: best-practice-digest
  plan: Plans/最佳实践/YYYY-MM-DD-案例名.md    # 指向人类卷 .md
  date: YYYY-MM-DD
  contexts_used:
    - path: Contexts/最佳实践/提效度量口径.md
      utility: high
      reason: "按口径取基线与证据链"
  contexts_missing:            # 本次暴露的「该有却缺」的能力 → 下月新 Skill/Contexts 候选
    - "{{如：反爬场景的半自动采集流程}}"
  contexts_stale: []
```

> 兼容旧案例：未拆分的旧报告若仍把 skill_run 写在 .md 里，`feedback-aggregate` 仍能回退读取；同一 plan 两处都有时以 .meta.yaml 为准去重。

## 六、纳米Work 生成提示词卷（`{{案例名}}.prompt.md`）

> **三卷分离**：①人类卷 `.md`（干净成品，给读者/给纳米Work 当素材）；②AI 卷 `.meta.yaml`（给进化脚本）；③本卷 `.prompt.md`（**给纳米Work 智能体的生成指令**，让它拿人类卷直接产出可访问的云端 web 分享链接）。
> 本卷是给智能体看的**操作指令**，不进读者视线，也不进人类卷正文。

写一个 `Plans/最佳实践/{{案例名}}.prompt.md`，内容形如：

```markdown
# 给纳米Work 的生成指令

请把同目录人类卷 `{{案例名}}.md` 的正文，生成为一个可直接访问、可对外分享的云端 web 页面，并返回该页面的 URL。

要求：
- 忠实还原正文全部内容与 Mermaid 图（图渲染成可视流程图/架构图，非技术读者能看懂）。
- **视觉：简洁、漂亮、炫酷**。深色科技感基调（深底+高对比+品牌主色点缀），大量留白，现代无衬线字体；卡片式分区、渐变/微光点缀、关键数据用大字号高亮；Mermaid 图配色协调、线条精致；适度动效（滚动淡入、hover 反馈）但不喧宾夺主、不影响阅读与加载。
- 排版碎块化：清晰标题层级（主标题醒目、副标题次级）、列表与表格美观、代码块高亮、加粗归纳句突出。
- 自适应移动端，链接生成后可长期访问、可直接分享。
- **生成的页面必须零生产痕迹**：不得出现 `⏸`/待办标记、`{{占位}}`、`skill_run`/YAML 等机器块、以及「面向技术同学也照顾产品视角」这类对文章本身的写作要求/元指令。这条是本卷把关的核心。
- 生成后，把 URL 回填到本案例的分享入口。
```

> 把关责任在本卷：网站的「简洁漂亮炫酷 + 零生产痕迹」都由 `.prompt.md` 明确要求纳米Work 达成，即便人类卷素材朴素或偶带痕迹。

## 七、提交确认语（供用户拿到 web 链接后发群/领导）

> 确认语在**拿到纳米Work 生成的 web 链接后**再补 URL，不带 WIP 占位。

```text
【本周提效案例】{{姓名}} · {{技术/产品}} ·《{{标题}}》
{{一句话成果：旧X → 新Y，可验证}}
含流程/架构图，非技术同事看图也能懂。溯源：{{脚本/commit}}。
👉 全文：{{纳米Work web 链接}}
```

## 八、交接与进化钩子

```text
人工节点：把人类卷 .md + 同名 .prompt.md 交给纳米Work → 拿到 web 链接 → 补进确认语 → 发对应频道（2.技术 / 3.产品）
进化钩子：.meta.yaml 已写入 → 自动进 vault-evolve 月报；contexts_missing 作下月能力候选
```
