端到端提交流程：确认 → 提交 → rebase → 推送

「提交代码」在本项目是一套固定四步动作。每一步都有明确的命令与门禁，跟着走一遍即可安全地把改动推上远端。

01

确认改动

~1 min

提交前先列出改动给自己（或用户）确认，避免误提无关文件。

 terminal
git status --short
git diff --stat HEAD
✓
只 git add 与本次改动相关的文件，不要 git add -A 顺手带进 .env、大二进制等无关文件。
← 上一步下一步 · 提交 →
02

提交（三行格式）

~2 min

commit message 三个字段各占一行，用多段 -m 保证换行；修改说明 ≤30 字，不加 Co-Authored-By 尾注。

 commit
git commit -m "[修改类型] FIX" \
  -m "[修改说明] 修复切tab键盘未收起" \
  -m "[影响范围] 终端tab切换"
!
修改类型仅四种取值：FEAT / FIX / 优化 / UI。细节放 PR 描述，不堆进 commit。
← 上一步下一步 · rebase →
03

拉取 rebase

~1 min

拉远端并变基到当前分支，保持线性历史。遇 Podfile.lock 冲突取远端版本。

 rebase
git pull --rebase origin $(git branch --show-current)

# Podfile.lock 冲突时
git checkout --theirs Podfile.lock
git add Podfile.lock
GIT_EDITOR=true git rebase --continue
← 上一步下一步 · 推送 →
04

推送当前分支

~30 s

rebase 成功后只推当前分支，不跨分支操作。

 push
git push origin HEAD
!
严禁跨分支 merge / cherry-pick / checkout 他分支；不 force push 到已有他人提交的历史。rebase 完成若动过 Podfile.lock，记得 pod install。
