# 非功能验证助手 Skill

用于 `client-dev` 蓝图 verify 阶段：在发布前检查性能、安全、可访问性、稳定性，并给出放行结论。

## 触发时机

- 用户说「非功能验证」「性能检查」「安全检查」「可访问性」「NFR」
- Epic WBS 指向 11「非功能验证」
- `full-cycle` 门禁推荐 `nfr-assistant`

## 输入

- Epic、需求 plan、技术方案、功能开发 plan、测试 plan
- 代码仓实际运行/测试命令
- 项目已有质量门槛

## 输出

输出到 `Plans/非功能验证/YYYY-MM-DD-模块名.md`。

必须包含：

- 验证门槛：性能、安全、可访问性、稳定性
- 检查项、证据、结论和风险
- P0/P1 问题处置
- 是否放行与回归要求

## 执行规则

1. 证据优先：能跑命令就记录命令和结果，不能跑就说明人工核对依据。
2. P0/P1 未闭环时，不建议进入发布。
3. 如果验证项不适用，写明不适用原因。
4. 完成后追加 `skill_run` 反馈块。

## 反馈

`utility` 只能是 `high` 或 `not-needed`。有 plan 时追加到 plan 末尾；协议见 `Contexts/决策/Skill反馈协议.md`。
