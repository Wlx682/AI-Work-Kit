# HTML 生成助手 Skill

知识库：`/Users/wanglongxiang/git/AI-Work-Kit`
原则：[[Contexts/决策/Kit核心原则]] · 建站硬标准：[[Contexts/规范/炫酷建站规范]]

## 定位

把「一篇技术正文」变成「炫酷专业的自渲染网页」。技术文档偏多，所以**骨架要多、要不一样**——不是换配色，是换布局结构。本 Skill 维护一个**骨架库**并提供**内容→骨架选择器**：读正文形态自动挑骨架，也接受用户指定。

- **炫酷标准 / 技术基线 / 自检清单 / 交接话术**：全部沿用 [[Contexts/规范/炫酷建站规范]]，本 Skill 不重复，只做「选骨架 + 套正文 + 过自检」。
- **被谁调用**：`weekly-intel-digest`、`best-practice-digest` 产网页那一步内部走本 Skill；用户也可直接对任意正文触发。

## 骨架库（Contexts/规范/html模版/samples/）

每个骨架是一份可直接改用的 `.html` 成品样例，共享同一套深色科技感设计令牌（CSS 变量、图文表达引擎的深色适配、渐进增强脚本），**布局结构不同**：

| 骨架 | 文件 | 布局特征 | 最适合的正文形态 |
|------|------|----------|------------------|
| **A 单栏叙事式** | `A-single-scroll.html` | 无侧栏 · 顶部进度条 · 居中阅读列 · 首字下沉 | **保底通用款**：无明显结构特征的通用长文、随笔式技术说明 |
| **B 侧栏文档式** | `B-sidebar-docs.html` | 左侧常驻章节导航（滚动高亮/窄屏收胶囊）+ 右侧居中阅读列 | 章节多、需来回跳转的长篇技术文档、架构说明、设计文档 |
| **C 指标看板式** | `C-metrics-dashboard.html` | 首屏大数字卡成组 + count-up 入场 + 论点公式卡 | 有基线/本次值/提升幅度的**提效数据**、性能报告、压测结论 |
| **D 新旧对比式** | `D-before-after.html` | 左右分栏冷暖对照（旧→暖红 / 新→青绿）+ 中间 VS 焊点 | 方案演进、迁移、重构 before/after、两种做法取舍 |
| **E 流程时间线式** | `E-timeline.html` | 纵向脊柱 + 编号节点依次展开（done/warn 态） | 实施步骤、上线手册、里程碑、事故复盘时序 |

> samples/ 目录可能被其他会话并行扩充（如 api-reference / stepper / bento 等），**新增骨架先在 samples/ 落一份过自检的样例、补进本表再启用**，不擅自引用未登记的文件。

## 内容→骨架选择器（自动选 · 可覆盖）

**默认自动选**：读正文，按下列判据挑一种骨架；命中多条时取**权重最高**的一条，并在开工时一句话说明「选了哪种骨架、为什么」，让用户可当场改。

| 若正文里出现… | 选 | 权重 |
|---------------|----|----|
| 明确的量化提升（`↓60%`、`p95`、耗时基线→本次值、成组指标） | **C 看板** | 高 |
| 「旧做法/新做法」「迁移前/后」「重构前/后」两两对照、方案取舍 | **D 对比** | 高 |
| 有序实施步骤、`第1步/T0/T+1`、上线/发布/复盘时序 | **E 时间线** | 中 |
| 章节 ≥4 且以「概念讲解/架构说明」为主、需长文导航 | **B 侧栏** | 中 |
| 以上都不强命中的通用长文 | **A 单栏**（保底） | 低 |

**用户可一句话覆盖**：如「用对比骨架」「换成时间线」「这篇用看板」——用户指定 > 自动判据，无条件服从，不追问、不推 A/B/C 备选方案。

## 图文表达

本 Skill 只负责网页骨架和浏览器交付；复杂内容块的工具选择交给 `@Skills/visual_markdown_toolbox.md`。当正文包含公式、数据图、UML/架构图、复杂依赖、研究谱系、伪代码或 API/Schema 表格时，按图文工具箱的平铺选择表确定表达方式，再把结果嵌入当前骨架。

## 执行协议（五步）

```
1. 拿正文 + 选骨架 → 读正文形态跑选择器（或用用户指定的骨架）；一句话报「骨架X · 理由」
2. 套正文+图文   → 复制该骨架 .html 为起点，把正文标题/段落/表格/代码/图填进对应容器；
                    复杂内容块按 `@Skills/visual_markdown_toolbox.md` 路由，选择匹配的原子表达；
                    Mermaid 图源放 <pre class="mermaid">，节点标签 <br/> 转义成 &lt;br/&gt;
3. 落炫酷硬要求  → 首屏不像白底 Markdown、关键数字主角化、概念卡片化、流式栅格 clamp() 适配
                    （细则一律以 [[Contexts/规范/炫酷建站规范]] 为准）
4. 浏览器自检    → 本地起 python3 -m http.server，用 Playwright 过自检清单：
                    若使用图文工具箱，按其自检规则检查表达块渲染；console 0 error（favicon 404 忽略）/ section 全可见 /
                    375·768·1440 三宽度无横向溢出 / count-up 能触发；清理自检残留
5. 交接         → 产物给用户 + 一句托管话术：「把这个 .html 传 CDN、返回短链，不改内容」
```

## 硬规则

1. **骨架=布局不同，不是换皮**：新增骨架必须在结构上区别于已有款（侧栏/看板/对比/时间线…），并先在 samples/ 落一份过自检的样例、补进上文骨架表，再被选择器引用。
2. **自检不可省**：任何产出的 `.html` 必须过 [[Contexts/规范/炫酷建站规范]] 的浏览器自检清单（含 375/768/1440 三宽度无溢出），未过不交付。
3. **自动选要透明**：自动选骨架时必须一句话说明选了哪种、依据哪条判据，允许用户当场改；用户显式指定则无条件服从。
4. **表达保真优先**：原文的公式、复杂图、benchmark、伪代码、软件设计图属于知识本体，不得降级成大白话流程图；具体工具选择走 `@Skills/visual_markdown_toolbox.md`。
5. **设计令牌一致**：所有骨架共享深色科技感令牌与图文表达引擎深色适配，保证同一批文档观感统一；改令牌在样例层面改，不在单篇里硬覆盖。
6. **只托管不生成**：网页由 Agent 产 `.html` 成品，纳米Work 只上传 CDN + 出短链，不改内容/样式。

## 与两个 digest 的关系

- `weekly-intel-digest` / `best-practice-digest` 的「生成炫酷网页」步骤 = 调本 Skill：把各自的纯净正文 `.md` 交给选择器→套骨架→过自检。它们的正文形态天然对应骨架（周报深挖长文→B 侧栏；提效案例带数据→C 看板 / 带前后对比→D 对比）。
- 本 Skill 不产 `.md` 正文、不产 `.meta.yaml`——只负责「正文→网页」这一段；正文与 AI 卷仍由调用方各自产出。
