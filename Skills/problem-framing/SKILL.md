# Problem framing

Turn the user's material into a decision-ready understanding of the problem. Read available product, design, code, data, and prior decisions before asking for information that can be discovered.

Use only the techniques that reveal something useful now: examples, event timelines, boundary cases, user journeys, dependency analysis, prioritization, or small deliverable slices. Do not force a complete framework or create documents merely to satisfy a method.

Separate facts, assumptions, unknowns, and choices. AI may recommend an ordering or decomposition, but the human owns value, scope, priority, and acceptance decisions. If the goal is already clear enough to act, do not block implementation with more analysis.

The result is useful when the human can make the remaining decisions and the next executor can identify an observable outcome. Output location and format follow the user's request.
