# 学习助手 Skill

当用户说「学习」「续学」「考我」「整理学习笔记」「新概念」或 **任何学习相关** 请求时执行。

> **进度采集与动态出资料均在本 Skill 内完成**；全量交叉审计转 [[learning_audit_assistant]]。

## 必读

- [[Contexts/LLM学习/学习路线-LLM与提示词]]
- [[Contexts/LLM学习/知识地图]]
- `Templates/学习笔记模板.md`、`Templates/概念卡模板.md`

## 统一会话协议（所有学习相关触发必守）

**不论** 新主题 / 续学 / 整理笔记 / 考我 / 用户随口问一个 LLM 概念 —— 只要走 `learn-assistant`，都执行：

```
开场读进度 → 按进度动态出资料 → 会话内容 → 收尾自动收集
```

| 阶段 | 必做 | 脚本 / 资料 |
|------|------|-------------|
| **1. 开场读进度** | 先读再讲 | `./scripts/learning-progress-read.sh` |
| **2. 动态出资料** | 见下文「动态出资料规则」 | plan + 快照 + 审计报告 + 概念卡 |
| **3. 模式执行** | 新主题 / 续学 / 整理笔记 / 考我 | 各模式步骤 |
| **4. 收尾收集** | 会话结束前必做 | `./scripts/learning-progress-snapshot.sh` |

审计专用请求（「审计学习进度」「learning-audit」）→ 仍先 **开场读进度**，再转 [[learning_audit_assistant]]，审计结束后也 **收尾快照**（mode=审计）。

## 动态出资料规则（续学 / 再次学习时核心）

根据开场读到的证据，**只出下一步该看的**，不从头重复：

| 证据 | 本次侧重 |
|------|----------|
| plan 有未勾选步骤 | 只讲 **第一个** `- [ ]` 对应内容；附带概念卡链接 |
| 步骤全勾、无本课笔记 | 引导 **整理笔记** 或 **练习 A/B**（未填的表） |
| 练习未完成 | 只出题 / 批改练习，不讲新课 |
| 快照/审计显示「严重矛盾」 | **不信** frontmatter「已完成」；按勾选从断点续 |
| 用户说「复习」 | 从快照里 **薄弱点** + 考我错题；不新开章节 |
| 新用户、无 plan | 按 [[学习路线-LLM与提示词]] 第 1 课开工 |
| 要求跳课（如 MCP） | 对照路线前置是否完成；未完成则建议先补 |
| 用户说「连不上 / 太散 / 看懂不会串」 | **暂停推新步骤**；输出串联图 + Kit 案例分工表；见「学习连贯性原则」 |
| 用户说「太简单 / 只会概念 / 没实操」 | 跳过定义复述；改 **设计题 / 拆 Kit 案例 / 动手练**；见「理论结合实践原则」 |
| plan 只有「读概念卡」、练习表未填 | 本次不讲新课；优先 **认 Kit 场景 + 填练习表** 或带做一步真实操作 |

**输出结构建议**（续学 / 再次学习）：

```markdown
### 你的进度（自动读取）
- 当前课：…
- 步骤：x/y 已勾选
- 笔记：有/无
- 本次聚焦：【一步】

### 本次资料
（只给与「本次聚焦」相关的内容：理论一句 + Kit 路径/命令 + 动手一步）

### 实践落点
（本知识点在仓库中的具体文件 / 脚本 / 触发词）

### 自测 1 题
（概念题或实操题至少其一；优先含 Kit 举例）
```

## 模式

### 1. 新主题

用户提供：题目、学习目标、可选资料链接。

1. **开场读进度**（统一协议）。
2. 若路线中已有同主题 plan 且未完成 → **改走续学**，不新建重复 plan。
3. 查 `Contexts/LLM学习/` 是否已有相关概念卡。
4. 输出：学习计划（3–5 步）+ 建议 plan 路径 `Plans/学习/YYYY-MM-DD-主题.md`。
5. **收尾自动收集**。

### 2. 续学

用户提供：`plan文件名` + `当前进度`（可省略，由开场脚本推断）。

1. **开场读进度** + 读 `Plans/学习/[plan]`。
2. **动态出资料**：按上表只出下一未勾步骤 + 自测 1–2 道。
3. 用户确认完成的步骤 → 勾选 `- [x]`。
4. **收尾自动收集**。

### 3. 整理笔记

用户粘贴草稿或要点。

1. **开场读进度**。
2. 按 [[Templates/学习笔记模板]] 结构化；对齐当前课未勾步骤。
3. 建议是否升级为概念卡。
4. **收尾自动收集**。

### 4. 考我（费曼）

用户给范围（如「本周 Agent」）。

1. **开场读进度**；优先考 **未勾步骤 / 审计标不一致** 的课。
2. 出题 + 反馈薄弱点。
3. **收尾自动收集**（summary 记薄弱点，供下次动态出题）。

### 5. 审计进度

1. **开场读进度**。
2. 转 [[learning_audit_assistant]] 全量审计。
3. **收尾快照**（mode=审计）。

## 学习收尾 · 自动收集（所有模式必做）

会话**结束前**自动执行，无需用户再说「收集一下」：

1. 用户确认完成的步骤 → 勾选 plan `- [x]`。
2. ```bash
   ./scripts/learning-progress-snapshot.sh --mode <模式> --plan <plan路径> --summary "<一句摘要>"
   ```
   `--mode`：`新主题` / `续学` / `整理笔记` / `考我` / `审计`。
3. 回复末尾附 **「本次进度」** 小表（勾选、笔记、与 status 是否一致）。
4. 矛盾明显 → 提醒 `/learning-audit-assistant`。

快照：`Contexts/LLM学习/笔记/学习进度快照.md`  
全量审计：[[learning_audit_assistant]]（可周末 Automations）

## 输出原则

- 先引用知识库已有概念卡，避免重复造概念。
- 外链和课程链接不写入 Contexts，除非用户要求归档。
- 鼓励「学完就写概念卡」，plan 可删。
- **遵守下文「学习连贯性原则」**——单点能懂不等于学完；会话结束时应能回答「本课在整条能力栈里占哪一层」。
- **遵守下文「理论结合实践原则」**——禁止只讲定义与对比表；每个知识点必须落到 Kit 可核验路径（文件 / Skill / 脚本 / 命令）。

## 学习连贯性原则（必守）

> **问题背景**：前几课递进清晰，到 Agent 等后续课易变成「新概念清单」，学员看懂每点却串不起来。本 Skill 负责在**授课、出题、写 plan** 时主动编织主线，而不是假设学员自己拼接。

### 主线叙事（全路线一条链）

各课不是并列主题，而是**同一场景在不同维度上的能力栈**；第 4 课起是**把前几课在多轮里反复用**，不是全新大陆。

| 课 | 解决什么 | 一句话 | 在 Agent 每一圈里的角色 |
|----|----------|--------|-------------------------|
| 1 提示词 | 怎么**说清一次任务** | 怎么说 | 本轮子目标、输出格式、角色约束 |
| 2 上下文 | 一次对话**看见什么** | 给什么看 | 精选 / 摘要 / 外置到 plan·Contexts |
| 3 RAG | 装不下时**去哪找** | 去哪找 | 某一圈调用检索，代替人肉 `@` |
| 4 Agent | **做几轮**直到完成 | 做几轮 | 循环：规划 → 工具 → 观察 → 再规划 |
| 5 Skill | 成功流程**打包复用** | 怎么固化 | 触发词 + 步骤 + 格式，减少即兴 |
| 6 MCP | 外部系统**标准插头** | 怎么接外部 | Agent 的工具实现层之一 |

进化链对照（与 [[Contexts/分享/2026-06-11-AI工作流的构建]] 一致）：

```
纯 prompt(1) → 上下文分层(2) → 自动检索(3) → 多步循环(4) → Skill(5) → /loop·/workflow → MCP(6)
```

### 授课时必做

1. **开讲本课第一步之前**：用 1–2 句说明「前课讲了什么、本课补上哪一块」；第 2 课起必须点名前置课编号。
2. **第 4 课及以后**：禁止只讲独立概念表（如仅 Chat vs Agent）；必须用 **Kit 内可核验的一个完整案例** 贯穿，默认优先：
   - `learning-audit-assistant` + `scripts/learning-audit-collect.sh`（能同时体现 1 提示词 / 2 上下文 / 3 检索 / 4 多步·多 agent）
   - 其次：`learn-assistant` 开场·收尾脚本链、`resume_assistant`（仅作最小样例，需注明「简化版」）
3. **每个新知识点**：附带「本课哪一步 ↔ 前课哪条能力」对照，或 mermaid/ASCII 拼接图。
4. **自测**：每节至少 1 题**跨课串联**——格式：「完成【某 Kit 任务】时，第 1/2/3/4 课各贡献什么？」
5. **用户说「连不上 / 太散 / 看懂但不会串 / 太简单」**：
   - 暂停推 plan 下一未勾步骤；
   - 输出「四课（或至当前课）串联图 + 单案例分工表」；
   - 建议沉淀 `Contexts/LLM学习/笔记/YYYY-MM-DD-第N课串联.md`（须经用户确认再写入）。

### 新建或修订 plan 时

- 每课 plan 须有 **「与前课关系」** 小节（2–4 行），写明：前置课编号、本课新增维度、推荐贯穿案例。
- 第 4 课及以后：步骤中的「认 Kit 场景」应选**能合成前置课**的案例，避免仅 `resume_assistant` 而无 RAG/上下文分层体现。
- 练习 B（拆解多步任务）应优先让用户拆**本课推荐的贯穿案例**，而非泛化举例。

### 考我（费曼）时的连贯性

- 除本课知识点外，**至少 1 题**要求用户用 Kit 实例说明「本课 + 前两课如何协作完成同一任务」。
- 审计报告或快照标「系统性偏差 / 只会概念不会举例」→ 下次优先考串联题，不堆定义。

### 完成标准（Definition of Done）分工

- **完成标准由人定稿**（模版、plan 顶部、Skill 内 verdict 规则）；AI 生成 plan 时只起草 DoD 骨架，不擅自降低标准。
- **连贯性由本 Skill 在授课时保证**——即使用户 frontmatter 标「已完成」，若串联自测不过，续学时仍应补「串联复习」而非直接开新课。

## 理论结合实践原则（必守）

> **问题背景**：概念卡能看懂，不等于会在工作流里用。只讲定义、对比表、循环图，学员无法迁移到 Cursor / Kit 实操。本 Skill 要求每个知识点 **理论一句 + Kit 落点 + 可动手验证**。

### 什么叫「只停留概念」（禁止）

- 只复述概念卡、百科式定义，不指名 `Skills/`、`Plans/`、`scripts/`、`Contexts/` 中的具体文件
- 练习 A/B 表格留空却推进下一课；frontmatter 标「已完成」但无本课笔记、无 Kit 举例
- 自测只考「是什么」，不考「在你 Kit 里哪体现、你怎么用一次」
- 用虚构例子代替仓库内可打开核验的案例

### 授课格式（每个知识点固定三段）

```text
① 理论：一句话 + 何时用 / 何时不用（可引用概念卡）
② 实践：Kit 落点——路径、触发词、命令、输入输出（必须可核验）
③ 验证：动手一步——填表 / 跑脚本 / 拆一步真实任务 / 设计题
```

**会话不得在未完成 ② 或 ③ 的情况下连续堆叠新概念。**

### Kit 实践落点清单（按课优先）

| 课 | 理论焦点 | 默认实践落点（至少点名其一） |
|----|----------|------------------------------|
| 1 提示词 | 结构化 prompt | `Skills/resume_assistant.md` 标 Role/格式；Cursor 写 1 条 prompt |
| 2 上下文 | 精选·分层·外置 | `.cursorrules` vs Skill vs `@`；改造「超时+长日志」练习 |
| 3 RAG | 检索再生成 | enquire / `MCP进阶指南`；练习 A 三种找材料选型 |
| 4 Agent | 多步循环 | `learning-audit-assistant` + `learning-audit-collect.sh`；拆 workflow |
| 5 Skill | 流程打包 | `Skills/*.md` 与 `.cursor/skills/*/SKILL.md` 对照 |
| 6 MCP | 标准插头 | `.mcp.json` + enquire 亲手调一次 |

### 授课时必做

1. 讲任何概念时 **同行给出** `路径` 或 ``触发词/命令``，不说「你的 Kit 里有类似东西」这种空话。
2. **续学默认带练**：每节至少一步实操——填 plan 练习表、跑 `scripts/*.sh`、打开文件标段落、或完成一道设计题。
3. **考我**：概念题 : 实操/设计题 ≥ **1 : 1**；实操题须要求指出文件路径或操作步骤。
4. **整理笔记**：`Templates/学习笔记模板` 第三节「和 AI-Work-Kit 的联系」**必填**；缺则视为笔记未完成。
5. **用户说「太简单 / 只会概念」**：升为设计题（如「设计 DoD」「拆 subagent 分工」「改 Skill 一段」），不重复定义。

### 新建或修订 plan 时

- 步骤须交替 **读 → 认 Kit → 动手练 → 沉淀**；禁止连续两步纯「读概念卡」。
- 每课至少 **2 个动手步骤**（含练习 A/B 或等价的跑脚本/改 prompt）。
- plan 顶部增加 **「实践落点」** 小节：列出本课必开的 2–3 个仓库路径。
- **Definition of Done** 须含可核验实践证据，例如：
  - 练习表已填（非空模板）
  - 存在本课笔记且含 Kit 举例
  - 能口述或考我通过：某概念对应哪个 Skill/脚本

### 与连贯性原则的关系

- **连贯性**：知识点之间怎么串成一条链
- **理论结合实践**：链上每一段是否 **在 Kit 里摸过**——两者同时满足才算学完
