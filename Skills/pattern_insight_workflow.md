# 模式洞见创作工作流

目标不是把研究笔记排成段落，而是形成用户愿意承担、目标读者愿意读完、可核验且可发布的洞见文章。

## 核心产物链

`资料 → 中文研究包 → 人的批注 → 模式卡 → 核心主张 → 研究稿 → 读者版文章 → 已自检 HTML → 知乎问答版 → 已验收草稿 → 公开链接 → 发布反馈`

研究稿与读者版必须分离：`06-draft.md` 保存论证材料和编辑记录，`06-article.md` 才是面向读者的纯净正文。研究稿不得直接进入 HTML 或发布。

## 九阶段与门禁

1. 领域校准
2. 研究立项
3. 资料发现与中文研究包
4. 基于研究包的人的阅读与批注（门禁 A）
5. 模式提炼
6. 主张确认与研究稿（门禁 B）
7. 文章润色（门禁 C）
8. 核验、HTML 与知乎发布（门禁 D + 行动时确认）
9. 反馈复盘

完整方法见 `.cursor/skills/pattern-insight-workflow/references/method.md`。

## 文章润色硬门禁

- 写正文前先完成读者入口卡：文章类型、具体角色、与主题的知识距离、当前处境、已有认知、切身利害、默认判断、读后改变与非范围。只有“技术负责人”等角色标签不算完成。
- 开场没有固定句式。技术观点文优先借鉴 Nature 的同心入口：“共同现状 → 直接压力 → 解释缺口 → 核心判断”；前 150–250 个汉字先完成读者定向，再承担吸引功能。
- “冲突开场”不等于第一句必须讲故事或案例。案例只有在读者能立即识别场景、理解切身利害、无需陌生术语并知道它将证明什么时才能前置；否则先补最小背景和问题框架。
- 先区分研究结果型、技术观点型与案例复盘型。没有真实项目证据时，不得把假设场景写成真实事故复盘；Nature 的结构用于学习信息依赖与跨领域可读性，不机械复制学术格式。
- 全文只服务一个可反驳的核心主张；材料是证据，不是章节目录。
- 用读者问题链而不是材料目录组织章节；每节只回答一个读者此刻自然会问的问题，并按“旧信息连接 → 新信息推进”桥接新概念。
- 正文只保留主叙事、最强证据、必要边界和行动含义；完整方法、协议、架构细节与次要证据进入补充层，不把研究充分等同于把所有材料塞进正文。
- 删除“本期研究、材料一、AI 推断、门禁、待确认”等过程语言。
- 将清单改造成因果推进、张力、反方与回应；只有真正需要比较时才保留列表。
- 标题承诺明确收益或冲突；结尾完成观点闭合，不复述目录。
- 正文稳定后调用 `visual-markdown-toolbox` 做一次关系扫描：出现三步以上流程、三个以上模块、状态变化或反馈闭环时，优先增加 1–2 个可编辑的流程图或架构图，并在图后解释关键边与读者应看到的关系。
- 图源优先 Mermaid、PlantUML、D2 或 Graphviz，不把所有关系都硬画成普通 flowchart；没有结构价值时可以不画。
- 用户必须明确判断“这已经是值得目标读者读完的文章”，才能通过门禁 C。
- 门禁 C 还要执行释义测试：只读标题和前 150–250 字，目标读者能说出“写给谁、为什么现在值得读、作者主张什么”；逐节反向提纲能说明本节回答的问题和新增判断。

完整规则与来源见 `.cursor/skills/pattern-insight-workflow/references/reader-centered-writing.md`；质量检查见 `.cursor/skills/pattern-insight-workflow/references/quality-rubric.md`。

## HTML 生成硬门禁

- 仅以已通过门禁 C 且完成事实核验的 `06-article.md` 为输入。
- 门禁 C 通过后以当时正文为内容基线。新增/删除核心观点、改变结论或适用边界、引入新的事实论据时，门禁 C 自动失效；必须在发布包记录变更摘要并重新完成事实核验与门禁 C。纯排版、交互和不改变论点的视觉变更不使 C 失效，但必须重跑受影响的渲染自检。
- 生成 HTML 前先在发布包锁定视觉资产清单：文本图表、确定性渲染图和生成式图片的对应段落、表达任务、文件路径与数量；封面不是默认必需资产。
- 强制调用 `html-generate`，透明选择内容骨架，生成 `07-article.html`。
- HTML 阶段只做信息层级、视觉表达和交互增强，不擅自改写核心正文；发现内容缺陷退回文章润色阶段。
- 必须完成本地浏览器自检：console 无错误、内容区完整可见、375/768/1440 三宽无横向溢出、图表正常渲染。
- 用户明确要求封面或生成式图片时，先生成并人工检查语义贴切性，再保存为项目本地资产；发布包记录最终提示词、用途、路径、尺寸和预览结论，并验证图片加载及 375/1440 首屏裁切。
- HTML 是默认必交付产物；只有用户明确说“不需要网页”才可跳过，并记录在 `STATUS.md`。
- 未经用户批准不得上传、发布或发送；进入知乎草稿前必须通过门禁 D。

## 知乎发布硬门禁

- 默认发布渠道为知乎问答；先确定目标问题、发布账号和读者匹配度，再从 `06-article.md` 生成 `08-zhihu-answer.md`，不得把研究稿直接粘贴到平台。
- 用户指定知乎独立文章时，改用 `{NN}-zhihu-article.md`，并按 `.cursor/skills/pattern-insight-workflow/references/zhihu-independent-article.md` 实测当前字段；不得继续套用问答配置。
- 平台稿开头必须直接回答问题，保留核心主张和引用边界；可针对问答场景调整标题、长度和段落，但不得偷偷改变论点。
- 独立文章相关性由标题、首屏 150–250 字、封面语义和 2–3 个平台真实话题共同建立；当前编辑器没有独立摘要字段时不得虚构摘要配置。
- 优先把 Markdown 中已审核的流程图、架构图渲染成 SVG/PNG 后上传；这些确定性渲染图不计入生成式图片额度。
- AI 生成插画默认不生成，确有表达价值时最多 1–2 张且绝不上探。每张必须写清“对应正文哪一段、承担什么表达任务、为什么文本图表不能替代”；说不清或预览不贴切就删除，不为凑封面保留。
- 独立文章封面若生成，统一到 1440 × 810，同时验收 16:9 原图和 3:2 居中裁切；关键语义必须处于中央安全区。
- 图片必须从本地文件上传，正文不得残留 `file://`、本地绝对路径或失效占位符。
- 使用内置浏览器写入知乎草稿后，通用核验正文、标题层级、图片、外链、自动保存和按钮；独立文章额外核验新发布/更新、标题、封面、话题、投稿至问题、创作声明和内容来源。投稿至问题最多 1 个，没有强匹配就保持未选择。结果写入 `07-publish-package.md`。
- 门禁 D 要求用户明确批准“内容 + 账号 + 发布位置”。最终点击属于公开代表性操作，必须在按钮前再次说明账号、位置或目标 URL、标题、字数、标题数、正文图片、封面、链接、话题、投稿至问题、声明、来源和按钮名称，并取得用户行动时确认。
- 发布成功后把实际链接、账号、时间和结果写回发布包；失败时保留草稿并记录错误，不得反复点击或假定已经发布。

## 所有权

- AI：选源、中文翻译总结、证据索引、反方材料、结构、事实核验、润色、HTML、自检、发布版本和反馈归档。
- 用户：阅读中文研究包后的原始判断、核心主张、价值判断、文章声音、门禁 C/D、知乎发布位置与最终点击授权。
- 明确区分来源事实、用户观察和 AI 推断；用户未确认的实质判断不得伪装成用户洞见。

## 中文研究包硬门禁

- 找到 5 份角色不同的核心材料后，必须生成 `02-research-pack.md`；不能只给链接或要求用户默认阅读原文。
- 每份材料用中文完成翻译式总结：问题、主张、机制、证据、局限/反方、与本期关系和判断题。翻译式总结不是全文逐字翻译。
- 原文链接及章节/页码只放在材料末尾供核验；正文不得大段粘贴原文。
- 门禁 A 默认基于中文研究包。只有用户主动要求核验具体结论时，才回到原文定位。
- AI 承担语言与检索成本，但不能替用户形成同意、反对、惊讶和跨材料连接。

## 反馈闭环

文章被评价为“像笔记、没人会看”，必须退回阶段 7；被评价为“上来举例无法带入、看不出与我有什么关系”，归因为读者入口卡或开场定向失败，先修读者模型、利害和旧→新信息桥接，不得只换案例、缩短句子或用 HTML 美化掩盖。完成实质工作后更新 `STATUS.md`；一期完成后追加 `insight-ledger.md`，不覆盖历史。
