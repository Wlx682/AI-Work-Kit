## 门禁 A 批注

- **原来以为：** 实践应从评估开始，不急于完成整个控制系统。
- **现在注意到：** 评估不是天然可信的上游事实。条件定义、参照物或评分机制一旦虚假、失真或没有参考价值，上一篇控制母模型的观测、判断和干预假设就失去基础。
- **核心冲突 / 认知变化：** “评估优先”也可能制造假确定性。为了让流程跑完而强行给出分数或通过结论，会把未知包装成证据，比暂时没有评估更危险。
- **同意/不同意：** 评估必须靠谱；允许人工辅助，不能为了完成评估而强行完成。
- **跨材料连接：**
  - 对应 OpenAI 的 Harness 与有效性检查：结论必须限定于明确配置和可支持的主张，坏题、Reward Hacking 和失真 Harness 都会让分数无效；
  - 对应 Anthropic 的参考解、人工校准和轨迹复核：自动评分器不是天然真值；
  - 对应 Benchmark Lottery：任务和聚合方式本身携带价值选择，统一分数可能掩盖关键缺口；
  - 对应 DSH GUI 事故：选错验收对象后，HTTP 200 和替代服务成功会形成完全错误的“通过”。
- **由此形成的约束：**
  1. “不可评”“证据不足”“需要人工裁决”必须是合法结果；
  2. 先验证任务、参照物和评分器，再用它们验证 Agent；
  3. 自动化覆盖率不能高于评估可信度，低置信场景默认升级人工；
  4. 评估完成率、全量出分率不能成为团队 KPI。
