# 核心主张

- 大多数人认为：把 Agent 接入生产，关键是补齐日志、权限、工作流编排、评估和一个随时可点的暂停按钮。
- 我观察到：这些能力分别解决局部问题，却没有回答被控对象是什么；当 Agent 横跨多轮上下文、工具和现实环境时，局部控制仍可能同时“成功”却共同偏离目标。
- 真正起作用的机制：把 Agent 视为任务环境中的下层控制器，把 Agent—工具—工作对象—环境—人视为完整被控闭环；上层监督系统通过事实投影、状态估计、偏差与余量、分层控制输入和现实结果校准，改变 Agent 可以继续自主行动的条件。
- 可反驳核心主张：智能体生产系统真正要控制的不是模型输出，而是 Agent 改变世界的条件；不建立完整闭环的控制母模型，功能清单无法累积成生产可控性。
- 只在什么条件下成立：长任务、跨步骤、使用工具、存在现实副作用或延迟结果；不声称所有单步问答都需要完整控制面。
- 对读者意味着：先投资参考契约、事件事实、状态投影、控制接纳、能力边界、效果对账和恢复，再决定需要哪些平台页面与编排功能。
- DSH 与控制系统的关系：DSH 是可替换的下层 Agent Runtime；out-of-tree DSH 控制插件实现传感与控制接纳；框架无关控制面负责状态估计、偏差与监督决策；高权限 Safety Executor/Watchdog 负责不可旁路执行与降级。采用 DSH 不等于 fork DSH，也不等于让控制面重写 Agent Loop。
- 最强证据：Harness 生命周期和纯投影机制暴露了运行时存在多个不同接纳点与事实层；其 GUI 事故复盘证明内部动作成功不能替代外部世界正确。它们支持母模型，但不单独证明母模型已成立。
- 最强反方观点：LLM 不可精确建模，控制论类比会制造虚假确定性；回应是本文不控制隐藏思维、不预测 token，只控制可观测、可执行、可验证的运行条件和现实副作用。
- 用户确认：已确认。依据为用户要求从 AI Agent 视角和工程控制论重建系统、明确吸收 Harness，并要求根据该母模型撰写并发布文章。
