# 模式图

## 模式卡 1：控制对象错了，功能越完整越可能偏离

- 可反驳表述：若没有先界定 Agent—工具—环境—人的下层闭环，日志、编排、评估和治理功能越丰富，也不能自动形成有效控制。
- 来源事实：控制论从系统关系建模；Harness 生命周期显示控制点分散于 Turn/Step/Tool；事故复盘显示局部成功不等于现实目标成功。
- 用户连接：用户明确反对一次次临时添加模块，希望从 AI Agent 系统本体重建。
- 最强反例：在高度确定、单步、无外部副作用任务中，日志加权限可能已经足够。
- 边界：主张面向长任务、跨步骤、有工具或现实副作用的生产 Agent。
- 缺失证据：真实生产任务对照实验。
- 置信度：高（架构解释），中（生产收益）。

## 模式卡 2：命令是信息，生效才是控制

- 可反驳表述：控制系统若不区分命令发送与 Runtime 实际接纳，就无法计算控制生效率。
- 来源事实：Harness 的 follow-up、claim、pre-step 和 tool boundary 具有不同时间语义。
- 用户连接：母模型已引入 `u_cmd / u_applied / ControlApplicationReceipt`。
- 最强反例：完全同步且单线程的封闭执行器中，调用返回可能近似等于接纳。
- 边界：异步 Agent Runtime、长任务、并发工具和可取消执行。
- 缺失证据：接纳延迟的生产分布。
- 置信度：高。

## 模式卡 3：事实投影与认识估计必须分账

- 可反驳表述：把事件折叠和不确定推断放入同一个 StateEstimator，会让系统无法区分日志错误、投影错误和估计错误。
- 来源事实：Harness Session Projection 要求纯同步折叠；工程控制论强调观测、状态和模型适用性。
- 用户连接：母模型拆为 M4a Deterministic Projector 与 M4b Epistemic Estimator。
- 最强反例：极小原型可暂时在同一进程实现，但仍需逻辑分账。
- 边界：分层是语义边界，不强制拆成微服务。
- 缺失证据：不同状态族的估计校准率。
- 置信度：高。

## 模式卡 4：稳定不是输出一致，而是损失和恢复仍有边界

- 可反驳表述：开放语义 Agent 的稳定性应由目标、资源、影响、证据和恢复是否有界来定义，而不是多次输出是否相同。
- 来源事实：经典控制关注稳定、扰动和误差；Agent 输出具有随机性；Harness 事故说明内部完成可能偏离现实对象。
- 最强反例：对结构化、封闭答案任务，输出一致性仍可成为一个局部指标。
- 边界：稳定余量必须由具体任务数据校准，不能先合成单一健康分。
- 缺失证据：余量与真实失败之间的预测关系。
- 置信度：中高。

## 模式卡 5：Runtime、控制接缝与控制系统不能混为一层

- 可反驳表述：把可组合 Agent Runtime 直接称为“智能体控制系统”，会同时遗漏上层状态估计/监督决策和不可旁路的现实执行边界；反过来在控制面重写 Agent Loop，也会制造重复 orchestration。
- 来源事实：DSH 原生拥有 Session、Agent Loop、Turn/Step、Prompt 与 Tools，并通过 Cordis 插件暴露生命周期和能力接缝；母模型另外定义 StateEstimate、Deviation、ControlDecision、ContinuationLease、Safety 与 Outcome Calibration。
- 用户连接：用户直接反馈未看懂 DSH 与自己的控制系统的关系，证明此前按机制罗列不足以表达系统边界。
- 最强反例：只做研究原型且不触达外部副作用时，Runtime 插件可以临时把观测、控制和执行放在同一进程。
- 边界：逻辑职责必须分层，但不强制每层都是独立微服务；安全边界按权限/信任域而不是代码包装形式判断。
- 缺失证据：DSH out-of-tree 控制插件与现有 LangGraph Adapter 的同契约 Spike。
- 置信度：高（架构边界），待验证（Runtime 选型）。
