## 2026-08-14 · Agent 智能内核与编排主线修正

- 用户反馈：Agent 的核心价值来自各自性格和认知优势，系统主要任务应是对 Agent 进行编排；质量控制面只是治理层，不能与智能并列成“双引擎”。
- 影响判断：P0 架构变更。原 Gateway、账本、安全内核和控制论闭环继续成立，但从系统本体下沉为横切治理层；原单 Agent 控制面目标不足以证明系统产生智能价值。
- 修订：架构改为“Agent 智能内核 → Agent Orchestration Core 编排主干 → Quality Governance Layer 横切治理”；新增 AgentConfiguration、条件性 TraitEstimate、TaskDemandProfile、AgentTaskFit、RoleAssignment、CollaborationPlan、AutonomyEnvelope 和 ProductiveOutcome。
- 防误用：性格不采用固定人设或 Agent 自述，而采用按配置、任务域和阶段生效的可证伪行为特征；保留探索配额、反事实对照、跨域退化和 Profile 时效，避免历史分工自证循环。
- 验证：生产编排使用 P/Q/R 对照验证默认 Agent、特征匹配、动态角色/协作/自主权的净收益；治理层继续使用 A/B/C 故障实验，两套实验正交运行。
- 当前状态：文档主线已从“控制不确定 Agent”修正为“编排 Agent 产生价值，治理层约束现实后果”；仍需真实 Agent 配置、任务集、盲评者和延迟业务结果验证。

## 2026-08-14 · 取消“LLM 可精确控制”前提，补齐评估与进化产品闭环

- 用户反馈：即使工程控制论映射严谨，只要默认 LLM 的内部状态可估计、偏差可计算、反馈后会收敛，仍是对 LLM 的根本误判；最终必须是一套业务用户真正能使用、能够编排、评估和进化的 Agent 系统。
- 参考输入：用户提供的生产级 Agent 管理系统思考保留了分层、持久任务、最小权限、离线/在线评价、灰度和人工接管；未直接采纳固定“规划—执行—反思”、原样重试、单一 Judge 与自动自我优化等隐含确定性假设。
- P0 修订：明确 LLM 输出不可精确控制、隐藏认知不可观测、干预响应非单调、自评可能同源；工程控制论只保留在 MissionRun、资源、权限、退款/券外部状态和现实副作用。
- 产品化：新增 Mission Designer、Agent Roster、Orchestration Canvas、Run Center、Evaluation Center、Evolution Lab、Governance Center 的用户闭环。
- 评估：EvalSuite 冻结，多次采样，规则/工具事实/Judge/人工/业务结果分源，输出区间、缺失和 FailureSlice，`Inconclusive` 为合法结果。
- 进化：Agent、提示、技能、工具、记忆和编排只通过不可变 EvolutionCandidate、离线/影子/灰度实验、人工晋级、Release 血缘与回滚改变；禁止线上原地自改和自评自批。
- 当前状态：实施级契约已补齐，但没有真实用户、任务样本、人工 Rubric、AgentVersion 与延迟结果前，不能证明系统可用或进化有效。
