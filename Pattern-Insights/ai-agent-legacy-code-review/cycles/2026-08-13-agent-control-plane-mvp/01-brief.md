# 研究立项

## 主问题

智能体作为下一代生产工具，如何通过覆盖系统全部内容和状态变化的详尽监控，建立人类可驾驭的精细控制，把模型的不确定能力转化为可委托、可验收、可追责、可恢复、可持续进化的生产能力？

## 当前研究主线

**详尽监控 → 精细控制 → 生产工具化**

- 详尽监控：建立智能体系统的动态镜像，重建主体、意图、认知材料、判断、行动、状态变化和真实结果之间的关系。
- 精细控制：基于动态镜像，对意图边界、上下文、状态、权限、行动、资源、产物、故障恢复和进化实施精确约束与干预。
- 生产工具化：使智能体达到可委托、可检查、影响有界、成本可预期、可中断、可恢复、可追溯和可安全进化。

这里的“精细”不是逐步骤微操，而是让系统在保留自主性的同时，把不确定性限制在可观察、可干预、可恢复的边界内。

## 与上一篇文章的关系

上一篇《代码全绿，任务却错了：AI Agent 的错误已经迁移到系统层》完成了问题定义：代码断言仍然有效，但它无法覆盖任务意图、跨环节传递偏差和系统级完成判断；智能体系统需要生成与探索、证据与控制、受控进化三个平面。

本期不再重复论证“为什么需要控制”，而是回答“第一个可以落地运行的控制系统究竟长什么样”。目标是把三平面架构压缩成一个可实现、可验证、可逐步扩展的最小闭环。

## 为什么现在值得研究

上一篇停留在架构原则层。如果不能进一步给出运行对象、状态机、控制点和最小数据契约，“可断言”仍会退化成增加规则、增加评审或堆叠 Agent。团队需要一条更具体的分界线：哪些能力必须进入运行时，哪些规则可以以后通过进化环补齐。

## 目标读者与困境

目标读者仍是正在中型团队和遗留代码库中引入编码 Agent 的技术负责人、架构师和工具链负责人。

他们的困境不是缺少另一个会写代码的 Agent，而是不知道如何把现有 Agent 放进一个可控系统：

- 任务何时从“模型认为做完了”变成“系统允许完成”；
- 哪些证据必须伴随代码、测试和方案一起流转；
- 高风险工具调用在哪里隔离，失败后回到哪个状态；
- 真实结果如何反哺评估器，而不让系统直接自改规则。

## 暂定假设

- 最小系统的核心不是一个更强的主 Agent，而是一个独立于生成模型的控制回路。模型可以提出行动和完成声明，但不能自行批准高风险副作用，也不能自行把任务置为 Done。
- 系统的最小运行对象不是聊天消息，而是六类可版本化对象：`TaskContract`、`ActionIntent`、`Evidence`、`Checkpoint`、`CompletionDecision`、`EvolutionCandidate`。
- 最小控制面只需要七个职责模块：任务契约、Agent Runtime、行动代理、证据账本、完成门禁、恢复管理、结果评估；进化流水线消费失败证据，但不直接参与当前任务的即时判断。
- “可断言”不等于给开放任务预先写完正确答案，而是给完成声明定义可验证的证据义务：目标覆盖、约束未破坏、关键结果经过外部验证、未知副作用已被隔离、失败路径存在有效恢复点。
- 完成门禁必须输出带理由的三值判定：`pass`、`fail`、`unknown`。`unknown` 不能被默认当作 `pass`，而应触发补证、降级或人工接管。
- 执行环与进化环必须通过候选产物解耦。一次漏判只能生成 `EvolutionCandidate`；只有经过历史回放、对照评估、批准、灰度和回滚准备后，才可以改变评估器、提示、技能或工作流。
- 第一版不需要多智能体自治编排。先让单 Agent 在统一控制面下可靠运行，能更早验证控制对象和闭环是否成立；多 Agent 是后续扩展，不是 MVP 前提。

### 待验证的最小运行链

1. `TaskContract` 固化目标、边界、风险等级和完成所需证据。
2. Agent Runtime 生成计划或 `ActionIntent`，不直接执行有副作用的动作。
3. 行动代理按权限、预算、幂等性和风险策略决定执行、拦截或转人工，并在执行前建立 `Checkpoint`。
4. 每一步的输入、输出、工具结果和断言结果写入追加式证据账本。
5. Agent 发出完成声明后，完成门禁根据证据义务生成 `CompletionDecision`，而不是信任自然语言自报完成。
6. 任务进入真实环境后的结果由结果评估器回写，暴露“当时通过、事后错误”的漏判。
7. 漏判、误判和高成本人工接管生成 `EvolutionCandidate`，进入独立的回放、批准、灰度与回滚流程。

## 推翻证据

- 如果一个只依赖任务结束后结果验证、而不引入独立完成门禁的方案，能以更低成本达到相同的静默失败发现率，则“完成门禁是 MVP 核心”需要缩小。
- 如果团队无法为开放任务稳定表达最低限度的证据义务，且 `unknown` 长期占多数，说明 `TaskContract + CompletionDecision` 可能不是可用的主控制接口。
- 如果追加式证据账本无法显著缩短失败定位和恢复时间，只产生观测成本，则需要减少证据粒度或更换观测面。
- 如果将行动执行与生成模型隔离并未降低未知副作用或恢复成本，则行动代理与检查点不应被视为所有任务的强制路径。
- 如果失败样本经过回放仍不能可靠区分规则改进与过拟合，则进化环只能保持人工治理，不能逐步自动化。

## 本期不研究

- 不设计通用 AGI、自主公司或无限层级多智能体组织。
- 不比较具体基础模型的代码能力排行。
- 不把提示词模板、角色设定或 Agent 数量当作系统架构主体。
- 不一次性穷举所有业务规则和评估器。
- 不在本期给出完整生产级 UI、部署拓扑和厂商选型；只讨论验证控制闭环所需的最小实现。

## 时间盒与停止条件

- 首批仍只选 5 份角色不同的核心材料，至少包含一份真实生产架构或事故复盘，以及一份反对“重控制面”或揭示监控局限的材料。
- 用户至少实质批注 2 份关键材料，门禁 A 才通过。
- 研究必须产出：模块边界、核心对象/字段、任务状态机、完成门禁协议、错误与恢复路径、执行环—进化环的数据流。
- 用一个遗留代码改造任务走通 happy path、`unknown` 补证、危险行动拦截、事后漏判进入进化环四条场景。
- 新材料连续两次不再改变核心对象、状态机或模块边界时停止扩展资料。
