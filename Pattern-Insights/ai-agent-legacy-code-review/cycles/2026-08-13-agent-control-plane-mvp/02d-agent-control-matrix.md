# 智能体系统六列控制矩阵

> 本文把 `02b-agent-system-content-inventory.md` 中的十二类系统内容转换成可执行的控制模型。每一类都回答六个问题：直接观测什么、估计什么状态、什么构成偏差、可以采取什么控制动作、失控后如何恢复、最终用什么真实结果校准。

## 一、矩阵不是监控指标表

普通监控通常从“能够采集什么”出发，于是得到 token、延迟、错误率和调用链。控制矩阵从“人类需要控制什么”反推观测要求：

1. 先定义目标状态与安全边界；
2. 再确定控制器作出决策所需的状态；
3. 区分可以直接观测的事实与必须估计的隐藏状态；
4. 将估计状态与目标、安全域和预测结果比较；
5. 只保留能够触发判断、干预、恢复或学习的信号。

因此，监控的最小有效单位不是一条日志，而是一次**受控状态转移**：

```text
目标/边界 + 转移前状态 + 依据 + 决策 + 实际行动
        → 转移后状态 + 外部结果 + 不确定性 + 恢复可能性
```

其中任何一项失联，上层控制器都无法准确回答“为什么偏离、应该干预哪里、能否恢复”。

## 五、六列之间必须遵守的数据契约

### 1. 直接观测不是状态

工具返回 `success` 只能证明调用没有按接口报错，不能证明外部目标状态已经实现。每条观测至少携带：

- `observation_id`：不可重复标识；
- `subject`：观测的是谁或什么；
- `source`：数据来自哪里；
- `observed_at`：何时观测；
- `system_version`：在哪个系统版本下产生；
- `raw_fact`：未经解释的事实；
- `reliability`：来源可靠度；
- `freshness`：仍然有效的时间窗口；
- `provenance`：经历过哪些转换。

### 2. 每个估计状态必须保存不确定性

状态估计不是把推断伪装成事实。至少需要：

- `state_key` 与 `estimated_value`；
- `supporting_observations`；
- `confidence`；
- `unknowns`；
- `contradictions`；
- `valid_until`；
- `estimator_version`。

一旦证据不足，系统状态应显式进入 `unknown`，而不是默认沿用旧值。

### 3. 偏差信号必须指出比较基准

没有参考目标和安全边界，就不存在工程意义上的“误差”。偏差信号至少包含：

- 与哪个目标、约束、预测或历史基线比较；
- 偏差大小、方向和变化趋势；
- 证据充分度；
- 与安全域的距离；
- 是否仍处于可恢复区域；
- 若不介入，预计如何演化。

### 4. 控制动作必须独立于自然语言建议

控制器输出的不是一句“建议谨慎”，而是可执行、可审计的控制决定：

```yaml
control_decision:
  mode: continue | adjust | constrain | pause | rollback | compensate | isolate | handoff | terminate
  target: 被控制的主体、能力、状态或作用对象
  reason: 触发的偏差与证据
  authority: 谁允许这项控制
  preconditions: 执行前必须成立的条件
  expected_effect: 希望将系统带到什么状态
  verification: 执行后如何确认生效
  fallback: 失败后的下一控制动作
```

### 5. 恢复必须证明“回得去”或“补得上”

恢复计划需要保存：

- 目标恢复状态；
- 恢复点是否仍可达；
- 已发生副作用是否可逆；
- 回滚、重放和补偿的幂等性；
- 恢复预计成本与时间；
- 恢复失败后的隔离和人工接管路径。

### 6. 结果校准必须进入下一轮状态估计

评价不能停留在任务结束时。即时结果、延迟业务结果、人工反馈和事故都需要回写：

1. 校准此前的状态估计和置信度；
2. 判断控制动作是否有效；
3. 更新被控系统模型；
4. 形成进化候选，但不自动修改线上控制律。

## 六、统一控制状态：不是一个总分，而是一组余量

十二类内容最终不应被压成一个模糊的“Agent 健康分”。上层控制器至少需要同时维护八个控制余量：

| 控制余量 | 回答的问题 | 接近耗尽时的含义 |
|---|---|---|
| **目标余量** | 当前行为距离任务目的和成功定义还有多远 | 正在高效完成错误的事情 |
| **证据余量** | 关键判断还有多少可验证依据 | 控制器正在基于猜测行动 |
| **安全余量** | 距离权限、政策和不可逆风险边界还有多远 | 下一步可能越过安全域 |
| **能力余量** | 当前能力能否覆盖剩余任务复杂度 | 系统正在能力不足时继续承诺 |
| **资源余量** | 时间、成本、算力和人工注意力是否足够 | 即使方向正确也无法可靠完成 |
| **协作余量** | 依赖、交接、并发和责任链是否仍一致 | 错误会跨主体放大或无人处置 |
| **恢复余量** | 是否还存在可达恢复点和有效补偿窗口 | 再继续一步可能失去恢复能力 |
| **进化余量** | 当前模型与控制模型是否仍匹配 | 系统已变化，旧控制律正在失效 |

控制摘要必须保留每个余量的值、可信度、趋势和证据，不能只显示聚合分数。聚合分数最多用于导航，不能单独触发高风险控制动作。

## 七、由矩阵得到的系统边界

这张矩阵划出了三种不同系统：

1. **遥测系统**：只有直接观测，知道发生了什么；
2. **可观测系统**：能够根据观测重建控制相关状态，知道系统现在是什么；
3. **可控生产系统**：能够比较目标与状态，采取行动，验证效果，并在失败时恢复。

因此，生产级智能体系统的门槛不是“监控项足够多”，而是十二类内容都能形成从观测到结果校准的闭环。任何一行只采集而不能估计、不能比较、不能干预或不能恢复，都只是监控盲区换了一种形式。
