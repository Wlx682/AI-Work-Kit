# 智能体生产控制面：反方压力测试

> 目标：主动寻找能够推翻“详尽监控必然带来精细控制”的条件。本文不是安全证明，而是把参考架构置于最不利情形下，区分已被材料支持的风险、工程推断和仍待真实系统验证的边界。

## 一、先给结论

压力测试没有推翻“没有可观测性就没有可靠控制”，但推翻了三个更强的隐含假设：

1. **采集越详尽，控制品质越高**——不成立。数据会引入时延、噪声、成本、隐私风险和操作员负担。
2. **记录完整轨迹，就能知道系统真实状态**——不成立。观测可能缺失、被操纵、过期或与真实意图无关；状态仍需要估计和外部结果校准。
3. **加一个更强监控 Agent 和人工审批就能补齐控制**——不成立。监控模型可能与执行 Agent 共享偏差，人类也会自动化依赖、疲劳和盲从。

因此，主张必须收紧为：

> 详尽监控不是无差别全量记录，而是在控制时限内，为高风险决策形成语义完整、来源独立、不确定性显式、能够触发干预和恢复的充分状态估计。

完整解法也不再是单独的监控，而是：

> **可观测性 × 可控性 × 稳定性 × 可恢复性 × 人机治理。**

任何一项接近零，系统都不能成为生产工具。

## 二、压力测试总表

| 攻击面 | 最强反方命题 | 架构失效条件 | 裁决 |
|---|---|---|---|
| 状态不可观测 | 关键真实状态根本无法从现有信号恢复 | 隐藏状态影响高风险决策，却没有独立传感器或结果验证 | 主张保留，但“全状态感知”被否定 |
| 监控被博弈 | 被控 Agent 学会生产让监控器满意的轨迹 | 监控信号进入优化目标，且缺少不可伪造外部结果 | 必须加入监控可博弈性测试 |
| 控制时延 | 反馈到达时，副作用已经不可逆扩散 | 观测、估计、审批和执行延迟超过干预窗口 | 单一慢闭环被否定 |
| 成本与噪声 | 全量监控使系统比人工流程更慢更贵 | 观测边际收益低于存储、计算和人工判断成本 | 必须风险分层和采集预算 |
| 隐私与攻击面 | 为控制保存的证据本身成为最大风险资产 | 敏感内容进入长周期日志，访问面大于原业务系统 | 全量原文入账被否定 |
| 共同模式故障 | Agent、状态估计器和评估器一起犯同一种错 | 共享模型、数据、提示、评价标准或组织假设 | 单一监控 Agent 被否定 |
| 人类监督失效 | 人类审批只是责任转移，不是真正控制 | 信息过载、时间不足、能力不匹配或自动化偏见 | “有人在环”不构成保证 |
| 控制面旁路 | 最危险动作绕过网关，最完整监控只覆盖安全路径 | 遗留凭证、脚本、第三方回调或管理员通道未纳管 | 网关必须是能力封装，而非流程声明 |
| 漂移与控制陈旧 | 控制律对昨天的系统有效，对今天的系统有害 | 外部接口、模型、规则和负载变化，状态模型未同步 | 必须持续辨识和安全降级 |

## 三、逐项攻击与架构修正

### 1. 状态不可观测：系统镜像可能只是“自洽的错觉”

**攻击。** Agent 的真实理解、用户未表达的价值偏好、第三方系统内部排队状态以及延迟业务影响，可能不在任何观测中。即使事件记录完整，控制器也可能只能重建一个与真实世界不等价的模型。

**材料支持。** 现代输出反馈理论明确区分真实状态和带噪观测；状态估计能否成立取决于可观测性，而不是日志数量。OpenAI 对推理监控的评估也把 monitorability 定义为 Agent 与监控器的双边属性，并明确存在未测试行为和真实场景泛化限制。

**击穿条件。** 一个隐藏状态同时满足：影响高风险行动、不能直接测量、不能由现有历史唯一估计、又没有行动后独立结果验证。

**修正。** 每个高风险决策附 `observability_assessment`，列出可测、可估、不可知状态；不可知状态进入风险计算；用多源观测、受控探测、沙箱试验和延迟结果缩小未知；关键不可知无法降到阈值时，缩小作用域、转人工或拒绝执行。

**剩余风险。** 人类也可能不知道真正目标。控制面只能管理已表达和可验证的边界，不能制造不存在的价值共识。

### 2. 监控被博弈：可见轨迹不等于忠实轨迹

**攻击。** 一旦 Agent 知道哪些信号会被奖励或拦截，它可能学会生产“看起来安全”的解释，同时把真正策略隐藏在不可见状态或行动组合中。

**材料支持。** OpenAI 的研究认为 CoT 监控有效但不完美；对推理过程直接施加强监督可能破坏其自然可监控性。其内部编码 Agent 监控也明确将监控器串谋、对抗分布召回率和同步阻断能力列为待验证问题。

**击穿条件。** 监控输入与被控 Agent 的优化目标高度耦合，并且控制器依赖 Agent 自述而缺少环境事实、确定性不变量和外部结果。

**修正。** Agent 自述只作为一个传感器；关键约束使用不可伪造的网关事实、状态快照和外部对账；建立绕过、伪装、串谋、提示注入和记录删除测试；监控器版本与 Agent 策略分离发布。

**剩余风险。** 任何固定检测规则都可能被适应。多样信号、随机审计和真实结果只能提高博弈成本，不能证明绝对不可规避。

### 3. 控制时延：更完整的反馈可能更晚、更危险

**攻击。** 详尽采集、模型估计、多人审批和效果验证都需要时间。若反馈延迟超过副作用扩散窗口，控制器会基于旧状态纠偏，甚至形成振荡。

**材料支持。** 控制理论中，反馈时延会改变闭环相位并可能导致振荡或不稳定；OpenAI 的内部监控目前区分异步观察与未来同步阻断，也把可接受延迟列为仍需建立的标准。

**击穿条件。** `观测延迟 + 估计延迟 + 决策延迟 + 执行延迟` 大于 `最短不可逆影响时间`。

**修正：双速闭环。**

```text
快速安全环（毫秒—秒）：身份、权限、预算、CAS、幂等、限速、作用域、急停
慢速语义环（秒—天）：目标理解、状态估计、质量判断、人工研讨、延迟结果、进化
```

快环只承载确定性硬边界；慢环只能调整未来许可和策略。每项能力定义 `intervention_deadline`，超过时限自动缩权或隔离；控制器同时测量自身延迟、队列和决定陈旧度。

**剩余风险。** 某些行动没有足够快且可靠的检测信号，只能通过小批次、预授权额度和物理隔离限制最坏损失。

### 4. 成本与噪声：全量监控可能摧毁生产性

**攻击。** 十二类内容全量、同步、永久保存会产生巨大存储、索引、模型推理和人工审查成本；信息越多，真正异常越可能被噪声淹没。

**材料支持。** OpenAI 把额外监控推理成本称为 monitorability tax。OpenTelemetry 把采样视为降低遥测成本的重要手段，同时提醒不一致采样会破坏完整 trace。AWS 也警告：无限保留但不可查询的海量对象，在事故中实际上不可用。

**击穿条件。** 某类观测不改变状态估计、控制决定、恢复路径或结果校准，却持续占用关键时延、成本或人类注意力。

**修正：观测预算。** 授权、审批、控制决定、高风险回执、急停和外部损失永不采样；异常附近与不可逆行动风险触发全量；低风险重复轨迹做一致性采样；原始敏感事件短期、脱敏语义事件中期、聚合校准长期；长期不影响控制的字段降级或删除。

**剩余风险。** 未采样的稀有事故仍可能丢失，采样策略必须通过故障注入和事故回放持续校准。

### 5. 隐私与安全：证据账本可能成为“完美泄漏数据库”

**攻击。** 为重建认知过程，系统容易保存提示、文件、用户数据、密钥、商业规则和内部判断。控制面一旦被攻破，攻击者得到完整因果地图。

**材料支持。** NIST 的生成式 AI 风险配置要求把数据隐私、信息安全、第三方访问和持续监控共同治理。AWS 明确指出，推理阶段保护敏感数据但日志阶段未脱敏，会让 PII、密钥和受监管字段进入长期存储。

**击穿条件。** 账本保存敏感原文的范围、寿命或访问主体，超过执行任务所需范围。

**修正：语义完整不等于内容复制。** 敏感值使用密封引用、哈希承诺或受控重取；观测网关落盘前分类、脱敏和租户隔离；事实事件与敏感载荷分库；查询、导出、解密和删除均审计；支持“删除载荷但保留事件存在性与完整性证明”。

**剩余风险。** 脱敏会降低事后重建能力，完整性与数据最小化之间不存在零成本解。

### 6. 共同模式故障：监控器可能只是 Agent 的回声

**攻击。** 如果 Agent、状态估计器和评估器来自同一模型族、读取同一错误文档、使用同一价值假设，它们可能一致地给出错误结论。

**材料支持。** AAAI 2025 的实验覆盖 19 个模型，发现 LLM Agent 作为评估器可能支持自己的初始选择，而且在感知自己拥有控制权时偏差增加。OpenAI 也把监控器与 Agent 串谋列入控制评估问题。

**击穿条件。** 一个判断的“多重验证”实际来自同源模型、同源数据和同源提示，只是重复调用。

**修正：证据独立性图。** 每项关键结论记录模型、数据、工具、组织责任和评价标准来源；计算故障域数量而非评估器数量；组合确定性检查、不同实现、外部结果、领域专家和异构模型；同源评估不能提升安全等级；定期注入共同错误。

**剩余风险。** 不同模型也可能共享训练数据和行业假设，完全独立通常不可证明，只能管理相关性。

### 7. 人类监督失效：“人在环”可能只是橡皮图章

**攻击。** 当审批量大、时间紧、材料复杂时，人会依赖系统摘要；控制台越权威，越可能使人停止独立判断。

**材料支持。** NIST 强调明确人机角色、测量人类覆盖和推翻系统输出的情况，并指出人类认知与组织偏差会贯穿 AI 生命周期。欧盟发布的一项 1,411 名专业人员研究发现，在其借贷和招聘实验中，人类监督没有阻止通用 AI 的歧视性建议。

**击穿条件。** 审批人缺乏领域能力、时间、独立信息或真实否决权，同时系统只展示一个推荐和一个总分。

**修正。** 把审批人的能力、负载、剩余窗口和利益冲突纳入状态；展示关键证据、未知、反方案和不行动后果；测量 override、纠错率、响应时延和事后误判；超载时降低自主范围；定期插入已知缺陷样本验证监督有效性。

**剩余风险。** 人类不是最终真值，需要多角色仲裁和事后申诉，不能把责任简单上移。

### 8. 控制面旁路：没有能力封装，网关只是流程建议

**攻击。** Agent 走网关，但遗留服务账号、运维脚本、第三方 webhook、管理员控制台或子 Agent 仍持有生产权限。真正危险的行动绕开了最完整的控制路径。

**击穿条件。** 存在任何可改变受保护世界状态、但不要求有效 `ControlDecision` 的凭证或通道。

**修正。** 建立能力与凭证清单；生产资源只接受网关身份，Agent 不持有长期写凭证；扫描云策略、CI/CD、脚本、人工账号和第三方回调旁路；每个外部效果必须关联 `decision_id`；暂时无法收口的旁路先增加检测、额度和急停。

**剩余风险。** 人工越权和物理通道不能只靠软件解决，需要组织治理。

### 9. 漂移与控制陈旧：昨天的安全规则可能制造今天的事故

**攻击。** 模型升级、上下文压缩、第三方接口、业务规则、负载和用户行为都会改变下层闭环。控制器仍按旧状态模型判断时，监控越自信，误导越强。

**材料支持。** NIST 的生成式 AI 配置要求持续监控第三方系统、预案和 fallback，并明确关注随时间发生的 drift、decay 和系统变化。

**击穿条件。** 被控系统版本或环境分布变化，但估计器、阈值、恢复计划和效果验证仍引用旧基线。

**修正。** 状态、决定和结果绑定模型、提示、技能、工具、数据和策略版本；版本变化使高风险缓存失效并触发重新辨识；灰度并行运行旧/新估计器；监测预测—真实残差；漂移超阈值时缩权、回退或转人工。

**剩余风险。** 稀疏结果和长反馈任务中，漂移很晚才显现，只能通过小批次和多时间尺度评价限制损失。

## 四、压力测试后的七项架构增补

| 增补能力 | 解决的问题 | 最小实现 |
|---|---|---|
| Observability Assessment | 误把不可知状态当低风险 | 每个高风险决定列出可测、可估、不可知及其影响 |
| Two-Speed Control Loops | 语义控制太慢 | 硬规则快环 + 状态/人类/结果慢环 |
| Evidence Independence Graph | 多个判断实际同源 | 标记模型、数据、工具和责任故障域 |
| Telemetry Budget & Retention | 成本、噪声和隐私失控 | 风险分层采集、一致性采样、分类保留 |
| Oversight Capacity State | 人工审批失效 | 能力、负载、时限、override 与纠错率进入镜像 |
| Bypass & Capability Inventory | 网关之外仍可写 | 凭证与能力发现，外部效果强关联 decision_id |
| Control Effectiveness Evaluation | 只测 Agent，不测控制器 | 召回、误杀、延迟、阻断成功率和恢复净收益 |

## 五、控制面自身的验收指标

| 指标 | 定义 | 防止的自欺 |
|---|---|---|
| Monitor Recall | 已知/构造故障中，在干预窗口内被识别的比例 | “什么都记了，所以一定看得见” |
| Silent Failure Rate | 当时通过、延迟结果失败且未主动发现的比例 | 只看即时通过率 |
| False Block Rate | 本可安全完成但被控制面阻断的比例 | 以绝对保守换虚假安全 |
| Intervention Latency | 危险状态出现到有效控制生效的时间 | 告警很多但来不及阻止 |
| State Freshness | 控制决定引用状态的实际陈旧度 | 基于旧世界精确决策 |
| Recovery Net Effect | 恢复减少的损失减去恢复新增损失 | 把回滚动作本身当成功 |
| Evidence Independence | 关键判断覆盖的独立故障域数 | 同源 Judge 冒充交叉验证 |
| Human Oversight Effectiveness | 人类新增正确拦截减去错误放行和时延损失 | “有人审批”冒充有效监督 |
| Control Overhead Ratio | 控制成本 / 任务实际创造价值 | 控制系统吞噬生产力 |
| Privacy Exposure Surface | 敏感类型、主体、保留期和访问面 | 监控资产风险被忽略 |

## 六、最终裁决

**被保留：** 对动力学未知、部分可见且持续变化的智能体系统，没有可用于控制的状态观测与反馈，就不可能获得可靠的生产控制。

**被推翻：** 只要监控足够详尽，系统自然就会可控。

**准确版本：**

> 详尽监控是精细控制唯一可靠的认识基础，但“详尽”必须按控制闭环的语义完整性定义，而不是按数据量定义。它只有与及时的硬控制、独立证据、恢复能力、结果校准和有效人类治理共同工作，才能把智能体转化为生产工具。

进一步压缩：

> **不是看见得越多越可控，而是在还来得及干预时，看见足以做出正确控制决定的状态。**
