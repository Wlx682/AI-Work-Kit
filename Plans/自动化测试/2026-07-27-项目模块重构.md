## 一、测试范围

| 层级 | 覆盖模块 | 工具 / 框架 |
|------|----------|-------------|
| 单元测试 | HTTP DTO Mapper、权限、成员 diff、项目 scope、Gateway key/endpoint、Resolver、Token Store | XCTest / Swift Concurrency |
| 集成测试 | HTTP Repository、连接池、Access Store、Chat 导航、项目 Facade、生命周期清理 | XCTest + URLProtocol / Gateway fake |
| UI / E2E | 项目列表、连接中/失败、四 Tab、管理成员、申请记录、只读态、iPhone/iPad | XCUITest |
| 回归 | 个人 Chat、连接池上限/LRU、现有项目创建、现有专家 Provider | XCTest + 既有回归 |

### 不测

- 服务端内部 Token 签发、Items 数据库存储与 Gateway 资源计费。
- Figma 像素级截图差异；视觉阶段做人工/截图走查，本计划验证可访问元素、状态和导航。
- 未确认的任务/专家 HTTP 写 Route；先以 Repository contract fake 验证客户端行为，联调时补真实 API IT。

### 首批红测顺序

1. `NMProjectGatewayResolverTests`
2. `NMProjectGatewayEndpointBuilderTests`
3. `NMProjectScopeGuardTests`
4. `NMProjectKnowledgeTokenStoreTests`
5. `NMProjectChatNavigationTests`

这五组必须在生产实现前进入测试 Target；红灯只能来自被测类型/行为尚未实现，不得来自测试夹具、编译环境或随机时序。

## 六、夹具与可测试性要求

### 6.1 依赖注入

- Resolver 注入 `PoolConnecting`、`AccessStoring`、`GatewayRegistrationProviding`。
- HTTP Repository 注入 async request closure；禁止测试触网。
- Token Store 注入 clock 与 fetch closure，避免真实等待。
- Scope Guard 的 generation 可显式创建。
- Chat Push Helper 提供 gateway 参数捕获 seam。
- Lifecycle Coordinator 的清理依赖均为协议，验证调用顺序。

### 6.2 固定夹具

```text
me.idaas = user-me
ownerA.idaas = user-owner-a
ownerB.idaas = user-owner-b
projectOwn = project-own / vim-own
projectA = project-a / vim-a
projectB = project-b / vim-a   # 故意与 A 同 VIM，验证 projectId 隔离
tenant = tenant-1
```

所有异步测试使用 continuation / expectation 驱动完成顺序，不用固定 `sleep`。
