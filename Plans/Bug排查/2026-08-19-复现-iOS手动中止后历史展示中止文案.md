## 一、输入

- 来源：用户对比图；Android 参考项目 `/Users/wanglongxiang/git/clawapp` 的 `origin/dev_work_dayli_build` 分支。
- 范围：iOS 普通对话在用户手动停止后，退出再进入历史时的停止正文投影。
- 非目标：不改动 `chat.abort` RPC，不改任务挂起/余额不足逻辑，不重构整个历史轮次汇总卡。

## 二、阶段产出

- [x] 最小复现：历史返回当前轮 user，随后是 `assistant` 空正文 + `openclawAbort.aborted=true` + `stopReason=stop`；iOS 历史 Mapper 将该 assistant 丢弃，因而不产生“已停止”正文卡。
- [x] Android 对照：`ChatParsers.kt` 识别 `openclawAbort.aborted == true`，空正文补“已停止”，有正文则幂等追加“\n已停止”；`ThinkItemBuilder.kt` 将其当作本轮 BODY，不当作 gateway system notice。
- [x] iOS 已有能力：`NMChatHistoryCompletionAnalyzer` 已能识别当前轮 `openclawAbort`；`NMChatTextCellVM` 可直接展示补齐后的文本。
- [x] 差异点：`NMChatHistoryMapper` 仅对空正文 `terminalReason=interrupted` 保留消息，未解析 `openclawAbort`，也未补停止文案。
