## 一、输入

- 来源：复现 Plan、iOS 当前 Mapper/ViewModel 代码、Android `origin/dev_work_dayli_build` 对照实现与定向测试。
- 范围：定位 `chat.history` 从网关中止标记到 iOS 可见正文的丢失点。
- 非目标：不将实时中止卡持久化为本地历史，不改 Gateway 历史协议。

## 二、阶段产出

- [x] 协议层正常：Gateway 已把用户手动停止落盘为 `assistant.openclawAbort.aborted=true`，iOS `NMChatHistoryCompletionAnalyzer.hasAbortMarkerAfterLatestUser` 也已将它判为 `.aborted`。
- [x] 根因：`NMChatHistoryMapper.buildMessage` 在 `parseContentBlocks` 得到空数组后，只保留 user 和 `terminalReason=interrupted` 消息；`openclawAbort` 未解析，导致中止 assistant 在进入 ViewModel 前被 `return nil`。
- [x] 二次影响：即使只把空消息保留，`appendAssistantHistoryCellViewModels` 也不会为空 content 生成可见 Cell，所以必须在 Mapper 层实体化“已停止”文本。
- [x] Android 成熟规则：`parseChatMessageObject` 仅在 `role=assistant && openclawAbort.aborted=true` 时调用 `withStoppedDisplayContent`；空正文新增 text block，有正文在最后一个可见 text 末尾幂等追加。
- [x] 需要保护的边界：非 abort 空 assistant 仍应丢弃；已含“已停止”不重复追加；有部分正文时保留原文；停止标记在 `model=gateway-injected` 时仍应当作本轮正文而不是系统提示。

## 三、根因结论

`chat.history` 数据没有丢失，丢失发生在 iOS 历史映射层。这是已有历史投影规则缺少 Gateway abort marker 分支，不是新需求，继续走 bugfix。
