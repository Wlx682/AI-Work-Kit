## 一、输入

- 来源：用户在有线 iPhone 真机（iOS 18.6.2）点击输入框 ASR 后反馈“启动失败”；Flutter resident session 与冻结 iOS ASR 生产链。
- 范围：复现 ASR 从输入框点击到 token、WebSocket、采音启动的失败范围，并锁定可观测性缺口。
- 非目标：不改输入框视觉，不扩展句子/文件 ASR，不更换 ASR 服务商。

## 二、阶段产出

- [x] 真机 App 正常驻留，Runner PID 9300；故障只发生在点击 ASR 后，App 本身未崩溃。
- [x] 生产入口已接到 `NamiVoiceInputComposition.launch`，首页、对话页、项目页共用同一链路。
- [x] 启动链依次执行登录 HTTP scope、ASR token、WebSocket、16k 单声道 PCM 采音；任一步异常都会导致用户看到统一“语音识别失败/不可用”。
- [x] 当前顶层 `on Object` 未记录异常，Controller 的 `failure/reasonCode` 也未写诊断日志，因此现有 resident 控制台只能确认失败，没有可判定的终端原因。这是需要在 diagnose 阶段补齐的可观测性缺口。
- [x] 冻结 iOS 对照确认 token 路径同为 `api/b/token?key=doubao_asr`，WebSocket 同为 `bigmodel_async`，可排除“Flutter 接错 token endpoint”这一假设。
- [x] 影响范围：iPhone 已复现；Android/iPad/Pad/Fold 未运行，状态保持 `NOT_RUN`。
