## 二、阶段产出

### Findings

- `235fddff` 删除首屏 pending 的方案经用户真机反馈失败：缓存帧上屏后刷新仍在途，主动收口 footer 会扩大重复触发窗口。
- 修正后的 diff 未发现新的阻塞 / 高 / 中级问题：`NMTaskRecordListVM.swift:225-257` 只在首屏请求结束时消费 pending 并延后一拍，`NMTaskRecordListVM.swift:323-331` 明确排除分页在途重入。
- 测试缺口：目标 XCTest 未实际执行；Xcode 在解析依赖前失败，原因是 `OpenClawKit` 要求 Swift tools 6.2，而当前唯一 Xcode 提供 Swift 6.1.2。

### 复核结果

- [x] 首屏刷新在途上滑：保存一次 pending，不提前结束 footer，不使用缓存帧 cursor 发起分页。
- [x] 首屏请求结束：等待下一主线程周期再消费 pending，使 footer 先完成异步 idle 切换。
- [x] 分页在途再次上滑：忽略重复触发且不设置 pending，避免旧意图残留到后续刷新。
- [x] 正常上滑：`isRequesting == false` 时仍按原逻辑请求下一页。
- [x] 刷新请求状态：pending 不修改 `isRequesting`，原 SWR 流继续消费网络最终帧。
- [x] 数据路径：未修改会话转换、排序、追加、`nextCursor` 或 `hasMore`。
- [x] 性能：仅增加两个布尔状态和一次必要的主线程异步调度，无列表遍历或额外数据转换。
- [x] 静态验证：生产文件、测试文件 Swift 语法解析通过；`git diff --check` 通过。
- [ ] 动态验证：在 Swift 6.2/Xcode 26 环境运行目标 XCTest，并真机回归“返回后立即快速上滑”。
