## 二、阶段产出

### 根因树

1. **质量编排缺少唯一所有者**：为解决线上模型生成失败，把 quality audit 和 retry 下沉到了 DeepSeek Adapter；Application 原有重试未删除，形成重复策略和不一致错误语义。
2. **结构不变条件没有封装成统一发布门禁**：首次创建、变更和回滚分别调用 validator，并通过 `allow_single_child` 产生入口差异；质量审计又假定结构已通过而把 structure 写死。
3. **把字段计数当作语义质量**：修复逻辑通过复制后代数组满足最小数量，没有 provenance、diff 和对齐审计。
4. **JSON Repository 缺少提交协议**：领域写入直接覆盖多个最终路径，Application 在元数据、投影和快照之间没有 transaction/unit-of-work。
5. **Observability 以“尽可能完整”为默认值**：事件模型缺少 payload policy、trace context、retention/clear；secret-key redaction 被误当作隐私脱敏。
6. **错误契约只有 code/message**：GraphAudit finding 没进入失败 envelope，Flutter 对已知 code 只展示固定本地化字符串。

### 修复原则

- Application 是 generate/audit/revise/publish 的唯一编排者；Adapter 只返回 schema-valid draft。
- 所有发布、变更和回滚入口调用同一个 strict publish gate。
- 不再静默改变模型知识拓扑或复制其他节点量规；修订必须由模型基于 findings 生成完整新 draft。
- GraphVersion/Audit/Snapshot 先构造完整 immutable bundle，active projection 最后原子切换；失败可恢复。
- Debug 默认 summary-only；详细 payload 显式 opt-in，事件具备 trace/span，支持清除。
- `GRAPH_AUDIT_FAILED` 返回结构化 findings，Flutter 展示可行动详情。

### 必须补的 Red 测试

- 生产 Adapter + Application 组合总 LLM 调用不超过 2，适配器不导入/调用质量门禁。
- unary draft 不被静默修复，严格 validator 失败。
- create/update/delete/rollback 共享 strict gate；删除导致 unary 时零版本变化。
- 持久化中间步骤失败时 active graph/version/snapshot 保持原值，重启可读取。
- Debug 默认事件不含完整 prompt/answer，详细模式可开关并可清除，trace/span 完整。
- API 返回 GraphAudit findings，Flutter 错误面板显示 code/node/message。
