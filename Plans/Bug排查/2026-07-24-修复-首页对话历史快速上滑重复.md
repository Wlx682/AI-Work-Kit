- 来源：定位阶段确认的首屏刷新与延迟分页重放时序。
- 范围：刷新在途时的 `loadMore` 策略、footer 收口和对应单元测试。

## 二、阶段产出

- [x] 恢复 `pendingLoadMoreAfterCurrentRequest`，仅用于 SWR 首屏刷新在途时保存一次上拉，等待网络最终帧提供最新 cursor。
- [x] 增加 `isReloadingFirstPage` 区分首屏刷新与分页；分页在途的重复 footer 触发直接忽略，不再污染 pending。
- [x] pending 分页延后一主线程周期重放，确保 `MJRefresh.endRefreshing()` 先完成异步 idle 切换。
- [x] 不恢复 `pendingLoadMoreBlock` / 手动 `footer.beginRefreshing()`，footer 状态继续由实际上拉和结果回调管理。
- [x] 新增两类单元测试：首屏刷新在途上拉会 pending 且不提前收口 footer；分页在途重复触发不会留下 pending。
- [x] 已撤销会话 ID 去重方案，数据转换和服务端分页游标逻辑保持原样。
- [x] `swiftc -frontend -parse` 与 `git diff --check` 通过。
- [ ] 真机验证“缓存帧上屏后快速上拉”及“返回首页后连续快速上拉”。
