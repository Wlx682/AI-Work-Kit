## 一、输入

- 来源：iPhone 最新 Debug 包完整重编译后的启动日志、ASR Composition、认证 HTTP runtime 与 Push Alias provider 生产代码。
- 范围：定位 ASR 获取 token 前失败的真实根因，并确定最小修复边界。
- 非目标：不改 ASR 密钥、不改麦克风权限，不改服务端 token/WebSocket 协议。

## 二、阶段产出

- [x] 最新代码已完整 Xcode build、安装并启动，排除“旧 17:15 Runner 未包含 17:18 内置密钥提交”的产物错位。
- [x] 真机稳定记录 `runtime bind failed: CircularDependencyError`，堆栈落在 `pushAliasLifecycleProvider` 的 current-owner 回调读取 `authOwnerRepositoryProvider`。
- [x] 依赖环：`authOwnerRepositoryProvider` watch `authPushAliasCleanupPortProvider` → watch `pushAliasLifecycleProvider`；后者又通过自身 `Ref` read `authOwnerRepositoryProvider`。
- [x] `_synchronizeNamiHttpRuntime` 在 Push Alias 同步抛错后执行 `revoke()`，导致 `AppNamiHttpRuntimeController.acquireAuthenticatedAt` 返回 unavailable；ASR 在 token 请求前即失败。
- [x] 麦克风 plist、permission_handler、record iOS plugin、ASR 内置密钥、`api/b/token?key=doubao_asr` 与 WebSocket 地址均已核对存在，不是本次启动失败根因。
- [x] 最小修复方向：Push Alias coordinator 不再持有 provider 自身 `Ref` 去反向读取认证根；在 `synchronize` 调用边界注入 current-owner guard，保留绑定前后两次 owner 校验。

## 三、根因结论

ASR 本身尚未进入 token、握手或采音阶段。认证 HTTP runtime 在 App 初始化期间因 Push Alias 与 Auth Owner 的 Riverpod 循环依赖被撤销，ASR 共用该 runtime，因此点击后统一显示启动失败。
