# 根因定位：学习活动无效 JSON 未重试

## 复现

- 真实 DeepSeek 五视图集成测试连续两次在 `startRecommendedPractice` 失败。
- 错误：`LEARNING_INTELLIGENCE_FAILED: LLM returned invalid JSON after one repair attempt: Unterminated string`。
- 图谱生成、质量审计和路径推荐均已成功，故障位于 Tutor `create_learning_activity`。

## 根因

- 共享 `llm.chat_json` 对 JSON 语法执行一次原样修复，仍失败时抛出 `ValueError`。
- `DeepSeekLearningIntelligence._call` 把所有非领域异常统一映射为 `LEARNING_INTELLIGENCE_FAILED`。
- `_call_validated` 只重试 `INVALID_INTELLIGENCE_OUTPUT`，且 `_call` 位于 try 外，因此无效 JSON 绕过重新生成。
- 修正重试后 live 测试仍稳定失败，继续下钻确认共享 `_parse_json` 只要在响应任意位置看到三反引号就执行 `split("```")`；合法 JSON 字符串内的 Markdown 代码块因此被误识别为外层围栏并截断。
- 解析修复后 live 流程进入 Evidence，但进度页仍为 0；后端 `/evidence` 已返回更新后的 `course`，Flutter `RuntimeReview.fromEvidenceJson` 未解析该字段，Controller 因而保留提交前快照。

## 边界

- 无效 JSON 属于模型输出质量问题，可重新生成一次。
- Timeout、鉴权、网络错误仍属于传输失败，不做结构化输出重试。
- App Adapter 负责错误翻译和有上限重试；共享 Agent 解析器负责只剥离真正包裹整个响应的外层围栏，不能破坏字段内部 Markdown。
- Evidence 成功响应中的课程快照必须由 typed client 解析并立即替换 Controller 当前课程，不依赖可选 Graph Proposal 的确认流程刷新。
