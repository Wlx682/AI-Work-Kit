# 修复：图谱来源引用缺失导致质量门禁失败

## 架构结论

- 需求和已采纳架构都规定只有 Critical 阻断发布；来源缺失在当前 Scope 为 warning。
- 原架构缺少统一质量决策契约，实现又让 Application、模型和 UI 分别消费扁平 findings，形成架构漂移。
- 已在架构文档增加 ADR-010：Graph Quality 统一输出发布决策、blocking/advisory 分区和稳定顺序。

## 实现

- `GraphQualityAudit` 新增 `publish_allowed`、`blocking_findings`、`advisory_findings`、`ordered_findings`。
- Application 只把 blocking findings 交给唯一一次模型修订，并在 API details 输出统一决策。
- DeepSeek 修订提示明确优先解决阻断项、保留合格字段和已有来源、不虚构 URL。
- Flutter 对旧版扁平 findings 兼容排序，先展示阻断项及数量，再展示提醒数量。

## Code Review（Findings-first）

### Findings

- **阻塞：无。** Graph Quality 已成为发布决策唯一所有者；创建、节点变更、回滚均消费 `publish_allowed`。
- **高：无。** API 继续保留扁平 `findings` 兼容字段，同时增加 `publish_decision` 与 blocking/advisory 分区。
- **中：无。** Flutter 对新旧响应均可用，有限展示时 Critical 不再被 warning 遮蔽。

### 测试缺口与残余风险

- `Source Grounding` 与来源可信度验证仍是已采纳架构中的后续能力；当前 `NODE_SOURCE_MISSING` 按需求保持 warning。
- 真实 DeepSeek 端到端用例仍需显式 `R4_LIVE_DEEPSEEK=1` 才执行；确定性契约和模型修订输入已由替身测试覆盖。
- 两次模型调用上限属于已确认需求约束；若第二次仍有 Critical，系统会正确拒绝并展示真实阻断项，而不会静默放行。
