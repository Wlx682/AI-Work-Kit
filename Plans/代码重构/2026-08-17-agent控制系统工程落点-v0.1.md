## 七、依赖与工具链

- Node/pnpm：使用 DSH 官方锁定的 pnpm 主版本起步，根 `packageManager` 和 lockfile 一并提交；
- TypeScript：Host 聚合与 Client 聚合按 DSH 规则隔离，普通包只能进入一个聚合；
- DSH：精确固定 `@deepseek-ai/dsh@0.1.0-rc.6`、直接 DSH 包同 rc.6、`@deepseek-ai/cordis@4.0.1`，依赖经 `packages/dsh-bridge` 收口，不修改上游；
- LangGraph.js：使用官方 `@langchain/langgraph` 与 `@langchain/core`；旧显式 graph 以 `StateGraph` 为主，不改写成黑盒 prebuilt agent；
- LangGraph.js 恢复：用官方 checkpointer、`interrupt` + `Command`、`getStateHistory` 重建 checkpoint、人工暂停、恢复和 time travel；本地学习持久化使用 `@langchain/langgraph-checkpoint-sqlite` 的 `SqliteSaver`；
- 测试：Vitest + DSH 官方 typecheck/build 命令 + contract/fault/acceptance 分层；
- Schema：即使单语言，持久化和跨进程协议仍有 JSON Schema 与 valid/invalid fixtures；
- 存储：Control Ledger v0.1 使用 SQLite WAL 单写者并置于 Provider Port 后；追加、幂等、稳定序号、durable commit 和可重放为不变量，未来 PostgreSQL 替换须新 ADR；
- CI：typecheck → unit → plugin lifecycle → qualification → integration → fault injection → cutover rehearsal。
- Lab CI：独立 TypeScript/Vitest job 运行迁写后的 60 tests；失败不应隐藏，但不得把 Lab 加入生产部署图。

LangGraph.js 官方核验入口：[LangGraph.js 仓库](https://github.com/langchain-ai/langgraphjs)、[Graph API](https://docs.langchain.com/oss/javascript/langgraph/graph-api)、[Persistence](https://docs.langchain.com/oss/javascript/langgraph/persistence)、[Time travel/interrupt](https://docs.langchain.com/oss/javascript/langgraph/use-time-travel)。版本必须在 B0/B1 固定到 lockfile，不能依赖 `latest` 漂移。

## 八、删除和切换规则

1. 不在用户当前脏工作区原地覆盖；先保护用户修改并创建独立 clean worktree；
2. Python 删除只能发生在 B5，同一个 cutover 变更中完成；
3. 删除前必须有 baseline tag、依赖清单、旧 60 tests 日志、TS 60 tests 映射、真实任务 transcript 与人工签字；
4. 任一 Oracle 或环境无法证明可靠，切换状态保持 blocked，不得修改结论迎合进度；
5. cutover 后生产代码、必需 CI、启动入口和部署制品只能指向 TypeScript/DSH；
6. baseline tag 保留用于审计和回滚；学习源码只位于 `labs/runtimes/langgraph-ts/`，不得使用含糊的 `legacy/` 名称；
7. LangGraph.js Lab 不持生产凭证、生产网络配置或生产数据；生产 package 不能 import Lab；
8. 两套 Runtime 只允许通过离线 task fixture/transcript 学习对照，不建设 live RuntimePort 或热切换。
