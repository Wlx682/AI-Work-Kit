# Agent 可信评估最小改造 v0.1

## 一、目标

直接在 TypeScript + DSH 生产基座上实现 `US-CP-EVAL-000`：证明评估可以区分现实成功、现实失败、证据不足和评估失效。用户已确认不再创建 Python 评估包或生产 LangGraph Adapter；现有 Python 工程只从冻结 tag/worktree 提供迁写基线，最终另有 TypeScript/LangGraph.js Learning Runtime 用于离线学习对照。

本计划不是为了给一次性迁移开绿灯，而是允许得出“当前不能切换”。参考解、负对照、外部 Oracle 或环境任一不可靠，结论必须为 `ABSTAIN`/`INVALID` 或阻断，不能为完成任务强制 PASS。

## 二、为什么仍从现有 agent 取证

现有工程提供迁移前事实，而不是目标 Runtime：

- `core/definition.py` 提供任务/Agent 配置语义；
- `core/models.py` 提供旧技术状态语义，但 `succeeded` 不等于现实成功；
- `orchestration/langgraph.py` 提供 run/resume/recover 行为样本；
- `capabilities/act.py` 提供 Action ID、unknown 与人工补证据路径；
- `tools/registry.py` 提供工具 Schema 和错误样本；
- 2026-08-17 已验证旧基线 `python3 -m pytest -q tests` 为 `60 passed`。

这些证据必须固化到 baseline tag/worktree 和 transcript；目标工作树不保留 Python Runtime。LangGraph.js Learning Runtime 可生成同版离线 execution/report fixture，但不能接生产控制面或成为热切换 Provider。

## 三、Scope

### 本轮包含

- pnpm/TypeScript 最小 workspace 与固定 DSH 依赖；
- `evaluation-domain` 的 `PASS/FAIL/ABSTAIN/INVALID`；
- 版本化 `EvaluationConfig`、`RuntimeManifest`、`EvaluationReport`；
- DSH `evaluation` Cordis 插件及可逆 Effect；
- 只读/沙箱 `evaluation` Profile、Bundle/Provider 组合指纹；
- 从 Session Log 派生 technical execution 和 evidence refs；
- 外部 `OutcomeOracle`，首个候选为文件状态 Oracle；
- 参考解、已知错误、unknown、坏题/坏环境资格检查；
- 人工复核责任人、裁决来源和版本化报告；
- 与冻结 Python 基线的一个真实任务行为对照；
- LangGraph.js Learning Runtime 对同一 Case/Oracle 生成离线对照报告；
- Red 测试、插件生命周期测试和故障测试。

### 本轮不包含

- 完整 M1—M12 控制面；
- 生产写权限或不可逆工具；
- Safety Executor 正式生产部署；
- Python `evaluation/`、生产 LangGraph Adapter、DSH Python SDK；
- 跨语言 Schema parity；
- 多 Agent、排行榜、LLM Judge 平台或在线自动调参；
- 删除 Python 工作树——删除只在全系统 cutover 门禁和 LangGraph.js 60 tests 迁写通过后发生。

依赖规则：

```text
evaluation plugin → evaluation-domain → contracts
evaluation plugin → dsh-bridge → DSH/Cordis
evaluation plugin → OutcomeOracle → external reality
```

`evaluation-domain` 和 `contracts` 不 import DSH/Cordis。只有 `dsh-bridge` 和插件读取 SessionEvent、Context、Profile/Bundle/Patch 和监听器顺序。DSH Session Log 是模型可见历史来源；现实结果必须来自独立 Oracle，不能从 assistant 自述或 turn status 推断。

LangGraph.js Lab 可以依赖 `evaluation-domain/contracts` 生成离线报告，但生产 packages、plugins、profiles 和 deploy graph 不得反向依赖 Lab。两套 Runtime 不共享 live RuntimePort。

## 五、四态语义

| 状态 | 定义 | 示例 |
|---|---|---|
| PASS | Oracle 对正确目标给出充分、可复核成功证据 | 目标文件内容和约束均正确 |
| FAIL | Oracle 给出充分失败证据 | DSH 正常结束，但目标内容错误 |
| ABSTAIN | Case 有效，但现有证据不足以裁决 | 外部系统延迟、需要人工检查 |
| INVALID | Case、Oracle、目标身份或环境失效 | 目标路径错误、权限缺失、参考解也失败 |

`technicalStatus=completed` 只描述 Runtime 完成请求，不得覆盖上述状态。人工裁决必须保存 reviewer、reason、sourceRefs、timestamp 和新报告版本，不能覆盖原报告。

## 六、资格门禁

一个 Case 只有同时满足以下条件才可用于切换判断：

1. 参考解在受控环境稳定 PASS；
2. 至少一个已知错误稳定 FAIL；
3. Oracle 对错误目标、缺权限和读失败返回 INVALID/ABSTAIN；
4. Case 明确目标身份、初始状态、允许效果和禁止效果；
5. DSH commit、Profile、Bundle 顺序、Patch、Provider 和监听器组合可指纹化；
6. 原始 Session/Oracle 证据可追溯；
7. 人工责任人复核 Case、Oracle 和首份报告；
8. 重复运行的差异落在已声明随机性/环境容忍区间。

任何条件失败，G-EQ 不通过。允许人工辅助完善证据，不允许人工把坏题直接标成 PASS。

## 七、Red→Green→Refactor

### Red

- DSH step/turn 完成、目标文件错误，必须 FAIL；
- Oracle 读错路径或缺权限，必须 INVALID/ABSTAIN；
- 没有 external evidence 时不能 PASS；
- 参考解不能 PASS 时 Case 无资格；
- 已知错误不能 FAIL 时 Case 无资格；
- plugin dispose 后仍有 Service/Event/Effect 时失败；
- Runtime composition 指纹变化时旧报告不能复用；
- 人工裁决无 reviewer/reason/sourceRefs 时拒绝。

### Green

实现纯 TS models、qualification、evaluate、FileStateOracle、DSH evaluation plugin、evaluation Profile、报告 Schema 和 evidence store；使用 DSH Session Log 投影 technical execution，使用外部 Oracle 生成现实 verdict。

### Refactor

保持 `evaluation-domain` 纯 TS/框架无关；将 DSH 版本差异压在 `dsh-bridge`；任务特定字段留在 Oracle/Case，不污染通用报告；重复运行统一 fixture、clock 和 artifact identity。

## 八、真实任务与人工复核

首个 Case 必须使用真实遗留代码任务，而不是只验证模型输出字符串。最低要求：

- 明确唯一工作区和目标文件身份；
- 参考补丁与一个已知错误补丁；
- 独立读取最终文件/测试结果的 Oracle；
- DSH Runtime 使用只读或隔离沙箱；
- 人工确认目标、参考解、负对照和 Oracle 都有参考价值；
- 若人工无法确认，记录 blocked，不切换。

## 九、验收标准

- [ ] TypeScript/DSH 最小 Profile 可复现启动；
- [ ] 四态均有自动化用例和稳定证据；
- [ ] technical success 可以被外部 FAIL 推翻；
- [ ] 参考解和负对照均通过资格检查；
- [ ] Session Log 与 Oracle evidence 分账且可追溯；
- [ ] 插件卸载无残留 Effect；
- [ ] 真实任务由人工复核并签署；
- [ ] 评估不依赖 Python Runtime 或跨语言 Adapter；
- [ ] LangGraph.js Lab 能用同一 Case/Oracle 产出离线对照报告，但不进入生产依赖图；
- [ ] G-EQ 失败时不会触发 Python 删除或生产切换。
