01 — 文章介绍

这篇文章是什么

Lilian Weng 是 OpenAI 应用研究负责人，她的个人博客以高密度研究综述闻名。这篇 "Harness Engineering for Self-Improvement" 发表于 2026 年 7 月 4 日，约 28 分钟阅读量，主题是：围绕基础模型的部署基础设施——即 harness——如何成为递归自改进（RSI）的实际载体。

Harness 是围绕基础模型的系统，负责编排执行并决定模型如何思考与规划、调用工具与行动、感知与管理上下文、存储产物、以及评估结果。

文章的核心论点：递归自改进不仅取决于模型智能本身，更取决于模型被嵌入的系统架构。被优化的对象不一定是模型权重，更可能是 harness 代码本身。

02 — 递归自改进

从 I.J. Good 到现代 RSI

概念追溯到 I.J. Good（1965）定义的"超智能机器"：能超越人类并设计更好后继者。现代 RSI 并非发生在"模型自己训练自己"这一步，而是发生在部署系统架构层面：改进训练流水线、改进部署系统，从而产出更强的后继模型。

03 — 设计模式

三种基础 Harness 设计模式

模式一：工作流自动化

目标导向循环：规划 → 执行 → 观察/测试 → 改进。关键不在于"循环"本身，而在于循环中的评估环节如何决定是否终止或回退。

模式二：文件系统作为持久记忆

长时域 agent 把持久状态写入文件而非依赖上下文窗口。Harness 的记忆机制不是对话历史的简单拼接，而是外部化的、可被其他进程读取的结构化状态。

模式三：子代理与后台作业

生成并行子代理进行假设测试和并发实验，强调显式可检视的并行性。结果以文件形式存储，支持中断后恢复。

工具类别代表操作
文件系统glob, grep, read, write, edit, apply_patch
Shell 执行bash, PowerShell
IO 操作LSP, git
外部上下文MCP, Skills, web search
后台进程进程管理
代理委托agent delegation

主流编码代理已收敛到这组稳定接口——差异化竞争正在上移到"如何编排这些工具"层面。

04 — 上下文工程

三层递进的上下文优化

Agentic Context Engineering (ACE)

把上下文视为不断演进的操作手册，由三个组件协作：Generator 产出轨迹、Reflector 蒸馏洞察、Curator 更新为结构化条目（标识符+描述）。Curator 输出结构化条目而非完整提示词重写——上下文的更新是增量的、可追溯的。

Meta Context Engineering (MCE)

将机制（如何管理上下文）与产物内容（上下文里放什么）分离，使用双层优化：内层在训练数据上找最优上下文，外层在验证数据上找最优管理技能。"上下文管理策略"本身是可优化的超参数。

Meta-Harness

最高层级：优化"决定什么信息被存储、检索和呈现"的代码本身。使用编码代理在帕累托前沿上生成 harness 候选方案。

06 — 自改进 Harness

Harness 优化自身的两条路径

Self-Taught Optimizer (STOP)

实现了"改进改进器本身"的递归。种子改进器接收解、效用函数和 LLM；元效用度量下游任务的平均效用；自改进更新公式：

I_t = I_(t-1)(û, I_(t-1); M)
// 第 t 轮改进器 = 上一轮改进器对自身施加改进操作的产物
!
关键警示：STOP 在 GPT-4 上提升性能，但在更弱模型上反而退化。递归自改进有能力地板——基础模型必须足够强才能有效理解并改进自己的策略。

Self-Harness

采用提议-评估-接受循环：弱点挖掘（将失败聚类为验证器锚定的模式）→ Harness 提议（基于失败模式建议有界编辑）→ 验证（在留入和留出数据上测试，检查回归）。

"有界编辑"是核心设计——不重写整个 harness，而是在失败模式锚定的范围内做局部修改，限制搜索空间和灾难性回归风险。

07 — 进化搜索

从提示词进化到代码仓库进化

Promptbreeder

通过变异操作优化任务特定提示词，变异提示词本身也在进化——两层进化：内层优化任务提示词，外层优化变异策略。

AlphaEvolve

维护候选程序池，冻结的 LLM 生成代码 diff 进行改进。用 # EVOLVE-BLOCK-START/END 标记可进化区域，限制修改范围——"可控进化"。

Darwin Gödel Machine (DGM)

明确以 harness 代码仓库为进化目标，允许 agent 修改自己的基础设施代码。本文最激进的方法——self-modification 对象不限于提示词，而是整个运行时代码。

Hyperagents

引入元代理控制如何修改现有任务代理，按性能正比、后代数反比选择父代。增加了"进化策略的进化"——不只是谁活下来由适应度决定，怎么繁殖也在被优化。

08 — 联合优化

权重 + Harness 的双通道

SIA 将 harness 改进与模型参数更新结合，由三个角色协作：

角色职责
Meta-Agent提出初始 harness
Task-Specific Agent执行任务，产出轨迹
Feedback-Agent根据轨迹决定：更新 harness 还是更新权重

解决根本归因问题：任务失败时，是 harness 编排有问题，还是模型能力不足？Feedback-Agent 做这个判断，然后路由到正确的优化通道。

11 — 工作流启发

对 AI 工作流系统的设计原则

优化对象可以上移

从优化模型权重 → 优化提示词 → 优化 harness 代码 → 优化"优化策略"，每一层都把下层当作搜索空间中的一个点。当前瓶颈是模型能力不足还是编排逻辑不对？后者意味着优化 harness 比换模型更有效。

有界编辑优于全量重写

Self-Harness 和 AlphaEvolve 的共识：自改进系统需要控制变更的爆炸半径——每次只改失败锚定的局部，用回归测试兜底。

机制与产物分离

MCE 将"如何管理"与"管理什么"分离为两层。管理策略和被管理的内容应独立演化，否则改策略时意外破坏内容。

评估器质量决定自改进天花板

七个瓶颈中"弱评估器"排第一不是偶然——系统设计应优先投资评估能力，而非生成能力。

人类监督层应动态上移

不是"移除人类"，而是"上移到合适的抽象层"。人机协作的接口需要随系统能力变化而重新校准。
