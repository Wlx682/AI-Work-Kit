主题

这不是一次 agent 演示，而是一条学习流水线

OpenAI Cookbook 这篇文章搭了一个金融尽调 agent，但真正值得看的不是金融场景，而是它怎么处理 agent 跑完以后的东西。它让 agent 连跑任务，捕获 trace；给 trace 加人类反馈和模型反馈；把反馈转成 Promptfoo eval；再用 HALO 生成 Codex 可执行的 harness 改造 handoff。

这和 AI-Work-Kit 的反馈进化链非常像：一次 Skill 执行后留下 `skill_run`，月度聚合把分散小票变成进化证据，再由人工 review 决定是否写进 Contexts、Skill 或 workflow。

反馈只有变成可复跑验收和可交接改造包，才真正进入系统进化。
第一步

Trace 是原材料，不是日志残渣

传统软件里，代码是行为的主记录；agent 系统里，代码只能告诉你它被允许做什么，trace 才能告诉你它这次真的怎么查、怎么调用工具、怎么走偏。OpenAI 示例保存输入、配置、工具调用、引用材料、输出和反馈，让每次运行成为可审查样本。

第二步

反馈不能只当评论，要变成以后每次都能跑的门禁

原文把人类和模型反馈转成 Promptfoo eval suite。这样一条反馈不再只是“这里答得不好”，而是变成下一次改 harness 时必须满足的验收条件。它让经验从一次性判断，变成可复跑的质量门槛。

第三步

HALO 把证据包整理成 Codex 可以接手的工作包

HALO 读当前 harness、traces、人类反馈、模型反馈、generated evals 和 Promptfoo gate result，然后输出排好序的改造建议，写进 `codex_handoff.md`。这一步让反馈进化从散点建议变成可交接的开发任务。

对照

它和 AI-Work-Kit 几乎同构

OpenAI loopAI-Work-Kit
traceplan 执行过程、Skill 输出、`.meta.yaml`
human/model feedback`contexts_missing`、`contexts_stale`、`friction`、人工 review
Promptfoo eval suite`plan-gate-check.sh`、`workflow-gate.sh`、回归测试和未来验收用例
HALO recommendations`feedback-aggregate.py` / `vault-evolve.py` 产出的补全候选和进化报告
`codex_handoff.md`可落地的 Skill / Contexts / workflow 改造 plan

OpenAI 这篇的价值不在于 5 条示例 trace 的规模，而在于它把“运行反馈如何进入下一版系统”这件事拆成了明确工程对象：证据、反馈、验收、交接。

复用

给 Kit 补一段 handoff 视图

这篇能直接反哺 Kit 的反馈进化链。不是新建大系统，而是让现有 `contexts_missing`、`friction` 和月度聚合报告更接近“可执行改造包”。

缺口变验收`contexts_missing` 指向可落地能力时，附一句 acceptance hint，说明补完以后怎么证明有效。
月报变 handoff给 `vault-evolve` 增加 Codex 可执行视图：证据、建议、改动入口、验收命令。
卡点变结构`friction` 固定成 阶段/动作/卡点/建议，聚合时能定位流程瓶颈。
信任靠 gate短命产物可自动落地；长寿命 Contexts/Skill/workflow schema 仍需人工确认。
