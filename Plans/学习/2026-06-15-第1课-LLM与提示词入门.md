## 练习（必须动手）

### 练习 A：结构化 prompt

```
角色：你是团队会议秘书，擅长从口语化讨论中提取决策与待办。

背景：以下是 2026-06-23 站会录音转写原文（参与者：老王、小李、小张）：
「老王：会员弹窗这周能上线吗？小李：iOS 好了，Android 还在调接口，估计周五。
老王：那先上 iOS，Android 跟下周迭代。小李你记一下要补埋点。
小张：埋点文档在 Confluence，链接我发群里了。
老王：好，周五前大家对一下测试用例，有问题 @我。」

任务：整理成可执行的会议纪要，突出：已做决定、待办事项（含负责人与截止时间）、需跟进的风险。

输出格式：Markdown，固定三节：
## 决策
- （bullet 列表）
## 待办
| 事项 | 负责人 | 截止时间 |
## 待确认
- （若有歧义或未拍板项）

不要做什么：
- 不要编造未在原文出现的决策或日期
- 不要写成长篇叙述或逐字复述对话
- 不要给技术实现建议（只记录会议结论）
```

### 练习 B：温度

| temperature | 输出特点（你观察到的） |
|-------------|------------------------|
| 低 | 重复问同一问题，答案骨架一致；紧扣 token/上下文窗口，少发散。适合排查、续做、填表 |
| 高 | 措辞每次不同，可能多打比方或延伸未问内容。适合头脑风暴、起名、多方案 |

### 练习 C：和 Skill 对照

| 你写的 prompt 块 | resume_assistant 里对应哪一段 |
|------------------|------------------------------|
| 角色 | 首行「当用户说续做…时执行」+ Skill `description`（续做助手） |
| 任务 | 「执行步骤」1–7（读 plan → 判进度 → 推荐 Skill → 结构化输出） |
| 输出格式 | 「输出格式」代码块（`## 续做` / `### 已完成` / `### 下一步` …） |
