# 技术方案：项目专家 Provider 统一状态

## 一、方案结论

在项目详情生命周期内创建一个 `NMProjectExpertProvider`，作为专家列表和当前选中专家的单一状态源。Provider 归属 Projects 业务模块，不下沉 Core。

## 二、职责与数据流

| 模块 | 依赖 Provider | 数据流 |
|------|---------------|--------|
| `NMProjectTeamViewController` | 是 | 观察列表；增删查调用 Provider |
| `NMProjectDetailViewModel` | 是 | 从 Provider 解析当前专家和会话 agentId |
| `NMProjectDetailViewController` | 是 | 观察状态并协调弹窗、输入框 |
| `NMProjectAddedExpertPopupController` | 否 | 接收列表快照，通过回调输出完整列表 |
| `NMModelComponent` | 否 | 接收 `applyAgent` 展示更新，通过既有点击回调输出交互 |

## 三、Provider API

- `addObserver(_:notifyImmediately:)` / `removeObserver(_:)`：弱引用观察者。
- `updateExperts(_:)` / `selectExpert(_:)`：供调用方回写解耦模块的变化。
- `reloadExperts()` / `addExperts(agentIds:)` / `removeExperts(agentIds:)`：统一网络结果、缓存和通知。
- 列表更新时保留仍有效的选中专家；失效时回退首项；空列表时由上层显示云控兜底专家。
- 并发 `reloadExperts()` 共用一个 Task，项目切换后丢弃旧项目结果。

## 四、风险控制

- 观察者弱持有，避免 Provider 与控制器循环引用。
- 弹窗保留 `experts=nil` 时自行加载的兼容路径，避免影响定时任务场景。
- 新文件加入 Xcode Sources；不修改接口协议与 UI。
