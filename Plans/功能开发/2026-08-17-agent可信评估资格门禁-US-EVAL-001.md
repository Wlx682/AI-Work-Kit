# US-EVAL-001：拒绝虚假成功并判定 Evaluation Case 资格

## 一、需求分析

需求真理源：[[Plans/需求分析/2026-08-17-agent可信评估资格门禁]]。

作为评估负责人，我要让系统在技术执行完成但现实失败、证据不足、目标无效或 Case 未经完整复核时拒绝给出可用于切换的成功结论。

- AC1：external success + evidence 才生成 PASS；
- AC2：technical completed + external failure 必须生成 FAIL；
- AC3：unknown/缺证据生成 ABSTAIN，invalid 生成 INVALID；
- AC4：只有 reference PASS、negative control FAIL、人工签署完整时 Case qualified=true，否则返回原因；
- AC5：evaluation-domain 不依赖 DSH/Cordis/LangGraph，原工作区保持不变。

## 二、实现落点设计

机器契约：`Plans/功能开发/2026-08-17-agent可信评估资格门禁-US-EVAL-001.impl.json`。

- 修改 contracts 公共导出和根 typecheck；
- 新增纯 TypeScript `packages/evaluation-domain`；
- Red 只覆盖四态、false-success、资格拒绝和依赖隔离；
- 不实现具体 Oracle、DSH 插件、报告存储或真实 Case。

## 三、TDD

1. Red：测试因 evaluation contract/domain 尚未实现失败；
2. Green：实现最小裁决与资格函数；
3. Refactor：收紧不可变类型和理由码；
4. Integration smoke：frozen install、全部测试和 typecheck。

## 四、验收
