# 子任务 04：Chat 作用域隔离

## 输入

- 子任务03 Resolver/Access
- 现有 `NMClawChatPushHelper`、`NMChatEventDispatcher`
- 项目 iPhone/iPad Chat 导航入口

## 输出

- `NMProjectAccessContext`、`NMProjectScopeGuard`
- Project Chat 导航显式 `gateway:` 注入
- 历史/创建/发送/分享/删除统一 Access
- 企业上下文切换 drain 与旧回包丢弃
- Chat/Scope/Lifecycle 集成测试

## 边界

- 不改普通个人 Chat 默认行为。
- 项目入口不得调用默认 personal 重载。
- Access 不序列化；深链先重新 resolve。

## 验收

- [x] 项目会话创建、列表、删除、分享和 Chat 导航显式使用 `context.gateway`
- [ ] 流式事件同时匹配 gatewayKey + generation
- [ ] A→B 的旧 HTTP/Token/Socket 结果均无法写 B
- [x] 登出/切企业/切环境复用连接池生命周期 drain，并清理项目知识 Token
- [ ] 覆盖 AC5, AC7, AC17

## 当前进度

- 项目 Gateway 已贯穿会话列表、创建、打开、发送、历史、模型与分享入口；iPad 切项目会重建项目子控制器，避免沿用旧上下文。
- generation 级事件过滤与 A→B 快切的运行时集成测试仍待 Swift 6.2 环境验证。
- 2026-07-28 合并 develop 新增 Chat runtime/checkpoint/history 能力时，已解决 `NMChatNetworkHandler`、`NMChatHistoryLoader`、`NMSwarmHistoryLoader`、`NMSwarmNetworkCoordinator` 冲突：连接状态按注入 Access 路由，不再由个人 Gateway 全局通知驱动项目 Handler。
- `NMChatViewController → NMChatRuntimeRegistry → NMChatRuntime → Handler/Swarm` 已贯通同一个 `NMChatGatewayAccess`；runtime 按 Gateway 分桶，主/Swarm history 与 checkpoint 使用当前 Access 的 stableID。
- 新增相同 sessionId 跨 Gateway runtime 隔离测试代码；相关 Swift 文件通过 `swiftc -parse` 和目标文件 `git diff --check`。遵项目约定未执行 `xcodebuild`/XCTest。
- 其余 16 个 merge 冲突已逐块合并并清零；额外修复 Push Helper 漏传 Gateway、离线历史缓存回读个人 Gateway、项目模型查询回读个人 RPC，以及企业知识缓存写入个人 stableID 桶的问题。

## 依赖

依赖子任务03；与子任务02/05可并行。
