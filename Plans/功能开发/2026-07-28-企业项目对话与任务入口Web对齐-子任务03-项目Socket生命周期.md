# 子任务 03：项目 Socket 生命周期

## 一、目标与范围

对齐 Web 端项目 Gateway 生命周期：共享项目在进入项目详情前建连，项目内任务列表、绑定、历史和发送复用同一 `gatewayKey`，断线后用同键重连。

需求基线：[[Plans/需求分析/2026-07-28-企业项目对话与任务入口Web对齐.md]]。

## 二、输入

- 已有 `NMProjectGatewayResolver`、`NMGatewayConnectionPool` 与项目访问上下文。
- iPhone/iPad 项目入口控制器。
- 需求 AC-02、AC-11、AC-17。

## 三、输出

- 修改 `NMProjectsService.swift` 和必要的 `NMGatewayConnectionPool.swift`。
- 修改 `NMProjectsListViewController.swift`、`NMIPadProjectsListViewController.swift`、`NMIPadProjectContentViewController.swift` 的入口前建连。
- 建连复用、同键重连、失败关闭和零重复 Socket 测试。

## 四、实现边界

- 自有项目继续使用既有个人 Gateway；共享项目必须解析项目 Gateway。
- 项目 Gateway 解析或建连失败时不得进入详情，不得回退个人 Gateway。
- 点击项目内不同任务不得创建新 Socket；只有连接失效时按同 `gatewayKey` 重连。
- 本任务不实现会话列表合并和 `set.current.session` 绑定。

## 五、验收标准

- [ ] AC-02：所有项目内 Gateway 调用使用同一显式项目连接上下文。
- [ ] AC-11：建连失败时列表、历史和发送均不继续。
- [ ] AC-17：共享项目进入详情前建连，项目内复用，同键重连。
- [ ] 自有项目验证连接池建连次数为 0；共享项目首次为 1，任务切换不增长。
- [ ] 缺项目/租户/VIM 等关键身份时 fail-closed。

## 六、依赖与阻塞

- 无前置子任务；可与 T01 并行，完成后解锁 T05、T06。
- 必须复用既有 Resolver/Pool，除非验证证明其契约不足；不得另造第二套连接池。

## 七、验证

- Resolver/Pool Spy 验证自有、共享、断线重连和失败路径。
- 静态检查所有项目入口都早于详情创建触发 resolve/connect。
- 真机验证共享项目进入和项目内任务切换。

## 八、当前进度

- 已核对既有实现：iPhone `openProject` 在 push 详情前调用 Resolver；iPad 在 `installProject` 前调用 Resolver。
- 共享项目 Resolver 先按稳定 `gatewayKey` 调用 Connection Pool，失败时不创建详情；自有项目不调用 Pool。
- iPhone/iPad 任务列表均注入入口产出的同一 `accessContext.gateway`；任务点击链路未发现新的 Pool/Resolver 调用。
- Connection Pool 对相同 key 复用既有 manager，配置变化或断线才按同 key 重连。
- 现有 Resolver 测试代码已覆盖 owned 零建连、shared 建连、失败关闭；XCTest 按用户指示不纳入本轮，Socket 复用运行态证据待 T07 人工走查。
- 新增 `NMProjectGatewayConnectionEnsurer`：共享项目断线时通过既有 Resolver/Pool 同键重连，并校验 projectId、gatewayKey、ownership 与池化 access 对象均未漂移；不允许回退个人 Gateway。
- 同一 `gatewayKey` 的并发恢复复用一个 reconnect task，避免列表加载与任务点击同时触发重复 Socket。
- iPhone/iPad 的任务列表首次加载与错误重试、既有任务 bind、新任务 create 均在项目 RPC 前调用连接保障；项目切换/任务取消后不继续旧链路。
- 新增 connected-skip、shared reconnect、并发 single-flight、route-change fail-closed、owned zero-resolve 测试代码；相关 Swift 文件通过 `swiftc -parse`，并随 App 完成真机目标编译、安装和启动。
