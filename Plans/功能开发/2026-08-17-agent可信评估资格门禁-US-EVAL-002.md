# US-EVAL-002：真实遗留定义 Case 与 FileStateOracle 资格预览

## 一、需求分析

需求真理源：[[Plans/需求分析/2026-08-17-agent可信评估资格门禁]]。

作为评估负责人，我要用已确认的真实遗留定义升级任务验证 FileStateOracle 能区分参考解、非法版本、禁止副作用和无效目标，并在我尚未复核运行证据时保持 Case 未合格。

- AC6：参考 fixture 生成 success/PASS 和文件哈希证据；
- AC7：非法版本负对照生成 failure/FAIL；
- AC8：额外修改 prompt 的负对照生成 failure/FAIL；
- AC9：缺目标或路径越界生成 INVALID；
- AC10：资格预览保留 `HUMAN_REVIEW_INCOMPLETE`，不得代签 reviewer。

## 二、实现落点设计

机器契约：`Plans/功能开发/2026-08-17-agent可信评估资格门禁-US-EVAL-002.impl.json`。

- 通用 FileStateOracle 独立 package，不依赖 DSH/LangGraph；
- versioned Case package 保存 baseline/reference/negative/invalid fixtures；
- Case runner 只输出资格预览 JSON，不写最终签署；
- 测试覆盖重复运行稳定性、目标哈希、禁止副作用和路径身份。

## 三、TDD

1. Red：先创建 Oracle/Case 测试，因实现不存在失败；
2. Green：最小实现快照、哈希、diff 和预览；
3. Refactor：收紧路径越界、证据 URI 和确定性排序；
4. Integration smoke：frozen install、全测、typecheck、Case CLI 两次一致。
