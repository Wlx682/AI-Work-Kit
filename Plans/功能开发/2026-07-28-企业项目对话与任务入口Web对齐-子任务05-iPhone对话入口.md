# 子任务 05：iPhone 对话入口

## 一、目标与范围

把 iPhone 项目任务列表、既有任务进入和新建任务流程接入统一 Loader、项目 Socket 与会话绑定协调器。

## 二、输入

- T02 企业会话加载器、T03 Socket 生命周期、T04 绑定协调器。
- `NMProjectDetailViewController+Navigation.swift`、`NMProjectConversationListViewController.swift`、`NMClawChatPushHelper.swift`。
- 需求 AC-02、AC-05、AC-06、AC-07、AC-10、AC-11、AC-12、AC-14、AC-15、AC-17。

## 三、输出

- iPhone 项目任务列表使用 Gateway 真相源和完整列表状态。
- 既有任务：点击 → 绑定 → 加载历史 → 进入对话。
- 新建任务：创建运行会话 → 绑定 → 进入对话 → 首条消息仅投递一次。
- 错误态、发送门禁和草稿保留。

## 四、实现边界

- 页面只消费显式项目/Gateway/Bound Target，不从全局状态重新猜项目。
- 绑定或重连完成前禁用发送；失败后保留用户草稿。
- Pending 首条消息必须有一次性消费语义，重试不得重复发送。
- 不修改 App 主任务页 `MainList` / Search 的过滤或项目路由。

## 五、验收标准

- [ ] AC-02、AC-17：iPhone 全链路复用进入项目时建立的 Gateway。
- [ ] AC-05、AC-06、AC-14：既有任务先绑定，再加载历史或发送。
- [ ] AC-07、AC-15：新任务首条消息一次，失败保留草稿。
- [ ] AC-10、AC-11、AC-12：加载/空/错误/重试完整，失败不误入 Chat。
- [ ] 快速点击由 T04 last-wins 约束，页面不产生重复导航。

## 六、依赖与阻塞

- 依赖 T02、T03、T04。
- 视觉沿用现有组件，不新增设计系统；若现有 Chat 构造器缺显式 Bound Target，改造应控制在项目入口链路。

## 七、验证

- 控制器/导航 Spy 验证事件顺序和导航次数。
- 静态检查 MainList/Search 无改动。
- 真机走查自有/共享项目、既有/新建任务、断网/无权限/会话失效。

## 八、当前进度

- iPhone 既有任务已改为 bind 成功后才 push Chat，历史与发送使用 Bound Target。
- 新建任务已改为 create → bind → push；pending delivery 继续由 Chat 容器一次性消费。
- 输入栏发送回调设置 `skipResetForCurrentSend`：create/bind 期间禁用再次发送，失败保留原草稿，成功后才清空项目输入栏。
- Router Params 使用显式 `projectId`、bound sid/key 和 `active=true`。
- Gateway 硬失败会显示“任务加载失败，点击重试”，不再伪装为空任务；MainList/Search 未修改。
- 共享项目断线后，列表首次加载/重试、既有任务 bind 和新任务 create 都会先按原 `gatewayKey` 恢复池化 Socket；恢复失败不进入 Chat，草稿仍保留。
- `NAMIWork` Debug App 已构建、安装并启动到 `longxiang的iPhone`；登录态下的企业项目既有/新建任务点击结果仍待人工记录。
