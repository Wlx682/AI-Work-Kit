# 子任务07：停止置灰 + 历史恢复 + 草稿废弃

**parent**：[[2026-07-06-纳米AI助理计划模式计划卡片]]
**覆盖 AC**：AC9, AC9-反, AC6-反
**依赖**：T02（状态机），收尾于 T05/T06 之后

## 输入
- 方案 §5.5 流程二 + 需求 §D P0-3：**按钮可点 = pending && 会话未终止**。⚠️ 主动停止后 tool 停在 toolCall、不来 toolResult，phase 兜不住，必须靠终态把 pending 翻 disabled。
- 现有中止链：`NMChatViewModel.applyUserAbortTerminal`（`ViewModel/NMChatViewModel.swift:222`）+ `NMChatCommandProcessor.makeLocalAbortCommands`（`Command/NMChatCommandProcessor.swift:736`）；服务端终态 `final/error/aborted`（`NMChatCommandProcessor.swift:694` 等）。
- 历史映射：`NMChatHistoryMapper`（`Network/SubHandlers/NMChatHistoryMapper.swift`）+ 完成态分析 `NMChatHistoryCompletionAnalyzer`。

## 步骤
1. **实时终态置灰**：在 `NMChatViewModel` 处理终态（用户 abort 的 `applyUserAbortTerminal`，以及服务端 final/error/aborted 命令批处理收口）后，遍历 `cellViewModels`，把所有 `NMChatPlanCardCellVM` 中 `approvalState==.pending` 的翻 `.disabled` 并加入 `updatedItemIds`。抽一个私有方法 `disablePendingPlanCards()` 统一调用。
2. **历史恢复置灰**：历史映射出计划卡片时（ExitPlanMode tool 在历史 transcript 里），若该轮 `completionState` 为 aborted/error/已完成且该 toolCall 无对应 toolResult → 计划卡片初始态置 `.disabled`；末尾停在 toolCall 且该轮未终止 → `.pending`（可点）。落在 `NMChatHistoryMapper` 或 ViewModel 的历史 replace 逻辑。
3. **AC6-反 计划态不计执行费**：纯客户端确认——计划卡片生成/修改**只调 answerPlan / 渲染**，不触发任何执行侧请求；写注释标明计费由服务端按 R1/R3 口径处理，端无执行请求即可。草稿离开/新建任务（R3）：新会话/切会话时旧计划卡片随会话清理，端不发 answerPlan 即等价"不执行"。

## 输出
- `disablePendingPlanCards()` + 终态调用点 + 历史恢复置灰逻辑。

## 验收
- [ ] `xcodebuild build` 通过。
- [ ] AC9：草稿态点「停止」→ 该卡两按钮置灰不可点。
- [ ] AC9-反：会话已停止后再点开始执行/修改，无响应、不发 answerPlan。
- [ ] 历史恢复：末轮 aborted → 卡片置灰；停在 toolCall 且未终止 → 可点。
- [ ] AC6-反：计划态/修改期无任何执行侧请求发出（可 grep 调用链确认仅 answerPlan）。

## 不做
