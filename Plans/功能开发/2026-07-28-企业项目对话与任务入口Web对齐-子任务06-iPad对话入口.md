# 子任务 06：iPad 对话入口

## 一、目标与范围

把 iPad 分栏项目内容与对话入口接入和 iPhone 相同的 Loader、项目 Socket 与 Bound Target，消除由全局当前项目推导造成的串项目风险。

## 二、输入

- T02、T03、T04 的共享服务。
- `NMIPadProjectContentViewController.swift`、`NMIPadProjectsListViewController.swift`。
- 需求 AC-02、AC-05、AC-06、AC-08、AC-10、AC-11、AC-12、AC-14、AC-15、AC-17。

## 三、输出

- iPad 项目内容控制器显式持有并传递 `projectId`、`gatewayKey` 与 Bound Target。
- 既有/新建任务进入流程与 iPhone 一致。
- 分栏切换、项目切换和失败状态不会复用旧项目上下文。

## 四、实现边界

- 禁止从 singleton/global current project 反推项目身份。
- 分栏 UI 可复用现有布局，但数据和进入状态必须以显式项目上下文驱动。
- 绑定或重连未完成时不展示可发送状态；失败保留草稿。
- 不复制另一套 iPad 专用 Loader/Binder/Socket 逻辑。

## 五、验收标准

- [ ] AC-02、AC-17：iPad 项目内全链路复用进入前建立的项目 Gateway。
- [ ] AC-05、AC-06、AC-14：既有任务绑定成功后才加载历史/发送。
- [ ] AC-08：iPad 显式传递项目身份，切换项目不串数据。
- [ ] AC-10、AC-11、AC-12、AC-15：全状态、失败关闭和草稿保护生效。
- [ ] 同一项目/任务在 iPhone 与 iPad 产生等价 Bound Target。

## 六、依赖与阻塞

- 依赖 T02、T03、T04；可与 T05 并行。
- 需要在分栏复用控制器路径覆盖项目快速切换，不允许只验证首次进入。

## 七、验证

- 控制器注入与项目切换测试。
- 静态搜索确保项目对话链路不读取全局 current project。
- iPad 真机/模拟器走查分栏切换、自有/共享项目和错误恢复。

## 八、当前进度

- iPad 既有/新建任务已接入与 iPhone 相同的 Entry Coordinator 和项目 Gateway。
- Router Params 已补齐显式 `projectId`，固定使用 Bound Target 的 sid/key 与 `active=true`。
- 项目切换会 cancel 端侧任务并 invalidate binding revision，旧项目绑定完成后不能导航。
- 输入栏 create/bind 期间禁用再次发送；失败保留草稿，成功后清空并由 pending delivery 一次投递。
- 共用任务列表已区分错误与空态并支持点击重试；App 真机目标编译通过，分栏快速切换和 iPad 人工验收仍待执行。
- 共享项目断线后，列表加载/重试、既有任务 bind 和新任务 create 都会先恢复原项目池化 Socket；恢复期间若切换项目，旧链路取消且不导航。
