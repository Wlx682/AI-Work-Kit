# 子任务 02：企业会话加载器

## 一、目标与范围

把 Gateway 会话查询编排为硬依赖，把企业 HTTP 任务元数据编排为软依赖，向项目任务列表输出明确的加载、正常、空和错误状态。

## 二、输入

- T01 的 Merger 与页面模型。
- `NMProjectSessionManaging`、企业任务 Repository 和 Gateway 分页契约。
- 需求 AC-01、AC-02、AC-03、AC-04、AC-10。

## 三、输出

- 新增 `NAMIWork/Features/Projects/Service/NMEnterpriseProjectConversationLoader.swift`。
- 修改 `NMProjectConversationListViewModel.swift`，补齐错误、重试、空态和分页状态。
- Gateway 硬失败、HTTP 软失败、分页和取消过期请求的测试。

## 四、实现边界

- 首屏和翻页都只能由 Gateway 会话查询扩充行；HTTP 不能单独补行。
- Gateway 查询失败直接进入可重试错误态，不得回退为 HTTP 全量任务。
- HTTP 失败仅损失展示元数据，不影响已有 Gateway 会话的进入资格。
- Loader 不负责 Socket 建连、会话绑定或页面导航。

## 五、验收标准

- [ ] AC-01、AC-04：运行会话是唯一列表事实源，HTTP-only 不出现。
- [ ] AC-02：查询使用当前项目对应的 Gateway 上下文。
- [ ] AC-03：HTTP 元数据失败时保留 Gateway 列表。
- [ ] AC-10：加载、空、错误和重试状态可区分，错误不会伪装成空列表。
- [ ] Gateway 失败时验证 HTTP 回退调用次数为 0。

## 六、依赖与阻塞

- 依赖 T01；完成后解锁 T05、T06。
- XCTest 既有工程问题仍为验证阻塞，不扩张为修复测试基础设施。

## 七、验证

- Swift 语法检查和 Loader 依赖方向静态检查。
- 通过 Spy 验证 Gateway/HTTP 调用顺序、失败策略与分页。
- XCTest 工程恢复后定向运行 Loader 测试。

## 八、当前进度

- 已新增 `NMEnterpriseProjectConversationLoader.swift` 并加入 App target。
- 首屏改为 Gateway 运行会话硬依赖 + HTTP 元数据软依赖；Gateway 失败不回退 HTTP，HTTP 失败保留 Gateway 列表。
- 翻页只调用 Gateway，并复用首屏已加载元数据；ViewModel 已改用 Loader，企业会话不再由 HTTP 直接造行。
- 已补充真相源、Gateway 失败和 HTTP 软失败测试代码；Swift 语法、pbxproj、diff 检查及 `NAMIWork` Debug App 真机目标编译通过。XCTest 按用户指示不纳入本轮。
