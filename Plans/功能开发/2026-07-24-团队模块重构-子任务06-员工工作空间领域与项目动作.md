# 子任务 T06：员工工作空间领域与项目动作

## 输入

- T02 Team Service；员工公开内容与 items API 契约。
- 技术方案 ADR-5/6/7，需求 AC13–AC21/AC25。

## 输出

- `NMTeamWorkspaceContext/Models/ViewModel`：智能体 / 技能 / 任务 / 项目四 Tab 独立懒加载。
- 员工公开项目 detail / member 聚合、`join_status` 状态与详情页 `apply_join` 防重。
- `NMTeamProjectInviteViewModel`：owner 过滤、最大 4 并发成员检查、fail closed、`invitation_join`。
- 企业 / 员工 scope 切换清缓存与在途状态。

## 验收

- 首屏只请求默认智能体；Tab 首次选中加载一次，切回保留成功态。
- 申请与邀请的 API、身份、状态完全分离；重复提交不产生第二请求。
- 只展示当前用户可管理且目标未加入项目；未知成员状态不展示。
- 企业 / 员工变化后旧项目 / 内容回包均丢弃。

## 依赖

- T02。

## 覆盖 AC

AC13, AC14, AC18, AC19, AC20, AC21, AC25

## 不包含

- 不实现 UI，不实现公开项目内容编辑 / 审核中心 / 成员移除。

## 执行记录

- 新增 `NMTeamWorkspaceContext`，固化员工 qid / idaasUID / tenantID、企业 key 与 generation 组成的员工工作空间 scope。
- 新增 `NMTeamWorkspaceViewModel`，智能体 / 技能 / 任务 / 项目四 Tab 独立持有 state、数据、cursor 与 `hasMore`；默认只加载智能体，首次切换才加载对应 Tab，成功后切回不重复请求。
- 员工智能体 / 技能 / 任务参数与 Web 端对齐：`category_id=his_public`、目标员工 `team_user_qid`，智能体额外使用 `available_scopes=ee`；公开项目使用目标员工 idaasUID / tenantID 调用 `items/list_public`。
- 项目详情使用 `items/detail(item_uuid)` 与 `items/member(item_id)`；`join_status=0/1/2` 分别映射待审批 / 已加入 / 可申请。详情页申请只使用 `item_uuid` 调用 `items/apply_join`，普通失败解除提交态并允许重试。
- 新增 `NMTeamProjectInviteViewModel`：拉取当前用户全部项目后只保留 ownerQID / ownerIdaasUID 匹配的可管理项目，以最大 4 并发检查项目成员；成员检查失败的候选 fail closed。
- 邀请只使用目标员工 idaasUID / tenantID 调用 `items/invitation_join`；失败保留选择并允许重试，成功或终态冲突移出候选集合。
- 工作空间与邀请 VM 失效时均推进 generation、清除数据 / cursor / `hasMore` / 选择 / 写操作状态并通知 UI；所有旧员工或旧企业迟到回包均丢弃。
- AC13、AC14、AC18、AC19、AC20、AC21 的领域测试靶点已可执行；补充持有 completion 的旧员工智能体 / 项目成员回包失效测试。AC25 的弹层关闭部分留在 T08。
