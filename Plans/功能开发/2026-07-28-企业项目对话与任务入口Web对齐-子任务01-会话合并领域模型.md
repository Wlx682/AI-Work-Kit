# 子任务 01：会话合并领域模型

## 一、目标与范围

建立项目任务列表的纯领域合并规则：Gateway 运行会话决定列表行和运行态身份，HTTP 项目任务只按稳定标识覆盖标题、摘要等展示元数据。

## 二、输入

- 需求 AC-01、AC-03、AC-04、AC-16。
- 技术方案中的 `NMProjectSessionMetadataMerger`、会话身份和字段所有权约束。
- `GatewaySessionModels.swift`、现有项目任务 DTO 与首批红测。

## 三、输出

- `NMProjectSessionMetadataMerger` 及可测试的页面/合并模型。
- Gateway 与 HTTP 字段所有权、稳定匹配键和展示字段复制规则。
- 预计修改 `NAMIWork/Core/Gateway/Models/GatewaySessionModels.swift`。
- 预计新增或落在 `NAMIWork/Features/Projects/Service/NMEnterpriseProjectConversationLoader.swift` 的纯领域实现。
- `NAMIWorkTests/ClawTests.swift` 中的合并规则单元测试。

## 四、实现边界

- Merger 不依赖 UIKit、网络请求、Gateway 客户端或 Socket。
- HTTP-only 任务不得生成列表行，不按标题或数组位置猜测匹配。
- HTTP 不覆盖 Gateway 的 session key、运行状态、时间和可进入身份。
- 同名但不同稳定会话标识的任务必须保持隔离。

## 五、验收标准

- [ ] AC-01：列表基数和顺序来自 Gateway 运行会话。
- [ ] AC-03：HTTP 失败或缺失时仍能用 Gateway 会话形成可识别列表。
- [ ] AC-04：HTTP-only 任务不出现，同名不同会话不串行。
- [ ] AC-16：复制展示元数据后，Gateway 运行态字段完整保留。
- [ ] 纯领域测试覆盖匹配、未匹配、重复标题和字段冲突。

## 六、依赖与阻塞

- 无前置子任务；完成后解锁 T02、T04。
- XCTest 目标存在既有编译阻塞；开发期间先保留测试代码并执行 Swift 语法、静态范围检查，不能把未启动测试记录为通过。

## 七、验证

- `swiftc -parse` 或工程等价语法检查。
- 审查 Merger 无 UIKit/网络依赖。
- XCTest 工程恢复后定向执行合并规则测试。

## 八、当前进度

- 已新增 `NMProjectSessionMetadataMerger` 与展示元数据模型。
- 已补齐 `SessionHistoryEntry` 的只读运行态复制能力，HTTP 只能覆盖非空展示字段。
- 已编写 HTTP-only、字段保护、同名隔离、重复元数据 4 组测试。
- 相关 Swift 文件语法检查通过，且已随 `NAMIWork` Debug App 完成真机目标编译；XCTest 按用户指示不纳入本轮，不据此声明 AC 自动化通过。
