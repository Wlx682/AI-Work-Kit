# 子任务 04：会话绑定协调器

## 一、目标与范围

把 `sessions.set.current.session` 封装为可校验、可取消过期结果的串行进入流程，只有绑定成功才能产出供历史和发送使用的 Bound Target。

## 二、输入

- T01 的稳定会话身份。
- `GatewayRPCClient.setCurrentSession` 契约及错误模型。
- 需求 AC-05、AC-06、AC-11、AC-12、AC-13、AC-14、AC-16。

## 三、输出

- 新增 `NMProjectChatEntryCoordinator.swift`。
- `NMProjectSessionBinding` 端口与 `NMGatewayProjectSessionBinder` 适配器。
- 包含 `projectId`、`gatewayKey`、session identity 的 Bound Target。
- 串行 last-wins、响应校验和错误映射测试。

## 四、实现边界

- 所有绑定在目标项目 Gateway 上执行，不使用隐式全局当前连接。
- 绑定成功条件必须校验返回会话与请求目标一致。
- 快速连续点击只允许最新请求导航；旧响应不得覆盖新目标。
- 绑定失败、超时、无权限或会话消失时 fail-closed，不加载历史、不发送。
- Coordinator 不持有 UIKit 页面，不直接导航。

## 五、验收标准

- [ ] AC-05、AC-06：既有任务进入前先绑定，成功后才产出 Bound Target。
- [ ] AC-11、AC-12：连接或绑定失败不继续并映射为明确错误。
- [ ] AC-13：快速切换 last-wins，旧请求不能导航。
- [ ] AC-14：历史和发送只能接收 Bound Target。
- [ ] AC-16：绑定目标由稳定运行会话身份构成，禁止标题猜测。

## 六、依赖与阻塞

- 依赖 T01；完成后解锁 T05、T06。
- 若现有 RPC 返回结构不足以校验，先记录契约差异，再在本适配器内 fail-closed。

## 七、验证

- Binder/Coordinator Spy 验证调用顺序、错误映射、last-wins 和 Bound Target。
- 静态检查 Coordinator 无 UIKit 依赖。
- XCTest 恢复后执行并发与失败路径测试。

## 八、当前进度

- 已新增 `NMProjectChatEntryCoordinator`、`NMGatewayProjectSessionBinder`、`NMBoundProjectConversation`。
- Binder 在项目 Gateway 上调用 `sessions.set.current.session`，校验 `ok` 和响应 `sessionId`；未知方法、无连接、拒绝响应均 fail-closed。
- Coordinator 使用 revision fence 串行执行绑定，旧选择完成后返回 nil，只有最新选择可以导航。
- iPhone/iPad 的既有任务与新建任务均改为 bind 成功后 push；Router Params 固定使用 bound sid/key、`active=true` 和显式 `projectId`。
- 已补充成功、拒绝、A→B 串行且只返回 B 的测试代码。
- Coordinator 已通过 Swift 6 strict-concurrency 独立类型检查；真机构建期间发现并修复默认 binder 参数触发的 MainActor 初始化错误，随后 `NAMIWork` Debug App 编译成功。Swift 语法、pbxproj、diff 检查通过；XCTest 按用户指示不纳入本轮。
