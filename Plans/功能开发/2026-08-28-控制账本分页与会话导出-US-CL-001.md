# US-CL-001：稳定前后翻页浏览全部控制账本会话

作为控制账本使用者，我想稳定前后翻页浏览全部会话，以便较旧账本不再被固定 50 条上限遮蔽。

## 验收标准

- AC1：45 个会话默认返回最新 20 条和下一游标，连续翻页覆盖全部。
- AC2：空 corpus 和恰好一页均不返回伪下一页。
- AC3：第一页之后新增 Session，不会使下一页重复/跳过既有项；失效 cursor 明确失败。
- AC4：非法 limit 在读取任何 Session 详情前失败。
- AC5：首尾按钮正确禁用；翻页失败保留当前页并可重试。

## 故事内部实现边界

- UI / 交互：当前页、上一页游标栈、下一游标、页码、保留页加载/失败状态。
- Domain / 状态：分页 cursor 对客户端不透明；首尾操作不发无效请求。
- Data / API：新增 `listRunPage`，保留 `listRuns`；只读取当前页 Session。
- 测试与异常：多页/空/恰一页/新增 Session/失效 cursor/非法 limit/Remote 失败。

## 架构引用

- ADR-001：新增 `listRunPage` 并保留 `listRuns`。
- ADR-002：Session-id 锚点 cursor 与客户端游标栈。

## 实现落点设计

- 代码证据：`src/types.ts`、`src/index.ts`、`src/typert.ts`、`src/client/index.ts`、`src/client/ControlLedgerSection.tsx`、`tests/service.spec.ts`。
- 目标文件：修改上述契约/Host/adapter/UI/locale/CSS/test；新增 `src/client/pagination.ts` 与 `tests/client-pagination.spec.ts`。
- 模块边界：客户端 cursor 只存储回传；Host 先校验/选页再读取当前页；React 只消费 injected loader 与纯分页状态。
- Red 测试位置：`tests/service.spec.ts`、`tests/client-pagination.spec.ts`；命令见 `implementation_design` JSON。
