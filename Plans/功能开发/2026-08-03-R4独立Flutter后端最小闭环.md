## 一、需求分析与项目边界

- 需求输入：`Plans/需求分析/2026-08-03-知识图谱学习系统深色UI原型.md` 与父 plan AC-S5。
- Runtime 技术输入：`Plans/技术方案/2026-08-03-LearningAgentRuntime角色工具接入.md`。
- Flutter 工程固定为 `tmp/knowledge-graph-learning-flutter/`。
- 本地 HTTP 边界固定为 `agent/learning_api.py`。
- 复用 `agent/learning_contracts.py` 与 `agent/learning_runtime.py`，不复制一套伪 Runtime。
- 不接入 LearnStudio、aiso_flutter 或任何未确认旧项目。
- S4a 的静态 HTML 保留为视觉基准，S4b 是独立的可运行 Flutter 产品切片。

## 二、技术方案与实现切片

| 切片 | 实现 | 验收证据 |
|------|------|----------|
| Goal → Graph | 创建 Goal、Course、10 个 ConceptNode 与 prerequisite edges，JSON repository 持久化 | Python service/HTTP tests |
| Node → Session | 只有显式选择节点才创建 `LearningSession(status=learning)` | Controller + widget tests |
| Evidence → Eval | Evidence 持久化；EvalResult 更新 NodeProgress | Python tests |
| Runtime → HITL | GraphCurator → Planner → Tutor → Evaluator；proposal 触发 checkpoint/interrupt | Runtime event phases + paused response |
| Confirm → Apply | 批准后通过 GraphOperation contracts 新增 3 节点；拒绝保持 10 节点 | 真实 HTTP approve/reject tests |
| Flutter 多端 | 桌面侧栏、移动底栏、响应式图谱画布、学习面板、Eval 与 proposal 卡片 | Flutter widget tests + Web build |

## 三、接口

| Method | Path | 用途 |
|--------|------|------|
| GET | `/api/learning/health` | 本地服务健康检查 |
| POST | `/api/learning/goals` | 创建目标与课程图谱 |
| GET | `/api/learning/courses/{course_id}` | 刷新图谱与进度 |
| POST | `/api/learning/sessions` | 选择节点并启动会话 |
| POST | `/api/learning/evidence` | 提交 Evidence、运行 Eval 与 Agent Runtime |
| POST | `/api/learning/reviews` | 人工批准/拒绝并恢复 Runtime |
