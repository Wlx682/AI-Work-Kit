# 子任务 05：知识 Token 隔离

## 输入

- 子任务01 Project/Scope
- Web `project-token.ts`、`project-yunpan-access.ts`
- 现有 Cloud Drive/Knowledge 服务

## 输出

- project-token HTTP Client/Mapper
- `NMProjectKnowledgeTokenStore`
- owner QID 的 Cloud Service 创建逻辑
- 项目/账号/租户/环境失效策略
- Token 单元与集成测试

## 核心规则

- Endpoint：`POST /api/brand/claw/yp/project_token?appsource=so`
- body：`{"project_id": projectId}`
- 支持 direct data 与 `data.list[0]`
- Token 只驻留内存，不写日志/Analytics

## 验收

- [x] 同 scope 并发请求单飞
- [x] 缓存 key 含环境/租户/当前用户/项目，A→B 不命中 A Token
- [x] 他人项目 Cloud Service 与上传任务使用 owner QID
- [x] Token 错误 fail-closed，不刷新或回退个人 Token
- [ ] 覆盖 AC9, AC17

## 当前进度

- 已按 Web 行为限定为“他人企业项目”获取项目 Token；本人项目继续使用个人云盘凭证。
- Token 仅驻内存并显式贯穿列表、上传、入库、状态、建目录、删除、重命名、移动和下载；单测已编写但尚未执行。

## 依赖

依赖子任务01；与 02/03 并行。
