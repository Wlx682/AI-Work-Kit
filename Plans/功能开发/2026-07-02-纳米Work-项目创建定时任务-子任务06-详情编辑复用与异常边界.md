# 子任务 06：详情/编辑复用与异常边界

**WBS**：#9 | **依赖**：03,05

## 目标

项目任务复用现有详情/编辑/启停能力，补齐需求边界与异常态。

1. **详情/编辑复用（P0-4）**：project 任务点进详情页、可编辑，复用现有 `NMScheduledTaskDetailViewController` + 编辑页（`NMScheduledTaskCreateViewController(prefill:)`）。
   - 编辑回填时 `taskOwnerType` 复原为 project（`NMScheduledTaskMapper.editFormState` 增 owner 识别——**识别字段待与服务端确认**，先按"agentid 命中项目"占位）。
   - type 不可变：编辑页不提供"切换为专家任务"入口（AC5-反）；project 任务编辑时项目归属只读。
2. **启停/删除（P1-7）**：复用专家定时任务的暂停/启用/删除能力，project 任务一致可用。
3. **异常边界**：
   - B4 重复点击创建：首次后按钮置灰+loading（现有 `canEnableSubmitButton` + loading 已具备，验证 project 分支同样生效）。
   - B5 创建失败：Toast「创建失败，请重试」，表单内容保留不清空。
   - B3/AC8 项目删除降级：该项目下任务保留、project_id 置空、项目名显示「已删除的项目」（列表卡片 project 分支兜底文案）。
   - B1 无专家降级：@ 不弹（子任务04已处理，此处回归验证）。

## 验收

- [x] project 任务可进详情、可编辑；编辑不提供切专家入口，项目归属只读（chooseProjectTapped 对 isEditPage 只读）
- [x] 编辑回填 owner=project 正确复原（editFormState 加 owner 复原，识别占位）
- [x] project 任务可暂停/启用/删除，行为同专家任务（整链复用，未特殊化）
- [x] 创建防连点、失败保留表单、Toast 文案正确（现有机制对 project 分支生效）
- [x] 项目删除后任务显示「已删除的项目」（CellVM projectDisplayName 兜底）
- [x] 编译通过（EXIT=0）

## 落地记录（2026-07-02）

- **详情/编辑复用**：project 任务与专家任务共用 `NMScheduledTaskDetailViewController` → `fetchEditFormState` → `editFormState(from:)` → `NMScheduledTaskCreateViewController(prefill:)` 整链，无特殊化。
- **`NMScheduledTaskMapper.editFormState`**：加 owner 复原分支——`isProjectJob(job)`（**当前恒 false 占位**，待契约）为真时复原 `taskOwnerType=.project` + `projectId=agentid` + 项目名；否则走原 expert 逻辑。
- **type 不可变**：编辑页 `chooseProjectTapped` 已对 `isEditPage`/`isProjectContextLocked` 只读（子任务03），不提供切专家入口。
- **项目删除降级**：`NMScheduledTaskCellVM.projectDisplayName` 项目名为空时兜底「已删除的项目」（PRD 四·边界）。
- **防连点/失败保留/无专家降级**：分别由现有 `canEnableSubmitButton`+loading、失败 Toast 保留表单、@ 空态（子任务04）覆盖，project 分支均生效。
- **待契约 TODO**：`isProjectJob` 识别字段（与子任务05 `isProjectTask` 同源）；「项目 vs 专家创建」在编辑回显的最终识别方式。
