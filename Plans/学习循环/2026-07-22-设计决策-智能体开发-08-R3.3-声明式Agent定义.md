# 设计决策：R3.3 声明式 Agent 定义

## 七、设计决策

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 声明的所有者 | 独立 Agent Definition，不是 Orchestrator | Agent 有角色、目标、工具策略和验收；Orchestrator 是运行机制。 |
| 留在代码的内容 | LangGraph 节点、边、重规划、失败收口、安全最终裁决 | 这些决定状态机行为和真实权限，必须可测试且不可被配置越权。 |
| 最小字段 | `id`、`role`、`goal`、`tools`、`acceptance` | 足以让策略可审阅，又不把执行细节搬进配置。 |
| 定义文件格式 | JSON 元数据 + Markdown 角色说明 | JSON 用标准库严格校验；Markdown 承载长说明；不为 YAML 引入解析依赖。 |

用户选择按最佳实践采用混合定义：机器策略字段写 JSON，长角色说明写 Markdown，runtime/安全仍由 Python 代码掌控。
