### 第二课：System 2 不是“想久一点”，而是“会规划和纠偏”

System 2 在 Agent 里负责慢思考。它的核心不是输出更长，而是让 Agent 的行动更有方向。

你可以把它理解成一个循环里的“决策中枢”：

```text
读取目标
读取 state
读取 memory / context pack
生成候选计划
预测计划风险
选择一个计划
交给 System 1 执行
读取 observation
反思结果
决定推进 / 返工 / 换策略
```

用人员列表例子看：

```text
目标：进入人员列表框架设计
memory：所有需求用例 + 公共原则 + 框架设计原则

System 2 该做：
1. 检查需求 case 是否闭合
2. 把 case 分组成页面、状态、数据、接口、测试
3. 生成框架设计候选方案
4. 预测风险：状态遗漏？接口边界不清？权限规则遗漏？
5. 选择风险最低、最符合原则的方案
6. 把明确任务交给 System 1 去写设计/代码
```

## 六、问题与澄清

| 问题 | AI 回答 | 是否已懂 |
|------|---------|----------|
| System 2 和普通 prompt 有什么区别？ | 普通 prompt 可能只生成一次答案；System 2 会读取状态和记忆，生成计划，预测风险，并根据反馈持续修正。 | ⬜ |
| 为什么 System 2 需要 memory？ | 因为规划不能凭空生成。上一轮的 case、原则、约束会限制下一轮可选方案。 | ⬜ |
| 内在模拟和真实执行有什么区别？ | 内在模拟是行动前预测，真实执行是行动后拿反馈。模拟降低试错成本，但不能替代真实结果。 | ⬜ |

### 你现在先做一个小复述

请用“人员列表框架设计”这个例子回答：

1. System 2 在进入框架设计前要读哪些输入？
2. 它应该生成什么计划？
3. 它行动前要预测哪些风险？

### 用户复述与 AI 校正

| 题目 | 用户回答 | 判断 | 校正后应掌握 |
|------|----------|------|--------------|
| 进入框架设计前要读哪些输入？ | 需求的所有 case、当前代码框架、框架设计原则、边界、System 1 能力 | ✅ 主干正确 | 还要补充当前 state、验收标准、上轮 memory/context pack、可用工具与安全约束。System 2 不能只读“材料”，还要读“现在处于什么状态、允许怎么行动、行动能交给谁执行”。 |
| 应该生成什么计划？ | 框架设计计划 | ✅ 正确但需要展开 | 合格计划要拆成可执行任务包：模块边界、状态流、数据结构、API 契约、测试点、执行顺序，以及哪些交给 System 1 生成/修改。 |
| 行动前要预测哪些风险？ | 框架兼容性、设计复杂度 | ✅ 抓到关键风险 | 还要预测 case 遗漏、边界不清、现有代码冲突、过度设计、System 1 无法执行、测试盲区和返工成本。 |

### 学习结论

```text
你已经抓住 System 2 的核心：
1. 它读完整上下文，不是凭空规划。
2. 它输出可执行计划，不只是想法。
3. 它行动前做风险预测，降低返工。
```
