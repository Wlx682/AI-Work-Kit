## 七、实践任务

| 任务 | 输入 | 产物 | 验收 |
|------|------|------|------|
| 最小目标循环模拟器 | 一个目标字符串，例如“整理今天的学习收获” | 一个能输出 state / action / observation / reflection / memory 的小程序或伪代码 | 能看出状态、反思、记忆三者都存在，且下一轮会用到上一轮记忆 |

### 实践要求

先不要追求框架，也不要接真实 LLM。只做一个最小循环，核心是把你刚才说的三件事落到结构里：

```text
state：当前目标、当前步骤、历史观察
reflection：根据观察判断做得好不好，下一步怎么修正
memory：把可复用经验保存起来，下次循环读取
```

最小伪代码：

```python
state = {
    "goal": "整理今天的学习收获",
    "step": 0,
    "observations": [],
}

memory = []

def plan(state, memory):
    return "写出 3 条学习收获"

def act(plan):
    return "我学到：Agent 需要状态、反思、记忆"

def observe(result):
    return {"result": result, "ok": "状态" in result or "记忆" in result}

def reflect(observation):
    if observation["ok"]:
        return "方向正确，下一轮补充反思机制"
    return "缺少核心概念，下一轮重写"

def remember(reflection):
    memory.append(reflection)
```

### 你要完成的版本

请你先用自己的话写出一个更贴近 Agent 的版本，必须包含：

```text
1. state 里存什么
2. reflection 根据什么判断
3. memory 保存什么
4. 下一轮如何使用 memory
```

## 八、实践产物

| 产物 | 路径/链接 | 说明 |
|------|-----------|------|
| 最小目标循环模拟器 | 用户口头版：人员列表需求分析 → 框架设计 | 已能表达 state / reflection / memory；下一轮如何使用 memory 需要补清 |

### 用户实践输入（2026-07-09）

| 项 | 用户回答 | AI 校验 |
|----|----------|---------|
| state 里存什么 | 人员列表需求分析完成 | 方向对，但 state 不应只存一句结论，还应包含当前目标、阶段、完成事实、阻塞、下一步。 |
| reflection 根据什么判断 | 需求的所有 case 逻辑闭合，下一步开始框架设计 | 通过。这就是根据验收条件判断是否进入下一阶段。 |
| memory 保存什么 | 所有的需求 case | 部分通过。原始 case 要保存，但更重要的是保存“可复用的规则、边界、决策和验收标准”。 |
| 下一轮如何使用 memory | 不知道 | 待补。下一轮框架设计要把 memory 当作输入约束，逐条映射到模块、状态、接口和测试。 |
| 下一轮如何使用 memory（补答） | 将所有需求用例和公共原则，以及框架设计原则一起给到 LLM | 通过。更准确地说：把 memory 组织成 context pack，作为下一轮框架设计的输入约束和验收依据。 |

### 纠偏后的版本

```text
state:
  goal: 完成人员列表功能从需求分析到框架设计
  current_stage: requirement_done
  completed:
    - 人员列表需求分析完成
    - 所有需求 case 已闭合
  next_stage: architecture_design
  blockers: []

reflection:
  判断依据:
    - 是否覆盖所有人员列表 case
    - case 之间是否逻辑闭合
    - 是否存在未确认边界
  结论:
    - 若全部闭合，进入框架设计
    - 若存在缺口，回到需求补充

memory:
  保存:
    - 人员列表全部需求 case
    - 关键业务规则
    - 边界条件
    - 已确认的产品决策
    - 后续验收标准

next_round_use_memory:
  框架设计阶段读取这些 case，把它们转成:
    - 页面/模块边界
    - 数据结构
    - 状态流转
    - API 契约
    - 测试用例
```

### 实践通过结论

用户已经理解“memory 如何进入下一轮”：

```text
不是把记忆简单贴给 LLM，而是把上一轮沉淀的需求用例、公共原则、框架设计原则组织成结构化 context pack，
让下一轮 planner / LLM 在这些约束下输出框架设计。
```

最小闭环成立：

```text
state: 人员列表需求分析完成，准备进入框架设计
reflection: 所有需求 case 逻辑闭合，所以允许进入下一阶段
memory: 需求 case、公共原则、框架设计原则
next use: 作为下一轮 LLM 框架设计的输入约束
```
