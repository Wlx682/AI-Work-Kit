# 设计决策：R3.2 Trace 与 Eval

## 七、设计决策

| 决策点 | 用户选择 | 实现约束 | 理由 |
|--------|----------|----------|------|
| trace 写入失败的语义 | 默认成功但告警 | 不修改 `RunResult.succeeded`；追加 `warnings`；打印持久化失败原因 | 业务完成和观测降级是不同事实，不能因仪表盘失效否认已完成的任务。 |
| trace 保存格式 | 每个 run 一个 JSON | `agent/traces/<run_id>.json`，包含 schema 版本、保存时间和可序列化结果 | 不增加数据库依赖，方便人工读取和测试 round-trip。 |
| eval 输入 | 离线 fixture | mock 规划、预测、执行、反思；不调用真实 LLM 或网络 | 固定评估的是运行时行为，不让模型随机性污染回归测试。 |

## 八、编码实现

| 任务 | 产物 | 验收 |
|------|------|------|
| 扩展运行结果 | `RunResult.warnings` | 默认值保持旧调用方兼容，warning 不影响成功语义 |
| 保存 trace | `TraceStore` 与 JSON 结果契约 | 成功与失败运行均能读取回相同字段 |
| 接入 runtime | `LangGraphRuntime.run()` 非致命落盘 | 保存故障加入 warning，不覆盖业务错误 |
| 离线 eval | 三个固定场景测试 | 断言结果、事件、trace 文件和告警行为 |
