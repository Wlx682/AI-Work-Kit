## 十一、复盘

| 维度 | 内容 |
|------|------|
| 已掌握 | System 2 需要读完整输入；它要生成计划；行动前要预测风险；它还要约束 System 1，避免误删无关代码 |
| 未掌握 | 容易把业务状态流写成 workflow 状态；容易跳过 API 契约；执行任务包还不够像“给 System 1 的合同” |
| 误区 | “我明白”不等于 System 2 计划已完成。System 2 的输出必须能被另一个执行者复用 |
| 最有价值的一点 | 你补到了“代码可能正在被修改，不能强制删除无关代码”，这是 System 2 对工具行动的安全约束 |

### 本轮核心结论

```text
System 2 不是负责“想得多”，而是负责：
1. 读完整上下文。
2. 把目标拆成可执行计划。
3. 行动前模拟风险。
4. 把任务包交给 System 1。
5. 给 System 1 加边界：不能乱删、不能越权、不能破坏架构原则。
```

### 仍需补练的最小点

```text
业务状态流：
  idle -> loading -> success / empty / error
  success -> refreshing -> success / refreshError
  success -> loadingMore -> success / noMore / loadMoreError

API 契约：
  GET /persons?page=&pageSize=
  response: { list: PersonItem[], page: number, hasMore: boolean }

System 1 任务包：
  输入、输出、禁止项、完成反馈必须写清楚。
```
