# 需求分析：云盘三 Tab 页面缓存

**所属 Epic**：`Plans/Epic/2026-06-30-云盘三Tab页面缓存.md`
**平台**：客户端（NNamiWork，iOS） · **含业务逻辑**：是（数据流接线，非纯 UI）

---

## 一、需求背景

云盘页（`NMCloudDriveController`）有 3 个 tab，每次进入都要等网络返回才出数据，首屏白屏 / loading 遮罩体验差。项目已有统一缓存框架 `NMCacheService`（SWR：`primeFromCache` 秒显 + `persistIfNonEmpty` 防空覆盖），技能 / 推荐 / Projects tab 已落地此范式。本需求将同样的页面缓存能力补到云盘 3 个 tab。

3 个 tab：
| Tab | 控制器 | ViewModel | 列表模型 | 数据落点 |
|-----|--------|-----------|----------|----------|
| 用户上传 | `NMCloudDriveUserUploadController` | `NMCloudDriveUserUploadViewModel` | `[NMCloudNode]`（已 Codable） | `updateDataSource(isAppend:false)` |
| AI文件 | `NMAIFilesViewController` | `NMAIFilesViewModel` | `[ClawFileItem]`（非 Codable） | `handleLoadSuccess(isRefresh:true)` |
| 工作空间 | `NMNewWorkspaceController` | `NMNewWorkspaceViewModel` | `@Published nodes: [NMFileNode]`（非 Codable） | `handleResult` |

---

## 二、需求决策（已与用户确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 缓存范围 | **仅首页首屏（第一页）**，不缓存分页加载的后续数据。对齐技能/推荐 tab。 |
| 2 | 工作空间层级 | **仅缓存根层（专家文件夹列表 `currentLevel == .root`）**，进入子级（会话/文件）不缓存。 |
| 3 | 序列化方案 | **统一走 `NMCacheService` 框架**：每个 tab 声明一个 `CacheEntry`(spec) + store。非 Codable 模型缓存其上游 Codable 原始模型（详见技术方案）。 |
| 4 | 失效作用域 | 登出清理（`.user` scope），靠 per-qid 分桶天然隔离。 |
| 5 | 缓存键（bucketKey） | 用户上传 / AI文件：固定单桶（首页唯一）。工作空间根层：固定单桶。 |

---

## 三、验收标准（AC）

| AC | 描述 | 可测条件 |
|----|------|----------|
| AC1 | 用户上传 tab：二次进入命中缓存秒显首屏 | 有缓存时不闪 loading，先渲染缓存再被网络结果覆盖 |
| AC2 | AI文件 tab：同 AC1 | 同上 |
| AC3 | 工作空间 tab：根层二次进入命中缓存秒显 | 进入子级不读/写缓存 |
| AC4 | 防空覆盖 | 网络返回空列表时不冲掉已有有效缓存（`persistIfNonEmpty`） |
| AC5 | 失效 | 登出后缓存清空，换账号不串数据 |
| AC6 | 不回归 | 分页、下拉刷新、上传/删除/重命名后列表刷新行为不变；编译通过 |

---

## 四、边界与非目标

- **非目标**：不缓存分页数据、不缓存工作空间子级、不做 TTL 过期（登出/网络刷新即更新）。
- **边界**：网络成功但空结果 → 不落盘（防空覆盖）；网络失败 → 保留缓存，不清空。
- **风险**：AI文件 / 工作空间列表模型非 Codable，需在技术方案阶段确定「缓存上游 Codable 模型 + 渲染时映射」的具体落点。
