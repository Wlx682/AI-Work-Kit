# 事件风暴：团队模块重构

**目标**：按 2026-07-24 新版设计，把既有“团队首页 + 组织架构”重组为“部门 / 专家”统一入口，并补齐部门服务、部门成员、员工工作空间及邀请加入项目的业务边界。

**当前结论**：WBS 1–2 已完成；2026-07-27 最新确认部门只保留一级列表页，不再多级下钻；一级部门直接进入“部门服务 / 成员”详情。本文件是后续技术方案、测试与开发的需求真理源。

### 继承规则

- 仅企业账号展示团队入口；非企业账号不得发起 `api/claw/ent/*` 或企业公开内容请求。
- 所有异步结果必须同时通过 generation 与当前 `enterpriseKey` 校验，企业切换后旧响应不得覆盖新企业。
- 组织与成员数据、部门服务、员工公开内容均不得用 Figma 示例数据作线上兜底。
- 加载、空、失败、分页失败必须可区分；已成功区域不得被另一请求失败清空。
- 既有团队首页、组织架构代码是可复用实现背景，不再作为新版信息架构真理源。

## 三、业务对象与不变条件

| 聚合 / 对象 | 关键标识 | 不变条件 |
|-------------|----------|----------|
| 企业上下文 | `tenantID + qid + idaasUID` | 三项有效；响应返回时 `enterpriseKey` 仍匹配当前企业 |
| 部门 | `organizationID` | 团队页只展示一级部门；无论是否包含 children，点击后都直接进入“部门服务 / 成员”详情 |
| 部门服务 | `agentID / clawName` | 复用旧团队智能体单列表；所有一级部门看到同一列表，不按 `organizationID` 切分 |
| 专家 | 分类 ID / `agentID / clawName` | 复用旧专家页分类、榜单和搜索；“我的”从旧顶级 Tab 合并到二级分类 |
| 员工 | `idaasUID + tenantID`，必要时含 `qid` | 必须属于当前企业；公开内容请求使用目标员工身份，不覆盖当前登录人身份 |
| 员工公开内容 | 内容主键 + `team_user_qid` / `idaasUID` | 只展示公开范围；工作空间四 Tab 独立分页、独立空错态、切换不串页；智能体和任务点击无动作，技能打开既有弹窗，项目通过“查看”进入公开详情 |
| 项目申请 | `itemUUID + currentUser` | 只能在公开项目详情页发起 `apply_join`；任务 / 专家 / 成员不可点击，知识仅允许目录浏览与文件预览；重复申请不可重复提交，已加入隐藏入口 |
| 项目邀请 | `itemUUID + targetMember` | 项目须允许当前用户邀请；目标员工有效；重复提交不可造成重复成员 |

## 六、输出到实例化需求

### 必须覆盖的主链路事件

- 企业身份识别 → 团队页 → 部门列表 → 部门服务 / 成员。
- 部门成员 → 员工工作空间 → 智能体 / 技能 / 任务 / 项目。
- 员工工作空间 → 选择项目 → 邀请加入 → 成功 / 失败反馈。
- 部门 / 专家切换与各搜索链路。
- 企业切换时旧响应失效与新企业重载。

### 必须写成 Given-When-Then 的边界

- 非企业账号、企业身份缺字段、企业切换、员工离职 / 部门失效。
- 部门为空、部门服务为空、成员为空、四类员工内容分别为空。
- 搜索防抖、清空还原、无结果、旧搜索回包、分页失败与重试。
- 员工公开内容越权或下架、项目不可邀请、成员已在项目、重复点击邀请。
- 标题 / 名称 / 简介超长，小屏与安全区，底部按钮不遮挡列表末项。

### 暂不纳入范围

- 组织架构编辑、成员新增 / 移除、部门新增 / 删除。
- 员工私有智能体、技能、任务、项目及其管理操作。
- 项目申请审核中心、成员移除、项目公开性设置。
- 新造技能详情弹窗；已明确复用既有 `NMClawSkillDetailPopupController`。
