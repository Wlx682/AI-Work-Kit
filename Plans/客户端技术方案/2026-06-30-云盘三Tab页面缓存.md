# 技术方案：云盘三 Tab 页面缓存

**所属 Epic**：`Plans/Epic/2026-06-30-云盘三Tab页面缓存.md`
**需求 plan**：`Plans/需求分析/2026-06-30-云盘三Tab页面缓存.md`

---

## 一、设计原则

完全复用现有 `NMCacheService` 框架与 SWR 范式（对齐 `NMClawSkillListVM`）：
1. 每个 tab 声明一个 `CacheEntry`(spec)，在 `NMCacheService` 加一个 store 属性，registry 加一行（scope=`.user`）。
2. 在各 tab 的 ViewModel 加 `loadCachedFirstPageIfNeeded()`：用 `primeFromCache` 首屏同步秒显。
3. 在网络成功落点用 `persistIfNonEmpty` 防空覆盖落盘。
4. 控制器在触发网络加载前先调 `loadCachedFirstPageIfNeeded()`。

**关键约束**：缓存只在「首页 / 根层」生效，分页 append、工作空间子级不读写缓存。

---

## 二、三 tab 序列化方案（核心难点）

3 个 tab 的列表模型 Codable 情况不同。统一用框架的 `CacheTransformer` 解决——它本就是「序列化热插拔点」，自定义 `encode/decode` 即可桥接，**不改动展示模型**。

### Tab 1 · 用户上传（最简单）
- 列表模型 `NMCloudNode` 已是 `Codable`。
- Spec：`UserUploadNodeCacheSpec`，`Value = NMCloudNode`，`Stored = NMCloudNode`，`transformer = .codable`。
- store：`DiskCacheArrayStore<UserUploadNodeCacheSpec>`，bucketKey 固定单桶 `"first_page"`。

### Tab 2 · AI 文件（非 Codable 展示模型）
- 列表模型 `ClawFileItem` 非 Codable，但其字段全是值类型。
- 方案：定义 Codable DTO `ClawFileItemCacheDTO`（镜像 `ClawFileItem` 字段，含 `ClawItemType` 的扁平化 `isDir + ext`），用**自定义 `CacheTransformer<ClawFileItem, ClawFileItemCacheDTO>`** 双向转换。
- Spec：`AIFilesCacheSpec`，`transformer` 用自定义构造（`encode: ClawFileItem → DTO`，`decode: DTO → ClawFileItem`）。
- store：`DiskCacheArrayStore<AIFilesCacheSpec>`，bucketKey 固定单桶 `"first_page"`。
- 理由：DTO + 自定义 transformer 是框架推荐的新范式扩展点（见 `CacheTransformer.swift` 注释），不污染 `ClawFileItem`。

### Tab 3 · 工作空间根层（非 Codable + 多级）
- `NMNewWorkspaceViewModel.nodes` 为 `[NMFileNode]`（enum source，非 Codable）。
- **只缓存根层**：根层 node `kind == .agentFolder`，`source == .agent(NMWSAgentItem)`，而 `NMWSAgentItem` **已 Codable**。
- 方案：缓存 `[NMWSAgentItem]`（上游 Codable 模型），读盘后 `.map { $0.makeFileNode() }` 还原为 `[NMFileNode]`。
- Spec：`WorkspaceAgentCacheSpec`，`Value = NMWSAgentItem`，`transformer = .codable`。
- store：`DiskCacheArrayStore<WorkspaceAgentCacheSpec>`，bucketKey 固定单桶 `"root_agents"`。
- 门控：仅 `currentLevel == .root` 且非 append 时读/写缓存。

## 三、接线落点（每 tab 三处）

| Tab | Spec 文件 | prime 落点（读） | persist 落点（写） |
|-----|-----------|------------------|--------------------|
| 用户上传 | 新建 `NMCloudDriveCacheSpecs.swift` | VM 新增 `loadCachedFirstPageIfNeeded()`，控制器 `viewDidLoad` 加载前调用 | `loadFirstPage` 成功分支 `updateDataSource(isAppend:false)` 后 |
| AI文件 | 同上 | VM 新增同名方法，控制器加载前调用 | `handleLoadSuccess(isRefresh:true)` 内 |
| 工作空间 | 同上 | VM 新增同名方法（仅 root），`loadInitialData` 前调用 | `handleResult` 成功且 `currentLevel==.root && !isAppending` 后 |

新增的 spec / DTO / transformer 集中放 `NAMIWork/Core/Services/Cache/NMCloudDriveCacheSpecs.swift`（或拆薄壳 `NMCloudDriveDiskCache.swift`，对齐 `NMClawSkillDiskCache` 范式）。

## 四、NMCacheService 改动

```swift
// stores 区
let cloudUserUploadFirstPage = DiskCacheArrayStore<UserUploadNodeCacheSpec>()
let cloudAIFilesFirstPage     = DiskCacheArrayStore<AIFilesCacheSpec>()
let cloudWorkspaceRootAgents  = DiskCacheArrayStore<WorkspaceAgentCacheSpec>()

// registry 区（均 .user scope）
(.user, cloudUserUploadFirstPage.clear),
(.user, cloudAIFilesFirstPage.clear),
(.user, cloudWorkspaceRootAgents.clear),
```

## 五、风险与回归

| 风险 | 对策 |
|------|------|
| AI文件首屏缓存命中后被网络空结果覆盖 | `persistIfNonEmpty` + prime 只在 `items.isEmpty` 时渲染 |
| 工作空间在子级误用根层缓存 | prime/persist 均加 `currentLevel == .root` 门控 |
| ClawFileItem DTO 字段遗漏导致信息丢失 | DTO 逐字段镜像，preview/导航所需字段（path/fileId/sessionId/url 等）全覆盖 |
| 编译：transformer 泛型推断 | 自定义 transformer 显式标注类型，对齐 `.mappable` 写法 |
| 登出串数据 | 三 spec scope=`.user`，挂 registry 自动失效 |

---

## 六、不做（非目标）

- 不缓存分页后续数据、不缓存工作空间子级、不做 TTL。
- 不改动 `ClawFileItem` / `NMFileNode` 本体（用 DTO/上游模型桥接）。
- 不引入 wcdb 后端（首屏秒显用 `.file`）。
