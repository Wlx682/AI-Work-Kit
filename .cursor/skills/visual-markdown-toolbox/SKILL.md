# 图文工具箱

这是一个轻量路由 Skill，不接管写作结构，只帮助选择合适的图文表达。

## 原则

先把知识保留为可维护文本语法，再由 Markdown 预览或 HTML 渲染。Mermaid 常用，但不是上限。

Markdown 中出现三步以上流程、三个以上模块、状态变化、反馈闭环或多方交互时，主动判断能否用流程图、架构图、状态图或时序图降低理解成本；优先保留图源，不用生成式插画替代结构表达。

## 原子选择

| 内容块 | 首选表达 | 要点 |
|---|---|---|
| 公式/数学 | LaTeX + MathJax/KaTeX | 保留公式，解释符号、直觉和适用边界 |
| 普通流程/时序/状态/ER/Gantt/Git/C4 草图 | Mermaid | 用合适 diagram 类型，不把所有内容都画成 flowchart |
| 标准 UML/软件设计 | PlantUML | 类图、时序图、活动图、用例图、组件图、状态图 |
| 复杂依赖/DAG/调用图/拓扑 | Graphviz/DOT 或 D2 | 自动布局，边和分组必须有语义 |
| benchmark/趋势/消融/热力图 | ECharts、Chart.js、Vega-Lite、Observable Plot | 保留数据、单位、坐标轴、样本量和比较基线 |
| 研究谱系/概念树/方法族 | markmap 或 Mermaid mindmap | 保留层级，不改成线性流程 |
| API/Schema/配置/约束 | Markdown/HTML 表格 + code block | 字段、类型、默认值、约束、示例分开 |
| 算法/策略逻辑 | 伪代码块 | 保留控制流和变量名，必要时标注关键行 |
| 原文关键图 | 重画为 SVG/DOT/Vega/HTML，或在允许时引用 | 保留结构并标注来源，不热链版权不明图片 |

## 工具速查

| 工具 | 强项 | 避免 |
|---|---|---|
| Mermaid | flowchart、sequence、state、ER、Gantt、Git、mindmap、C4 草图，适合大多数流程和文档图 | 节点很多、布局复杂、标准 UML 严格时硬撑 |
| PlantUML | 标准 UML：类图、时序图、活动图、用例图、组件图、状态图 | 轻量业务流程过度 UML 化 |
| Graphviz/DOT | DAG、依赖图、调用图、搜索树、拓扑，自动布局强 | 需要精确像素级视觉设计的图 |
| D2 | 系统图、架构边界、依赖关系，比 Mermaid 更适合工程图 | 简单时序/流程图没必要上 |
| LaTeX + MathJax/KaTeX | 数学公式、优化目标、概率、矩阵、递推 | 把公式删成“核心思想是…” |
| ECharts | 复杂报表、交互图、中文图表、业务数据看板 | 很小的数据对比用得太重 |
| Chart.js | 轻量折线/柱状/饼图 | 复杂交互或多维图表 |
| Vega-Lite / Observable Plot | 可复现的声明式统计图、benchmark、消融实验 | 临时展示但不保留数据 spec |
| markmap | Markdown 列表转思维导图、研究谱系、概念树 | 有明确流程方向的内容 |
| Markdown/HTML 表格 | API、Schema、配置、约束、验收规则 | 把关系型/依赖型内容塞成大表 |
| 伪代码 | 算法、策略、调度、评估逻辑 | 本来是配置/字段说明时强行代码化 |
| 自绘 SVG/HTML | 原文关键图重画、特殊布局、品牌化视觉 | 能用文本图表表达时直接画死 |

## 输出模板

- **公式块**：公式 → 符号说明 → 直觉解释 → 适用边界。
- **数据图块**：数据/spec → 图表 → 坐标轴/单位/样本量 → 读者该比较什么。
- **架构/UML 块**：图源 → 边界/模块说明 → 关键边/状态/协议说明。
- **研究谱系块**：层级图 → 分支含义 → 作者结论或取舍。
- **API/Schema 块**：字段表 → 示例 → 约束/边界条件。
- **伪代码块**：伪代码 → 关键行解释 → 失败/边界路径。

## 使用流程

1. 识别原文/正文的原生表达形态：公式、表格、系统图、数据图、taxonomy、伪代码、UML、API 文档。
2. 选择能保留结构的最小工具。
3. 生成可编辑文本块，而不是截图式描述。
4. 面向混合读者补一层解释，但不删除技术结构。
5. 为每个表达块写一句“它帮助读者一眼看清什么”；回答不出来就删除或改回正文。
6. 产 HTML 或渲染稿时自检：公式无 raw TeX 泄漏，图表有 SVG/canvas，图形有 SVG，移动端无横向溢出。

## 生成式图片边界

- AI 生成插画默认 0 张，确有表达价值时最多 1–2 张；流程图、架构图等文本图表的确定性渲染不计入此额度。
- 每张生成图必须记录：对应正文段落、承担的表达任务、文本图表不能替代的原因、预览贴切性结论。
- 无法明确对应正文、概念关系错误、视觉隐喻偏离主张或仅用于填满版面的图片，直接删除。
- 不默认生成封面，不因“文章应该有图”而凑图；先完成文本图表，再决定是否需要生成式图片。

## 硬规则

- 宁可 1-2 个有意义表达块，也不要堆装饰图。
- 有明确流程、架构、状态或反馈关系时，优先使用可编辑文本图表；不要用氛围插画代替关系表达。
- 生成式图片绝不超过 2 张，贴切性检查失败则为 0 张。
- 不把公式、benchmark、UML、复杂依赖图、研究谱系压成普通流程图。
- 数据图必须有单位、坐标轴和比较口径。
- 架构/UML 图必须表达边界、方向、协议、状态或生命周期。
- 文章分析先保留原文知识形态，最后再映射到本地工作流。
