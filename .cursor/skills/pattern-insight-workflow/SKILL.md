# Pattern Insight Workflow

把 AI 当研究与编辑外骨骼，把形成判断、承担主张、文章声音和发布决定留给用户。目标不是把研究笔记排成段落，而是形成目标读者愿意读完的洞见文章。

## 开始或续做

1. 查找 `Pattern-Insights/`；续做时读取周期 `STATUS.md`，从第一个未通过门禁继续。
2. 新建周期时运行：

   ```bash
   python3 <skill-dir>/scripts/init_cycle.py --workspace <工作区> --domain "<领域>" --question "<问题>"
   ```

3. 一次只推进一个认知动作，并在完成实质工作后更新 `STATUS.md`。

## 九阶段循环

完整规则见 [method.md](references/method.md)。按顺序推进：

1. **领域校准**
2. **研究立项**
3. **资料发现**
4. **人的阅读与批注**（门禁 A）
5. **模式提炼**
6. **主张确认与研究稿**（门禁 B）
7. **文章润色**（门禁 C）
8. **核验、HTML 与知乎发布**（门禁 D + 行动时确认）
9. **反馈复盘**

门禁未通过时停在当前阶段。用户可明确放宽门禁，但必须写入 `STATUS.md`。

## 所有权

- AI：选源、证据索引、反方材料、澄清追问、结构、事实核验、润色、HTML、自检、知乎平台稿、草稿验收和反馈归档。
- 用户：阅读后的原始判断、核心主张、价值判断、文章声音、门禁 C/D、知乎发布位置与最终点击授权。
- 明确区分来源事实、用户观察和 AI 推断，不把 AI 总结伪装成用户洞见。
- 未经用户确认，不发布、不上传、不发送公开内容。

## 研究与写作规则

- 最新资料必须联网检索；技术主题优先论文、官方文档、作者原文和真实案例。
- 先找 5 篇角色不同的核心材料，至少包含一个反例；摘要只用于导航。
- 每张模式卡包含可反驳表述、事实、用户连接、反例、边界、缺失证据和置信度。
- 主张、最强证据和最强反方未确认前，不生成完整文章。
- `06-draft.md` 是研究稿，保存论证骨架、过程说明和编辑记录；不得直接发布或生成 HTML。
- `06-article.md` 是面向读者的纯净文章，必须经过独立润色门禁。

## 文章润色门禁 C

按 [quality-rubric.md](references/quality-rubric.md) 检查，并强制做到：

1. 明确目标读者为何现在要读、读后会改变什么判断。
2. 用冲突、反直觉现象或高代价问题开场，不用研究背景开场。
3. 全文只服务一个可反驳主张；来源是证据，不是目录。
4. 删除“本期研究、材料一、AI 推断、门禁、待确认”等过程语言。
5. 将清单式解释改造成因果推进、张力、反方与回应。
6. 标题承诺明确冲突或收益；结尾闭合观点，不复述全文。
7. 正文稳定后调用 `visual-markdown-toolbox` 扫描三步以上流程、三个以上模块、状态变化和反馈闭环；存在结构价值时优先加入 1–2 个可编辑的流程图或架构图，并解释关键边。
8. 图源优先 Mermaid、PlantUML、D2 或 Graphviz；没有结构价值时可以不画，不把所有关系硬画成普通 flowchart。
9. 用户明确确认“这已经是值得目标读者读完的文章”，门禁 C 才通过。

若用户评价“像笔记、没人会看”，立即退回本阶段；禁止用平台裁剪或视觉美化掩盖正文问题。

## 核验、HTML 与发布门禁 D

1. 核验事实、引用、标题边界、反方观点、隐私和保密风险。
2. 仅以已通过门禁 C 的 `06-article.md` 为输入，调用 `html-generate` 生成 `07-article.html`。
3. HTML 阶段只增强信息层级和视觉表达，不改核心正文；发现内容缺陷退回文章润色。
4. 执行 `html-generate` 的完整浏览器自检：console 无错误、内容完整、375/768/1440 无横向溢出、图表正常。
5. HTML 默认必交付；仅当用户明确不要网页时跳过，并记录原因。
6. 在 `07-publish-package.md` 记录核验、HTML 自检、知乎问答版、风险、目标问题和发布账号。
7. 展示最终正文、HTML、关键改动、风险、目标问题和账号；用户通过门禁 D 后才可写入平台草稿。

## 知乎发布协议

1. 默认渠道为知乎问答。确定目标问题、账号和读者匹配度后，从 `06-article.md` 生成 `08-zhihu-answer.md`；开头直接回答问题，保留主张与引用边界。
2. 优先把 Markdown 中已审核的流程图、架构图确定性渲染为 SVG/PNG 后上传；渲染图不计入生成式图片额度。
3. AI 生成插画默认不生成，确有表达价值时最多 1–2 张。每张记录对应段落、表达任务及不可由文本图表替代的理由；映射说不清或预览不贴切就删除，不为凑封面保留。
4. 图片从本地文件上传，正文不得残留 `file://`、本地绝对路径或失效占位符。
5. 使用内置浏览器写入草稿，核验账号与问题、正文非空、标题层级、图片数量及加载状态、外链、草稿已保存、发布按钮可用；把计数和结果写入发布包。
6. 门禁 D 只批准“内容 + 账号 + 发布位置”。点击“发布回答”前必须再次向用户说明账号、问题、字数、图片和链接数量，并取得行动时确认。
7. 发布成功后记录公开 URL、账号、时间和结果；失败时保留草稿并记录错误，不得反复点击或假定成功。
