# Pattern Insight Workflow

把 AI 当研究与编辑外骨骼，把形成判断、承担主张、文章声音和发布决定留给用户。目标不是把研究笔记排成段落，而是形成目标读者愿意读完的洞见文章。

## 开始或续做

1. 查找 `Pattern-Insights/`；续做时读取周期 `STATUS.md`，从第一个未通过门禁继续。
2. 新建周期时运行：

   ```bash
   python3 <skill-dir>/scripts/init_cycle.py --workspace <工作区> --domain "<领域>" --question "<问题>"
   ```

3. 一次只推进一个认知动作，并在完成实质工作后更新 `STATUS.md`。

## 九阶段循环

完整规则见 [method.md](references/method.md)。按顺序推进：

1. **领域校准**
2. **研究立项**
3. **资料发现与中文研究包**
4. **基于研究包的人的阅读与批注**（门禁 A）
5. **模式提炼**
6. **主张确认与研究稿**（门禁 B）
7. **文章润色**（门禁 C）
8. **核验、HTML 与知乎发布**（门禁 D + 行动时确认）
9. **反馈复盘**

门禁未通过时停在当前阶段。用户可明确放宽门禁，但必须写入 `STATUS.md`。

## 所有权

- AI：选源、中文翻译总结、证据索引、反方材料、澄清追问、结构、事实核验、润色、HTML、自检、知乎平台稿、草稿验收和反馈归档。
- 用户：阅读中文研究包后的原始判断、核心主张、价值判断、文章声音、门禁 C/D、知乎发布位置与最终点击授权。
- 明确区分来源事实、用户观察和 AI 推断，不把 AI 总结伪装成用户洞见。
- 未经用户确认，不发布、不上传、不发送公开内容。

## 研究与写作规则

- 最新资料必须联网检索；技术主题优先论文、官方文档、作者原文和真实案例。
- 先找 5 篇角色不同的核心材料，至少包含一个反例；随后必须生成 `02-research-pack.md` 中文研究包，不能只给链接或要求用户默认阅读原文。
- 中文研究包采用“翻译式总结”，不是全文逐字翻译。每份材料至少包含：中文标题与来源角色、要解决的问题、核心主张、机制/方法、关键证据、局限与反方、与本期问题的关系、需要用户判断的问题。
- 原文链接和章节/页码只作为事实核验入口，统一放在材料末尾；正文不大段粘贴原文。必要引用保持短小并遵守版权引用限制。
- 除非用户明确要求核验某处，门禁 A 的默认阅读对象是中文研究包，不是原文。AI 不得用摘要替用户形成判断，但必须先把理解材料的语言与检索成本承担掉。
- 每张模式卡包含可反驳表述、事实、用户连接、反例、边界、缺失证据和置信度。
- 主张、最强证据和最强反方未确认前，不生成完整文章。
- `06-draft.md` 是研究稿，保存论证骨架、过程说明和编辑记录；不得直接发布或生成 HTML。
- `06-article.md` 是面向读者的纯净文章，必须经过独立润色门禁。
- 写读者版前必须完成 [读者中心写作规则](references/reader-centered-writing.md) 的“读者入口卡”：目标读者不仅写角色，还要写知识距离、当前处境、已有认知、切身利害、默认判断和读后改变。
- 开场没有固定句式。“冲突开场”不等于第一句就讲案例；读者尚未理解案例与自己的关系时，先用熟悉处境和利害完成定向，再引入问题、主张或案例。

## 文章润色门禁 C

按 [quality-rubric.md](references/quality-rubric.md) 检查，并强制做到：

1. 先完成读者入口卡，明确读者的角色与知识距离、当前处境、已有认知、切身利害、默认判断和读后改变；只写“技术负责人”不算完成。
2. 先判断是研究结果型、技术观点型还是案例复盘型。技术观点文默认采用 Nature 式“共同现状 → 直接压力 → 解释缺口 → 核心判断”的同心入口；没有真实项目证据时，不得把假设场景伪装成案例复盘。
3. 前 150–250 个汉字完成“熟悉锚点 → 与读者有关的利害 → 尚未解决的缺口 → 本文主张”中的必要部分。顺序可按文体调整，但不得让读者先解释陌生案例或术语，再猜它为何重要。
4. 开场策略按知识距离选择：高接近度可直接给问题或反直觉判断；中接近度先唤起熟悉工作处境；低接近度先补最小背景。案例只有在读者能识别场景、理解利害并知道它将证明什么时才能前置。
5. 全文只服务一个可反驳主张；来源是证据，不是目录。用读者问题链组织章节，每一节回答一个读者此刻自然会问的问题。
6. 段落和章节遵循“旧信息连接 → 新信息推进”：开头承接读者刚获得的概念，结尾落在需要强调的新判断，禁止连续抛出没有桥接的新名词。
7. 正文只保留主叙事、最强证据和必要边界；完整方法、协议和次要材料进入补充层，不把研究充分等同于把所有材料塞进正文。
8. 删除“本期研究、材料一、AI 推断、门禁、待确认”等过程语言，将清单式解释改造成因果推进、张力、反方与回应。
9. 标题承诺明确冲突或收益；结尾把开场的利害升级为判断或行动，不复述全文。
10. 正文稳定后调用 `visual-markdown-toolbox` 扫描三步以上流程、三个以上模块、状态变化和反馈闭环；存在结构价值时优先加入 1–2 个可编辑的流程图或架构图，并解释关键边。
11. 图源优先 Mermaid、PlantUML、D2 或 Graphviz；没有结构价值时可以不画，不把所有关系硬画成普通 flowchart。
12. 交付前执行标题与开头释义测试：只读标题和首段，能否说出“写给谁、为什么现在值得读、作者主张什么”；再逐节做反向提纲，无法说出该节回答什么读者问题就重构。
13. 用户明确确认“这已经是值得目标读者读完的文章”，门禁 C 才通过。

若用户评价“像笔记、没人会看”，立即退回本阶段；若评价“上来举例无法带入、看不出与我有什么关系”，归因为读者定向失败，先重做读者入口卡与开场策略，不得只换案例或缩短句子。禁止用平台裁剪或视觉美化掩盖正文问题。

## 门禁有效性与后置变更

- 门禁 C 通过后，以当时的 `06-article.md` 作为内容基线。新增/删除核心观点、改变结论或适用边界、引入新的事实论据，均属于**实质内容变更**：门禁 C 自动失效，必须在 `07-publish-package.md` 记录变更摘要，重新完成事实核验与门禁 C，之后才能进入门禁 D。
- 仅调整排版、配色、交互或不改变论点的视觉资产，属于**纯视觉变更**，不使门禁 C 失效；但必须重新完成受影响的 HTML、图片加载、响应式裁切与 console 自检。
- 无法确定变更类型时按实质内容变更处理，不允许沿用旧的门禁 C 状态掩盖正文变化。

## 核验、HTML 与发布门禁 D

1. 核验事实、引用、标题边界、反方观点、隐私和保密风险。
2. 在 `07-publish-package.md` 先锁定**视觉资产清单**：文本图表、确定性渲染图、生成式图片各自的对应段落、表达任务、文件路径与数量；封面不是默认必需资产。
3. 仅以已通过门禁 C 的 `06-article.md` 为输入，调用 `html-generate` 生成 `07-article.html`。
4. HTML 阶段只增强信息层级和视觉表达，不改核心正文；发现内容缺陷退回文章润色。
5. 执行 `html-generate` 的完整浏览器自检：console 无错误、内容完整、375/768/1440 无横向溢出、图表正常。
6. 用户明确要求封面或生成式图片时，先生成并人工检查语义贴切性，再保存为项目本地资产；发布包记录最终提示词、用途、路径、尺寸和预览结论。HTML 自检额外验证图片加载，并至少人工复核 375 与 1440 宽度下的首屏裁切。
7. HTML 默认必交付；仅当用户明确不要网页时跳过，并记录原因。
8. 在 `07-publish-package.md` 记录核验、HTML 自检、知乎发布形式、平台稿、风险、目标位置和发布账号。
9. 展示最终正文、HTML、关键改动、风险、发布形式、目标位置和账号；用户通过门禁 D 后才可写入平台草稿。

## 知乎发布协议

1. 默认渠道为知乎问答。确定目标问题、账号和读者匹配度后，从 `06-article.md` 生成 `08-zhihu-answer.md`；开头直接回答问题，保留主张与引用边界。用户指定独立文章时切换为 `{NN}-zhihu-article.md`，并完整执行 [zhihu-independent-article.md](references/zhihu-independent-article.md)，不得继续套问答字段。
2. 独立文章先检查当前编辑器字段；超过 30 天或界面变化时重新实测。标题、首屏 150–250 字、封面和 2–3 个真实话题必须回答同一个读者问题；当前界面没有独立摘要字段时不得虚构摘要配置。
3. 优先把 Markdown 中已审核的流程图、架构图确定性渲染为 SVG/PNG 后上传；渲染图不计入生成式图片额度。
4. AI 生成插画默认不生成，确有表达价值时最多 1–2 张。每张记录对应段落、表达任务及不可由文本图表替代的理由；映射说不清或预览不贴切就删除。独立文章封面若生成，统一到 1440 × 810，并同时检查 16:9 原图和 3:2 居中裁切。
5. 图片从本地文件上传，正文不得残留 `file://`、本地绝对路径或失效占位符。
6. 使用内置浏览器写入草稿。问答核验账号与问题；独立文章核验新发布/更新、标题、封面、话题、投稿至问题、创作声明和内容来源。投稿至问题最多 1 个，只有完整问题与核心主张强匹配才选择，否则保持未选择。两者都要核验正文非空、标题层级、图片数量及加载、外链、自动保存和按钮可用，并写回发布包。
7. 门禁 D 只批准“内容 + 账号 + 发布位置”。点击前必须再次向用户说明账号、位置或目标 URL、标题、字数、标题数、正文图片、封面、链接、话题、投稿至问题、声明、来源以及按钮是“发布回答”“发布”还是“更新”，并取得行动时确认。
8. 发布成功后访问公开页核验并记录公开 URL、账号、时间、封面、话题和结果；失败时保留草稿并记录可见错误，不得反复点击或假定成功。
