# 读者中心写作规则

本规则用于把研究主张转换成目标读者第一次阅读即可进入的文章。它不规定所有文章采用同一种开场，而是要求作者先完成读者定向，再选择问题、判断、场景或案例。

## 一、研究依据

- Harvard College Writing Center 的引言指南强调：引言应先框定问题、提供理解主张所需的定向信息，并说明为什么值得读；不要求用戏剧性事实或故事强行“钩住”读者。来源：[Introductions](https://writingcenter.fas.harvard.edu/introductions)。
- Google Technical Writing 把好文档概括为“读者完成任务所需的知识，减去读者已有知识”，并要求同时考虑角色与读者距离主题的远近。来源：[Audience](https://developers.google.com/tech-writing/one/audience)。
- Google 的文档组织规则要求在开头回答读者的关键问题，用读者已经理解的概念比较和承接新概念，并以读者需求而不是作者材料组织正文。来源：[Documents](https://developers.google.com/tech-writing/one/documents)。
- Gopen 与 Swan 关于科学写作的读者预期研究指出：读者需要先获得语境，再处理新信息；句子和段落开头用已出现的信息建立连接，强调位置再承载新判断。来源：[The Science of Scientific Writing](https://www.americanscientist.org/article/the-importance-of-context-in-genetics)。
- CDC 的清晰写作指南要求明确目标读者、单一主信息和读者行动，把最重要的信息放在前面，并通过目标读者测试判断材料是否被按预期理解。来源：[Your Guide to Clear Writing](https://www.cdc.gov/nceh/clearwriting/docs/clear-writing-guide-508.pdf)。
- NIH 建议围绕读者会提出的问题组织内容，每节回答一个问题，而不是围绕作者掌握的材料组织。来源：[Before You Start Writing](https://www.nih.gov/institutes-nih/nih-office-director/office-communications-public-liaison/clear-communication/plain-language-nih/plain-language-getting-started-or-brushing-up/before-you-start-writing)。
- Nature 的写作指南要求兼顾本领域与相邻领域读者，主动语态、拆开打包过度的概念、减少术语和缩写，并把正文压缩到“足以支撑一个聚焦信息”的最短长度。来源：[How to write your paper](https://www.nature.com/nature-portfolio/for-authors/write)。
- Nature 的 summary paragraph 采用由宽到窄再回到意义的结构：跨学科可懂的领域背景 → 相邻领域可懂的研究背景与理由 → 明确问题 → 主要结论 → 相对既有认识的推进 → 更广影响。来源：[How to construct a Nature summary paragraph](https://www.nature.com/documents/nature-summary-paragraph.pdf) 与 [Nature formatting guide](https://www.nature.com/nature/for-authors/formatting-guide)。
- IEEE 的文章结构指南要求标题具体、简洁、可描述；摘要自包含并覆盖问题、结论和影响；引言要把研究置于更大领域中，明确问题、重要性和新贡献；结论不能夸大证据。来源：[Structure Your Article](https://journals.ieeeauthorcenter.ieee.org/create-your-ieee-journal-article/create-the-text-of-your-article/structure-your-article/)。

这些来源共同支持一条工作流判断：**读者带入不是靠“上来讲故事”，而是靠先建立相关性。** 案例只是建立或验证相关性的一种手段，不是默认开场模板。

## 二、先选文章类型，不能把所有技术文章写成故事

不同文章承担不同的证据责任，结构也不同：

| 类型 | 核心论证顺序 | 适用场景 |
|---|---|---|
| 研究结果型 | 共同背景 → 已知工作 → 未解问题 → 方法/发现 → 证据 → 影响 | 有原创实验、数据或方法结果 |
| 技术观点型 | 读者熟悉的现状 → 新变化带来的压力 → 旧解释为何不足 → 核心判断 → 机制与证据 → 边界/反方 → 行动含义 | 架构判断、行业洞见、技术负责人文章 |
| 案例复盘型 | 原状态与目标 → 关键决策 → 结果证据 → 失败/限制 → 可迁移原则 | 有真实项目证据的复盘 |

`pattern-insight-workflow` 的大多数洞见文章属于技术观点型。没有真实项目证据时，不得把假设场景包装成案例复盘，也不得模仿研究论文的“Here we show”声称已经验证。

Nature 的格式可借鉴的是**信息依赖顺序与跨领域可读性**，不是机械复制学术论文格式。

## 三、技术深文优先使用“同心入口”

Nature 的 summary paragraph 之所以容易进入，不是因为先讲故事，而是先建立一层共同语境，再逐步缩小到作者真正的问题。技术观点文章可以改写为：

1. **共同现状**：目标读者已经观察到的行业或工作变化。
2. **直接压力**：这项变化如何影响读者当前的成本、风险或决策。
3. **解释缺口**：常见做法为什么没有解决真正问题。
4. **核心判断**：本文提出什么不同解释或原则。
5. **判断增量**：它相对读者原有理解具体改变了什么。
6. **行动含义**：如果判断成立，读者接下来应优先建设或停止什么。

这不是要求把六项都塞进第一段。开头先覆盖前四项，后两项可以在引言收束和结尾展开。

对跨团队技术负责人这类“中等知识距离”读者，默认先试同心入口；只有案例本身已经是共同事件或读者高频经历时，才考虑案例前置。

## 四、Nature 技术文章样本提供的结构信号

以下样本用于观察结构，不复制原文措辞：

- [Why ‘open’ AI systems are actually closed, and why this matters](https://www.nature.com/articles/s41586-024-08141-1)：先指出政策讨论中的概念含混与现实利害，再界定分析对象、给出主要发现和边界；案例和组件分析位于问题框架之后。
- [Discovering state-of-the-art reinforcement learning algorithms](https://www.nature.com/articles/s41586-025-09761-x)：先交代强化学习的共同目标，再用“人类学习机制与人工规则”的对比制造缺口，随后提出方法、证据和意义。
- [We need a new ethics for a world of AI agents](https://www.nature.com/articles/d41586-025-02454-5)：先说明 AI 开发重心正在变化并定义 Agent，之后才给购买与机器人等例子；例子用于落地已经建立的问题，而不是替代问题框架。
- [Multi-agent AI systems need transparency](https://www.nature.com/articles/s42256-026-01183-2)：先给当前趋势，再用资源风险构成转折，随后界定对象并提出透明性要求。

这些样本的共同点是：标题给出判断或问题；首段让读者知道领域正在发生什么变化；引言把变化收窄为一个可回答的问题；方法、案例和理论都在读者获得坐标之后出现。

## 五、先做读者入口卡

在写 `06-article.md` 前，必须在研究稿中回答：

1. **具体是谁**：角色之外，还包括他与主题的知识距离。
2. **他此刻在哪里**：正在做什么决策、承受什么风险或遇到什么摩擦。
3. **他已经知道什么**：文章可以直接承接的旧信息。
4. **他尚未意识到什么**：文章真正要打开的认知缺口。
5. **为什么现在读**：不理解会付出什么成本，理解后能改变什么。
6. **当前默认判断**：文章准备挑战或修正的看法。
7. **读后改变**：读者应形成的新判断或下一行动。
8. **不讲什么**：删除读者合理预期之外的支线。

只有角色标签，没有当前处境和已有认知，不算完成读者定义。

## 六、开场承担“定向合同”

开场的任务不是展示作者写得精彩，而是让读者迅速获得四样东西：

1. **熟悉锚点**：从读者已经见过的工作状态、判断或变化进入。
2. **切身利害**：说明这件事会影响他的成本、风险、决策或能力。
3. **认知缺口**：指出常见解释为什么不足，或哪个关键问题尚未解决。
4. **文章主张**：尽早给出本文将证明的判断。

四项不要求机械地各写一句，也不要求固定顺序。目标是在前 150–250 个汉字内，让读者能用自己的话回答：这篇文章与谁有关、为什么现在值得读、作者准备改变什么判断。

## 七、按知识距离选择开场

| 读者与主题的距离 | 优先开场 | 说明 |
|---|---|---|
| 高接近度 | 直接问题、反直觉判断、当前变化 | 读者已经掌握场景和术语，不必重新铺背景 |
| 中接近度 | 熟悉工作处境 → 新变化 → 利害 | 先唤起共同经验，再指出旧判断已经不够 |
| 低接近度 | 最小背景 → 为什么与他有关 → 核心问题 | 不先扔术语、理论或需要解释的案例 |

避免两种机械写法：

- **机械故事化**：第一句就进入具体人物或事故，但读者不知道自己为什么要关心。
- **机械背景化**：从行业历史、宏大趋势或字典定义开始，迟迟不说明本文的具体问题。

## 八、案例前置的四个条件

案例只有同时满足以下条件才能放在开场：

1. 目标读者能立即识别这是自己的场景或一个无需背景的公共场景。
2. 案例中的损失、冲突或选择与读者的切身利害直接相连。
3. 理解案例不依赖尚未解释的术语、组织背景或系统细节。
4. 案例结束后，读者知道它将帮助证明哪个问题，而不是只记住故事。

任一条件不满足，先用 1–3 段完成定向，再引入案例。案例也可以放在主张之后，承担“把抽象判断落地”的任务。

## 九、用读者问题链代替材料目录

列出读者接受主张前自然会提出的问题，例如：

1. 这和我当前的工作有什么关系？
2. 旧做法为什么突然不够了？
3. 作者真正提出了什么不同判断？
4. 这个判断靠什么机制成立？
5. 它在什么边界下不成立？
6. 我接下来应改变什么？

章节按依赖排序，而不是按研究材料、概念模块或作者发现顺序排序。每节只回答一个主要问题，并让答案制造下一问题的必要性。

## 十、按“旧信息 → 新信息”推进

- 每段开头用读者已经见过的人、对象或判断承接上文。
- 每段只引入一个主要新概念，并立刻说明它与旧信息的关系。
- 把需要强调的新判断放在段落或句子的收束位置。
- 如果相邻两段的开头连续更换主语和概念，检查是否缺少桥接句或正在同时讲多个故事。
- 专业名词首次出现时，先给读者能理解的功能性解释，再给术语名称。

## 十一、正文与证据分层

Nature 把聚焦结论留在主文，把方法、协议和额外数据放到补充材料。技术观点文章也需要分层：

- **主叙事层**：读者问题、核心判断、机制、最强证据、边界和行动含义。
- **证据层**：论文、数据、真实案例及它们能证明到哪里。
- **技术细节层**：完整架构、字段、协议、方法过程和扩展材料。

主叙事层必须在不阅读全部技术细节时仍能成立；技术细节必须能被读者按需找到。不要为了显示研究充分，把所有材料都压进正文。

## 十二、三类验收测试

### 1. 标题与首段释义测试

只读标题和前 150–250 个汉字，让目标读者回答：

- 这篇写给谁？
- 为什么现在值得读？
- 作者主张什么？

答不出或与作者意图明显不同，先改读者定向，不改后文细节。

### 2. 反向提纲测试

为每节补一句：

`读者此刻的问题 → 本节给出的新判断 → 为什么必须继续读下一节`

无法填写的章节，通常是材料残留、重复解释或论证跳跃。

### 3. 读者释义测试

请读者用自己的话复述核心主张，再说明哪一处让他开始在意、哪一处失去方向。优先记录读者实际理解，不用作者解释去纠正读者。门禁 C 以读者释义是否与作者意图基本一致为准，而不只问“好不好读”。

## 十三、反馈归因

- “上来举例无法带入” → 读者定向失败，不是案例不够精彩。
- “每句话都懂，但不知道为什么连在一起” → 读者问题链或旧→新桥接失败。
- “像研究笔记” → 正文仍按材料或作者发现顺序组织。
- “看完不知道要改变什么” → 读者承诺、主张或结尾行动不明确。
- “太浅” → 不能仅靠删术语修复，应恢复机制、证据与边界，再用读者已知概念承接。
