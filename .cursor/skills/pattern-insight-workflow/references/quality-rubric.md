# 洞见与文章质量量表

## 洞见质量

每项 1–5 分：新颖性、解释力、证据、边界、行动性。任一项低于 3，先说明缺口，不以文章完整性强行圆回。

## 文章润色门禁

每项 1–5 分，门禁 C 要求总分至少 32/40，且“读者定位、开场定向、叙事推进、去笔记感”均不得低于 4。

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 读者定位 | 只有泛化角色标签 | 知道角色和收益，但不清楚读者处境与已有认知 | 明确角色、知识距离、当前处境、已有认知、切身利害和读后改变 |
| 开场定向 | 直接抛陌生案例/术语，读者需猜为何相关 | 主题明确但利害或主张出现较晚 | 前 150–250 字以熟悉锚点建立利害与缺口，读者能释义文章为什么与自己有关 |
| 单一主张 | 多个观点并列 | 主张存在但支线较多 | 全文围绕一句可反驳判断推进 |
| 叙事推进 | 章节像独立笔记 | 顺序合理但跳跃 | 每段制造下一段的必要性 |
| 证据融入 | 按材料逐篇摘要 | 证据能支撑观点 | 证据、边界和反方共同推进论证 |
| 平台相关性 | 只填宽泛话题 | 标题、首屏、封面、话题大体一致 | 四个入口回答同一个读者问题；话题真实存在且有正文证据，裁切后封面语义仍成立 |
| 去笔记感 | 大量清单/过程语言 | 已基本成文 | 无研究小票感，有节奏和声音 |
| 标题与结尾 | 标题泛、结尾复述 | 能概括内容 | 标题有承诺，结尾完成判断升级 |
| 释义一致性 | 读者说不出或误解核心意思 | 能复述主题，无法说清主张变化 | 只读标题与首段即可说清写给谁、为何现在读和核心主张；逐节释义与作者意图一致 |

## 开场与读者带入检查

1. 标题和前 150–250 个汉字是否先给读者一个熟悉锚点，而不是要求读者立即理解作者熟悉的案例？
2. 开场是否说明这件事为什么与目标读者此刻的决策、风险、成本或认知有关？
3. 案例若前置，读者是否无需额外背景就能识别场景、理解利害并知道案例将证明什么？任一答案为否则后移案例。
4. 开场是否提供了理解主张所需的最小背景，但没有写成宽泛历史、字典定义或研究综述？
5. 只读标题和首段，目标读者能否用自己的话回答：这是写给谁、为什么现在值得读、作者希望我改变什么判断？
6. 每节第一段是否承接上一节已经成为“旧信息”的概念，再引入一个新问题；是否存在连续抛出新名词的跳跃？
7. 是否先区分研究结果型、技术观点型和案例复盘型；没有真实项目证据时，是否避免把假设场景写成真实复盘？
8. 技术观点文是否完成“共同现状 → 直接压力 → 解释缺口 → 核心判断”的必要定向，而不是把方法、案例或理论抢到问题之前？
9. 主文是否只保留支撑核心判断所需的最强证据与边界，把完整方法、协议和次要材料留在补充层？

## 反洗稿检查

1. 删除所有来源摘要后，还剩哪一句属于用户自己的判断？
2. 什么事实会推翻它？
3. 用户经验或观察改变了哪段论证？
4. 是否诚实区分已知、推断和未知？
5. 下一次反馈能否让模式更精确？

## 图文表达门禁

1. 三步以上流程、三个以上模块、状态变化或反馈闭环是否优先用可编辑文本图表表达？
2. 是否按内容选择 Mermaid、PlantUML、D2、Graphviz 等合适工具，而不是全部压成普通流程图？
3. 每张图是否表达正文难以一眼看清的边界、方向、状态或因果关系，并在图后解释关键边？
4. AI 生成插画是否控制在 0–2 张，且逐张明确对应段落、表达任务和不可由文本图表替代的理由？
5. 预览不贴切、只起装饰作用或无法明确映射正文的图片是否已经删除？
