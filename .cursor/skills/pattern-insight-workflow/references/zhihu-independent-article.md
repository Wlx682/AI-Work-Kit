# 知乎独立文章平台适配

> 适用于用户明确选择“知乎独立文章”时。平台界面会变化；以下字段来自 2026-08-13 对已登录编辑器的实测。每次发布仍以当前可见 DOM 为准，超过 30 天或界面变化时先重新检查，不凭记忆补字段。

## 1. 当前编辑器字段

| 字段 | 实测约束 | 工作流动作 |
|---|---|---|
| 标题 | 标题框提示最多 100 字 | 标题只放标题栏；正文导入稿不重复 H1 |
| 正文 | 富文本编辑器支持 Markdown 导入 | 从已通过门禁 C 的正文生成独立平台稿，去除研究过程和 Mermaid 源码 |
| 封面 | 支持 JPEG / JPG / PNG；已发布文章封面自然尺寸为 1440 × 810 | 用户明确要求时输出 1440 × 810；不把封面再次插入正文 |
| 创作声明 | 独立下拉字段 | 在发布包记录可见选项和最终选择，不默认为“原创”或代替用户作权利声明 |
| 文章话题 | 从平台搜索建议中选择 | 先验证话题真实存在，再选择 2–3 个；不自造标签 |
| 投稿至问题 | 新建独立文章在正文载入后出现；最多选择 1 个 | 只在搜索到与核心主张直接匹配的问题时选择；推荐或搜索结果不相关就保持“未选择” |
| 内容来源 | 新闻类内容需要明确标注来源 | 非新闻技术观点稿记录“不添加新闻来源”；新闻类必须逐项填写来源 |
| 摘要 | 当前编辑器未见独立摘要字段 | 不虚构摘要配置；由首屏 150–250 字承担推荐流摘要与读者定向 |

## 2. 封面语义与裁切检查

封面不是正文插画，也不是泛化 AI 海报。生成前先写一张“封面语义卡”：

- 核心冲突：标题中哪一组张力必须被看见；
- 视觉隐喻：用什么结构表达，而不是用机器人、发光大脑或仪表盘代替；
- 主视觉安全区：关键对象放在中央 70%，允许左右边缘被裁掉；
- 禁止项：文字、Logo、水印、无法解释的装饰、与正文无关的风险符号。

输出和验收顺序：

1. 生成 16:9 横图并统一到 1440 × 810；
2. 检查原图语义、清晰度、无错字/伪文字、无 Logo 与水印；
3. 额外检查 3:2 居中裁切。实测编辑器侧栏封面槽位为 150 × 100，使用 `object-fit: cover`；
4. 原图和裁切图都必须在 2 秒内传达与标题相同的核心张力；否则重做，不靠标题补救；
5. 发布包记录提示词摘要、文件路径、尺寸、原图结论、3:2 裁切结论与平台加载状态。

## 3. 相关性配置

相关性不是堆关键词，而是让四个入口回答同一个读者问题：

| 入口 | 应回答什么 |
|---|---|
| 标题 | 谁遇到什么反常结果或判断冲突 |
| 首屏 150–250 字 | 为什么现在与读者有关、旧解释哪里不够、本文主张什么 |
| 封面 | 不读文字也能看出同一核心张力 |
| 话题 | 读者会在哪些真实主题下寻找这类问题 |

话题选择采用“核心对象—工程语境—关键机制”三层，通常各取一个：

- 核心对象：如人工智能、智能体；
- 工程语境：如软件工程、生产系统；
- 关键机制：如可观测性、系统安全。

只选择平台搜索建议中真实存在且正文有实质覆盖的话题。2 个已经覆盖对象和语境时不必凑 3 个；不要同时选择多个近义宽泛话题稀释信号。把候选、平台实测结果、最终选择和每个话题对应的正文证据写进发布包。

“投稿至问题”不是必填流量开关。先用标题中的核心对象与问题搜索一次，核对结果的完整问题文本、URL 与正文主张；没有强匹配就保持未选择。不得因为推荐列表有浏览量而投稿到无关问题，也不得用宽泛问题掩盖文章与问答语境的不匹配。

## 4. 平台稿与发布验收

独立文章平台稿命名为 `{NN}-zhihu-article.md`，并满足：

- 不含重复 H1，不把封面放进正文；
- 标题层级从 H2 开始；
- Mermaid / PlantUML / D2 等源码先确定性渲染为 PNG 后上传；
- 本地图片逐张上传，平台正文不得残留本地路径或 Markdown 占位；
- 外链逐条检查锚文本、URL 与打开结果；
- 首屏能独立通过“写给谁、为什么值得读、主张什么”的释义测试。

写入后在可见 DOM 中核验：账号、操作类型（新发布 / 更新旧文章）、标题、字数、H2 数、正文图数、封面、话题、投稿至问题、创作声明、内容来源、外链、自动保存和按钮状态。

点击前的行动时确认必须逐项复述：

- 账号与显示名；
- 新发布还是更新旧文章，以及目标 URL（若有）；
- 最终标题；
- 正文字数、标题数、正文图片数、封面数、外链数；
- 最终话题、创作声明与内容来源；
- 投稿至问题的最终选择，未选择时也要明确复述；
- 即将点击的按钮是“发布”还是“更新”。

用户确认后只点击一次。成功后访问公开页核验标题、封面、正文图、话题和 URL；失败则保留草稿、记录可见错误并停止。
